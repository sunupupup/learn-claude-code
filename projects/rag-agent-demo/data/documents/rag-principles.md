# RAG 原理

## 摄取与切分

RAG（Retrieval-Augmented Generation，检索增强生成）在生成回答前，从外部知识源取回相关证据。摄取流程通常包括读取文档、清洗、按语义边界切分、生成 Embedding、写入向量数据库，并保存来源和权限元数据。

## 检索与 top-k

用户问题也会被转换为查询向量。向量数据库根据相似度返回候选 chunk，并可以应用租户、群组和文档状态等 payload 过滤。top-k 只表示返回多少候选，不表示候选一定能够回答问题；相似度分数也不是事实正确性的证明。

## 有依据与无依据

最终模型只能根据检索到的 chunk 回答。如果候选内容没有直接支持问题，系统应返回资料不足，而不是使用模型参数中的常识补全。回答应保留 chunk_id、标题或章节等来源信息，便于追踪和评测。
