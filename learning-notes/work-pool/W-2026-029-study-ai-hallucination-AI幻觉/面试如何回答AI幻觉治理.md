# 面试如何回答 AI 幻觉治理

记录日期：2026-09-20。延续常见幻觉与选择性拒答讨论；本轮是面试回答校准和应用工程建议，没有执行模型实验。

## 用户原始回答

> 前段时间面试被问：你怎么看 AI 幻觉、怎么解决 AI 幻觉？
> 我的想法是，回答内容需要带上依据，比如链接；可选让一个小模型二次分析。
> 这个回答比较依赖联网搜索了是吧？还有什么好的建议？

- 🟢 已验证（方向有研究依据）：给出可追溯依据、对答案进行二次核验，都是合理的治理方向。
- 🟡 需要补齐条件：带链接不证明内容正确；小模型是否有效取决于证据输入、任务、训练和实际评测。
- 校准：这个思路依赖的是可核验的外部证据，不一定是公开互联网。外部是相对于模型参数中的知识而言。

## 1. 证据来自哪里

| 场景 | 合适的证据 | 不足的做法 |
| --- | --- | --- |
| 时效性公共信息 | 一手网页、发布日期、原文片段 | 仅看搜索摘要，或由模型自行编 URL |
| 企业制度问答 | 内部文档的版本、适用范围、条款和片段 | 引用已失效制度，或其他地区的同名制度 |
| 订单和库存问答 | 权限内的数据库查询、业务接口结果与查询时间 | 让模型凭常识推测实时业务状态 |
| 代码问题 | 当前仓库、实际依赖版本、编译和测试结果 | 把“看起来能运行”汇报成“测试已通过” |
| 数值计算 | 原始数据、口径、计算程序与结果 | 数字附了引用，但计算过程或单位错误 |

RAG（Retrieval-Augmented Generation，检索增强生成，应用层）可以检索本地或企业内部资料，不要求互联网搜索，也不要求每个场景使用向量数据库。结构化业务数据通常通过查询工具获取更直接。

**先获取可信证据，再据此生成，并让关键结论对应证据片段。** 事后补引用也需要逐项核验，不能把找得到相关网页当成答案已经被证明。

引用要检查：来源是否真实且适用；原文是否支持这个具体结论；关键结论是否遗漏依据。ALCE 将正确性和引用质量分开评估，说明两者不能互相替代。[论文](https://aclanthology.org/2023.emnlp-main.398/)

## 2. 小模型应该复核什么

把“小模型再分析一下”具体化为一个范围明确的核验任务：

输入：用户问题、回答中的一条事实断言、对应原文片段及来源元数据。

输出：支持 / 矛盾 / 证据不足，以及对应片段或不匹配之处。还要检查时间、对象、条件和数字是否被改变。

例如原文是“试用期结束后，每年可报销一次培训费”，答案是“所有员工每月都能报销培训费”。核验应找出资格和频率的变化，而非凭语气判断答案可信。

这类任务属于事实一致性或文本蕴含检查：文本蕴含（Textual entailment）指给定证据能否推出结论，属于语言理解和应用校验层。CaLF 研究使用事实一致性模型检查引用对断言的支持关系；不能据此推断任意小模型都能有效复核。[论文](https://aclanthology.org/2024.acl-long.641/)

工程上可试用专门训练的小模型控制延迟与成本，但应拿人工标注案例测其漏检、误报和净收益；复杂问题再升级更强模型或人工。模型之间可能共享知识盲点，换模型也不自动产生独立证据。

如果来源本身错误，忠实性核验可能仍通过，因此来源质量和答案支持关系必须分别检查。数字、ID、单位、权限与执行状态，能用程序精确检查的部分优先用程序。

## 3. 面试回答可用的完整框架

**先界定问题，再讲“证据—生成—核验—兜底—评测”。**

1. **界定场景与错误**：事实问答、总结、代码或工具执行，需要不同证据。模型生成看似合理但不真实、不被资料支持的内容可构成幻觉；检索失败和工具超时首先是系统故障。
2. **准备证据**：知识问答检索可信资料；动态业务状态查接口；关注资料版本、适用范围和访问权限。没有必要为所有问题联网。
3. **约束生成**：明确允许使用的证据，保留条件与范围；区分事实和推测。缺信息时澄清或保留结论，错误前提有证据时纠正。
4. **核验结果**：逐条检查断言与证据；计算交给程序、代码执行相应验证、业务状态查询确认。模型复核用于难以规则化的语义部分。
5. **失败处理**：证据不足时补查、缩小结论或回答不知道；限定重试次数。重要输出按业务风险升级人工；核验服务超时不能默认为通过。
6. **效果评测**：建立正常、无答案、错误前提、过期资料、冲突证据和工具失败案例。一起看事实错误率、引用支持率、回答覆盖率、误拒答率，以及延迟和成本。

以上是应用层方案。模型层还可通过监督微调、偏好或强化学习改善承认未知和依据证据的行为，见[拒答研究](教AI拒答、纠错与减少迎合的研究.md)。对于应用工程面试，先讲清前述完整流程，再按追问展开训练方法。

线上可保留必要的来源版本、模型/提示版本与工具结果来定位失败，并对敏感数据脱敏；根据坏案例修正系统后做回归测试。这里是设计建议，尚未落地或验证。

## 4. 一段可以口述的答案

> 我把幻觉理解为模型生成看似合理、但不符合事实或缺乏证据支持的内容。工程上我不会承诺彻底消除，会按业务场景降低发生率和影响。
>
> 我会先给模型可靠依据：公共信息可以联网，企业知识检索内部文档，订单状态查业务接口，所以并不只依赖联网。回答里的关键事实要能对应到原文或工具结果，而不只是附一个链接。
>
> 生成后，确定性的部分用程序校验；语义部分可以让经过评测的小模型核对断言和证据，但复核模型也会犯错。证据不足时应补查、澄清或明确不知道，重要场景再转人工。
>
> 最后通过包含无答案、错误前提和过期资料的测试集，检查错误率、引用支持、误拒答，以及延迟成本，确认这些措施带来了净收益。

## 5. 容易被追问的边界

- 低随机性不等于事实正确；稳定地重复错误仍然是错误。
- JSON 格式合法不等于字段值真实。
- RAG 找到资料不代表资料正确，也不代表模型忠实使用了资料。
- 让模型再想一遍不保证改对。ICLR 2024 的自纠错论文研究了当时特定推理任务中缺乏外部反馈的局限；它不能证明所有现代模型或有证据的复核都无效。[原论文](https://proceedings.iclr.cc/paper_files/paper/2024/file/8b4add8b0aa8749d80a34ca5d941c355-Paper-Conference.pdf)
- 对复杂事实不能把多个模型的一致意见直接当成真值。
