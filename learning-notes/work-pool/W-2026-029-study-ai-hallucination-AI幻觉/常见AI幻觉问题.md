# 常见 AI 幻觉问题

记录日期：2026-09-20。承接用户“先记上有哪些常见幻觉问题”的请求；本轮只建立问题清单，供后续逐类讨论如何解决。

## 先建立一个直观理解

**AI 说得自然、具体、肯定，不代表内容有事实或证据支持。**

幻觉（Hallucination）常用来描述模型生成不符合事实、不被资料支持或与资料冲突的内容。不同研究的口径不完全一致。本笔记按日常表现整理，类别可重叠，不是统一学术分类，也不是发生频率排名。

研究中的两个常用观察角度：

- **事实性（Factuality）**：答案与现实事实是否一致。
- **忠实性（Faithfulness）**：答案是否忠实于给定资料或上下文。本笔记重点讨论资料忠实性；部分研究还讨论指令与逻辑一致性。

它们属于模型输出的评价维度。比如原文写错年份，模型照抄可以忠实于原文，却不符合现实；模型添加了一条现实中正确但原文没有的事实，也可能超出“只根据原文总结”的任务范围。

## 常见表现清单

下表均为构造的教学例子，不是已观测到的当前模型行为；“检查依据”是后续定位入口，并不代表已经解决。

| 常见表现 | 直观例子 | 首先检查什么 |
| --- | --- | --- |
| 1. 编造不存在的事实或实体 | 编出一本书、一家公司、一项研究，细节还很完整 | 实体和事件是否存在，有无独立来源 |
| 2. 对真实对象填错属性 | 公司真实存在，却把创始人、日期、地点说错 | 对象与属性的对应关系 |
| 3. 编造数字和精确细节 | 无数据却说“成功率提升 37.6%”，附上虚构样本量 | 原始数据、统计口径、计算过程 |
| 4. 编造来源和引用 | 给出不存在的论文标题、链接、页码或原话 | 来源能否找到，原文是否真有这句话 |
| 5. 来源存在但不支持结论 | 论文只描述相关性，回答却说论文证明了因果关系 | 引用段落能否支撑具体断言 |
| 6. 总结、翻译或抽取时改写事实 | 原文说“部分用户可能受影响”，总结成“所有用户已受影响” | 范围、否定、条件、数量和语气是否被改变 |
| 7. 给资料补上没有的信息 | 报告只说销售下降，回答擅自补成“因为管理层内斗” | 哪些是原文事实，哪些是推测，是否明确区分 |
| 8. 把旧信息当成当前事实 | 用旧版本功能或旧政策回答现在的问题 | 时间、版本和适用范围；这也可能是数据更新故障 |
| 9. 混淆对象和上下文 | 把甲公司的数据安到乙公司，把用户 A 的偏好说成用户 B 的 | 主体、会话、来源绑定；也应排查应用隔离错误 |
| 10. 编造对话历史或用户偏好 | 用户没说过预算，模型却说“你之前说预算是一万元” | 当前可见对话或有来源的记忆是否支持 |
| 11. 编造代码接口或环境能力 | 生成不存在的库函数、参数、文件路径或可用工具 | 实际版本文档、仓库和工具清单 |
| 12. 编造工具结果或完成状态 | 没有运行测试却说“全部通过”，执行超时却说“已成功保存” | 调用记录、结果、产物和实际业务状态 |
| 13. 接受错误前提并继续补故事 | 问题虚构了某公司的收购事件，模型直接解释收购动机 | 问题前提是否成立，不把提问当作证据 |
| 14. 编造推理中的条件或因果链 | 已知 A 与 B 同时出现，回答自行补出不存在的实验来证明 A 导致 B | 前提和中间证据是否存在、推论是否成立 |

同一回答可能同时出现多项。例如虚构一篇论文，再用虚构实验数字声称某技术绝对可靠，会同时涉及事实、引用、数字和因果问题。

## 哪些容易被混称为幻觉

| 现象 | 更准确的区分 |
| --- | --- |
| 算错一道算术题 | 首先是计算错误；虚构计算器输出则另外涉及无依据的结果声明 |
| 检索没找到答案 | 首先是检索或知识覆盖问题；随后无依据地编答案才是新的生成问题 |
| 工具超时、网络失败 | 首先是执行故障；把未知执行状态说成成功则是错误汇报 |
| 没遵守格式或长度要求 | 首先是指令遵循问题，不必全部归为事实幻觉 |
| 顺着用户观点附和 | 属于迎合（Sycophancy，模型交互行为）；可能伴随幻觉，两者不等同 |
| 前后回答矛盾 | 是值得调查的信号，但输入更新、版本变化或明确纠错也能导致答案变化 |
| 按要求写小说 | 明确约定的虚构内容不属于把虚构当事实的错误 |
| 图片里认出不存在的物体 | 属于多模态模型的幻觉表现，本主题后续选学 |

**不要由现象直接跳到原因。** 看到“答了旧政策”，仍要检查是资料旧、检索错、上下文丢失，还是模型没有遵循新资料。

## 后续讨论如何衔接

下一步先拆一个文档问答案例：资料中没有某项信息时，模型应该如何回答；资料中有信息却答错时，应该检查哪一环。

之后再按需要讨论提示约束、RAG、工具、验证、表达未知和评测，不预设某一种方法能够包治所有问题。生产环境还需根据错误后果设置核验强度，并保留回答依据与执行记录。
