## 术语与证据状态

**幻觉（Hallucination）**：本主题关注生成内容与事实、资料或可验证状态不符，或缺乏支持却被表述为已知事实的情况；属于模型输出与应用可靠性问题。具体分类边界见模块笔记。

- 🟢 已核验：综述采用事实性与忠实性两个分类视角；只是资料核验。
- 🔴 待验证：用户对各类问题的理解，以及具体措施在实际任务中的效果。

# 我的笔记

关于AI幻觉的研究，大概有三种路线

| 方向 | 教模型什么 | 一个直观例子 |
|---|---|---|
| **选择性不作答（Abstention）** | 信息不足时保留结论 | “目前资料没有营收数据，无法确定。” |
| **纠正错误前提（False-premise correction）** | 先检查问题是否成立 | 文档写项目尚未发布，用户问发布后的增长，应先指出尚未发布 |
| **减少迎合（Anti-sycophancy）** | 不因为用户坚持就接受错误说法 | 用户质疑正确答案时，重新核验依据，而非立即改口 |


# 后训练，让模型学习适当表达未知

R-Tuning：教大模型说“我不知道”（NAACL 2024）则更直接针对知识边界：先估计模型对哪些问题有把握，再构造带有确定或不确定表达的训练数据，让模型学习适当表达未知。这属于模型后训练，会调整模型参数，比在提示词里写一句“不知道就说不知道”更深入。


# “答题奖励” 机制

强化学习机制，调整模型的行为

可以用一个简化的考试规则理解：
- 答对加分。
- 编错扣分。  主要是 答错，会扣分
- 承认不知道不加不扣。

如果“答错”和“空着”都没有分，而猜对能得分，模型就有动力冒险猜。把错误回答的代价纳入奖励，才可能鼓励它在不确定时停下来。这解释了为什么幻觉治理也涉及训练和评测的激励设计。

# 拒绝回答，并且，指出原因

Abstain-R1（2026 年 4 月预印本）进一步训练模型：除了适当不作答，还要指出关键缺失信息。
https://arxiv.org/abs/2604.17073

例如，用户只提供总收入，却问利润率：
“目前缺少成本或利润数据，因此无法计算利润率。”

# AI幻觉解决办法 - 添加依据

对不同场景的llm内容，需要带上额外的依据

| 场景 | 依据 |
|---|---|
| 公共信息、近期事件 | 官方网页、原始报道 |
| 企业知识问答 | 内部文档、制度条款 |
| 订单、库存、余额 | 数据库或业务接口结果 |
| 代码问题 | 当前源码、依赖版本、测试结果 |
| 数值计算 | 原始数据和计算程序 |

比如，内部知识库，RAG检索，拿到文档id和名字，就是一个外部依据

可选，二次验证
可选：“用户问题、答案中的具体断言、对应证据”交给复核模型，让它判断：支持、矛盾，还是证据不足。

# 其他业内解决方案

1. 自己提供可靠的数据源：RAG、MCP、TOOL

2. 一致性检查：业内常称为 Groundedness checking，依据一致性检查，属于应用校验层。
其实就是检查 回答 、 资料 ，俩含义是否一致

| 公开产品 | 做什么 |
|---|---|
| **微软 Azure AI Content Safety** | 检测回答与提供资料的不一致；还提供预览版纠正能力。[官方说明](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/groundedness) |
| **Google Cloud Check grounding** | 输入答案和参考事实，返回支持分数，以及各项结论对应的引用。[官方说明](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding) |
| **AWS Bedrock Contextual grounding** | 检查回答是否被来源支持、是否切题，并按阈值过滤；有明确的任务适用限制。[官方说明](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-contextual-grounding-check.html) |

3. 模型后训练、强化学习： 教模型说不知道、拒绝回答
