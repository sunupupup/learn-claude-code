# 长任务工程知识图谱

这张地图说明问题之间的关系，不是一次要学完的清单。范围与验收见 [Change](../../../specs/changes/C-2026-026-study-long-running-agent-tasks-and-goals.md)，学习进度见[总览](LEARNING_NOTES.md)，查词见[名词清单](名词清单.md)。

## 1. 完整技术链路

```text
用户目标 + 成功标准 + 权限/预算
  → 计划：步骤、依赖、阶段检查
  → 从保存的任务状态和证据中选下一步
  → 模型提出动作 → Harness 检查与执行工具
  → 保存实际结果、产物和执行记录
  → 验证当前步骤；需要时调整计划
  → 继续 / 等待事件或批准 / 核对未知结果 / 停止
  → 跨轮或重启时恢复所需状态并重建模型上下文
  → 对照用户目标验收，报告结果与未解决项
```

Harness 是模型外围的执行与支撑程序：负责发起模型调用、执行工具、维护状态等；具体具备哪些机制取决于实现。**模型负责提出下一步，不意味着它自己保存了全部进度或能在进程退出后自动运行。**

这是一张通用观察框架；各环节可以由同一程序或不同组件承担，不预设所有框架都具备完整实现。

## 3. 概念之间的关系

- **目标与计划是“终点与路径”的关系**：目标定义结果，计划组织行动；改路径时仍需保留约束。
- **任务状态与完成证据是“记录与依据”的关系**：状态便于选择下一步，证据用于支持或推翻状态；不能只因字段写成 `completed` 就认为工作正确。
- **持久状态与模型上下文是“保存与使用”的关系**：状态可以长期保存，程序仍需按当前步骤把相关部分提供给模型；保存不等于自动读到。
- **记忆、历史和任务记录可以组合**：用户偏好属于长期记忆，历史保存对话，任务记录描述工作进度；不把所有“记得”都归为同一机制。
- **后台执行与自动继续解决不同环节**：前者承载慢操作，后者决定何时发起下一轮；后台工具完成与模型收到结果可能发生在不同时刻。
- **检查点、重试与幂等相互配合**：检查点提供恢复入口，重试再次尝试，幂等约束重复动作的效果；仅保存检查点不能自动解决副作用重复。
- **程序校验与模型评判可以组合**：前者适合可明确计算的规则，后者辅助语义评价；评判输入缺证据时不能凭分数补出真实事实。

## 4. 主线与选学扩展

**必学主线：单执行者，一个目标，一组可核验产物。** 依次学习完成证据、规划、可信进度、持续执行、上下文保持、恢复和停止条件，再串联最小实验。

后续串联实验计划覆盖：漏处理却宣告完成、中途退出、产物已写但进度未记、压缩后继续、取消后迟到结果、无进展/预算停止。均未实施；每次只选当前问题需要的一个实验。

选学分支按需要深入：多执行者与租约、分布式恢复、工作流版本迁移、跨机器容灾、多 Agent 协作、复杂补偿。不把它们当作所有长任务的必要前置。

**Codex Goal 实现继续暂缓，Typed Evals 只留存。** 主线先学会提出和检查问题，再进入特定产品实现。
