# 长任务工程名词清单

这是按块查词的入口，不是背诵或已掌握清单。完整关系见[知识图谱](长任务工程知识图谱.md)，进度见[总览](LEARNING_NOTES.md)。术语用于建立通用观察框架，不预设某个产品的具体实现。

## 1. 完成与证据

| 词 | 中文解释、所属层与相邻概念 |
| --- | --- |
| Acceptance Criteria | 成功/验收标准，属于用户需求与验证层：事先说明什么结果才算完成。不同于“准备怎么做”的计划。 |
| Artifact | 产物，属于执行结果层，如摘要文件、报告、构建包。文件存在还不代表内容符合需求。 |
| Evidence | 证据，属于结果与验证层，如实际产物、执行输出或检查报告。证据需要说明来源和能证明的范围。 |
| Verifier | 验证器，属于 Harness/业务层，按约定规则检查结果。不能只把 AI 的一句“通过”换个名字。 |
| Eval / Judge | Evaluation 是评测，Judge 是评判者；属于质量评价层。可以使用程序或模型，模型评分不等同于业务事实。 |

## 2. 目标、计划与步骤

| 词 | 中文解释、所属层与相邻概念 |
| --- | --- |
| Goal | 目标，属于任务定义层：描述最后要达到什么结果。这里是通用词，不自动指 Codex 的 Goal 功能。 |
| Plan | 计划，属于决策与任务编排层：当前准备采用的路径，可以随新信息调整。 |
| Task / Dependency | 任务与依赖，属于任务系统层：任务是可跟踪的工作单元，依赖说明它开始前需要哪些条件。 |
| Run / Attempt | 一次运行与一次尝试，属于执行层。同一任务可能多次尝试；“尝试过”不代表成功。具体项目可能采用不同命名。 |
| Replanning | 重新规划，属于决策层：根据结果调整步骤或顺序，不应悄悄改变用户的成功标准。 |

## 3. 进度与上下文

| 词 | 中文解释、所属层与相邻概念 |
| --- | --- |
| Task State / State Machine | 任务状态与状态机，属于任务系统层。状态记录当前处境，状态机规定允许怎样变化；两者都需要与实际结果对齐。 |
| Persistence | 持久化，属于存储层：把状态保存到进程退出后仍可读取的位置。只存在内存里的变量不具备这种性质。 |
| Context | 上下文，属于模型输入层：当前这次模型调用实际获得的信息。磁盘上保存了什么，不等于本次输入里就有什么。 |
| Memory / History | 长期记忆与会话历史，属于信息存储与检索层：前者常保存偏好或提炼事实，后者保存对话过程；都不能自动替代可信任务进度。 |
| Compaction | 上下文压缩，属于 Harness 的输入管理层：减少历史占用，同时尽量保留继续任务所需的信息；不等同于任务已被可靠保存。 |
| Trace | 执行轨迹，属于可观测层：记录调用、事件和结果。日志内容是否完整、来源是否可信，仍要检查。 |

## 4. 执行、等待与唤醒

| 词 | 中文解释、所属层与相邻概念 |
| --- | --- |
| Harness | 智能体外围执行与支撑程序，承接模型调用、工具、上下文与控制流程；实际能力取决于实现。 |
| Agent Loop / Turn | 智能体循环与轮次，属于 Harness/运行层。一轮内可能经历多次模型与工具交互；跨轮继续还需要触发和控制机制。 |
| Background Task | 后台任务，属于工具执行层：慢操作异步运行。它完成后，还需要有人回收结果、决定下一步。 |
| Scheduler / Event | 调度器与事件，属于触发/运行层：调度器按时间或条件安排工作，事件表示发生了变化；二者都不自动证明任务完成。 |
| Polling / Wake-up | 轮询与唤醒，属于运行层：前者反复查询状态，后者让等待中的执行流程重新获得推进机会。 |

## 5. 恢复与停止

| 词 | 中文解释、所属层与相邻概念 |
| --- | --- |
| Checkpoint | 恢复检查点，属于执行与存储层：保存继续任务所需的状态。具体保存哪些内容取决于系统，不保证包括外部副作用。 |
| Resume / Retry | 恢复/继续与重试，属于执行层：恢复接续已有状态，重试再次尝试某个动作；不是同一种操作。 |
| Idempotency | 幂等，属于工具/业务层：设计重复请求的效果，避免同一业务操作被重复办理。它与“尽量少重试”是不同的保障。 |
| Unknown Outcome | 结果未知，属于执行与核对层：目前不能确认操作成功或失败；不应直接按失败重新办理。 |
| Durable Execution | 持久执行，属于运行基础设施层：结合保存状态、事件或恢复机制承接中断后的工作；不能仅因聊天记录落盘就认定具备。 |
| Budget / No Progress | 预算与无进展，属于运行控制层：预算限制资源消耗，无进展指有效结果没有推进。消耗很多资源不代表有进展。 |
| Blocked / Paused / Cancelled | 阻塞、暂停、取消，属于控制状态：分别强调缺少继续条件、暂时停止、撤销继续意图。它们都不等于外部动作已经停止或回滚。 |
