# 第二阶段自测：Pir 项目

> 学完再做：先独立回答，再用固定版本源码核对；注明“源码确认 / 本次运行 / 线上未知”。不要用旧目录或历史报告替代当前证据。
> 复习入口：[Pir 对照学习](./02-Pir对照学习.md)、[现状核验](./Pir现状核验.md)。

## 请求与数据

1. 从 BFF 收到请求到用户收到回复，按顺序说出 Pir 的主要调用链。模型调用与工具执行分别在哪里？
2. 选一个 turn，列出关联请求、会话、模型和工具的关键 ID；如果跨服务记录断开，你会查哪一段？
3. 公共流事件、会话历史、遥测 Trace、聚合指标分别保存什么、解决什么问题？能互相替代吗？
4. Rust 的 model/tool span、runtime.stream_event、BFF 原文采集有哪些内容差别？为什么不能笼统说“全部是哈希”或“全部原文完整保存”？
5. 一条内容只有长度和 SHA-256，能不能直接用于模型语义评测？还缺什么证据，应该从哪里取？
6. Langfuse 中没有记录，如何区分未采集、未启用、投递失败、缓冲未发送和平台不可查？指标面板存在能证明什么？

## Eval、回放与质量流程

7. 通用 pir-eval 与产品 pir-popipo-eval 各负责什么？从一条 YAML 到最终报告，谁运行 Agent、谁执行断言？
8. runtime target 与 server target 的验证范围有什么区别？为什么不能单凭 server target 就认定用了真实模型？
9. tool_called、tool_succeeded、side_effect_exists 分别能证明什么？异步任务提交成功后，还缺什么才能判断业务完成？
10. 选两个名称容易高估的断言，找到实际实现，说出读取字段和漏检可能；例如 trace_has_terminal_span、no_claim_without_tool_result。
11. trace.json、events.json、response.json、transcript.md、report.json 各用来排查什么？trace.json 是完整远端 Span 树吗？
12. 历史上下文回放、turn_replay、full_replay、continue_next 分别意味着什么？fork 新 session 后为什么仍可能影响源工作区？
13. 怎样证明 baseline 比较条件一致？当前比较报告、单次 case 执行和成本/延迟预算之间有哪些边界？
14. 质量流程里的 observation 与 required 有什么区别？CI 通过、发布有质量证据，是否足以证明真实模型质量达到要求？请指出实际配置。

## 综合练习

15. 选一个工具失败或编辑冲突案例，讲清：如何发现 → 哪份记录取证 → 怎样安全复现 → 写什么断言 → 修改哪里 → 如何比较回归 → 还缺哪些线上证明。

## 自查完成条件

- 至少沿固定版本源码讲通一条请求和一个评测案例。
- 回答“项目已经支持”时，能指向实现、配置和证据等级。
- 能指出一个断言局限、一个回放边界和一个质量门禁缺口。
- 未真正运行的案例标“待实践”，不把源码存在算作运行通过。
