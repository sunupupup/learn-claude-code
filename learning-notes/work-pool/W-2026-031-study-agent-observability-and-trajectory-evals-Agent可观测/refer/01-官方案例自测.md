# 第一阶段自测：官方案例

> 学完再做：先不翻资料，用自己的话回答；不会的标“待复习”。不要求背 API，优先用自己的 Trace、源码和实验结果解释。
> 复习入口：[官方案例学习](./01-官方案例学习.md)。

## 基础理解

1. 沿一次用户请求，讲清模型、工具、Agent 程序与 Langfuse 各自做了什么。是谁真正执行工具？
2. 两轮聊天，每轮各有两次模型调用和一次工具调用，你会怎样组织 Session、Trace 和内部步骤？这种对应关系由谁建立？
3. 平台能看到模型调用，却看不到工具过程，你会先检查什么？“接入了 Langfuse”为什么不能证明记录完整？
4. 一条 Trace 应怎样关联提示词版本？版本号与 production 这样的标签有什么区别？

## 评测与迭代

5. Workshop 的平台在线监控和本地离线实验分别由谁触发、在哪里执行？请各画一条数据流。
6. 一条测试案例的输入、预期结果、Agent 实际输出、评分标准分别是什么？选一个案例举例。
7. keyword_overlap 高而 correctness 低，可能是什么原因？两个分数相反时又该怎样排查？
8. 用户反对助手的回答，能直接判定助手错误吗？这种监控信号适合怎样使用？
9. 你修改了一条提示词，新实验平均分更高：还要检查哪些逐例结果和实验条件，才能判断修改是否有效？

## 综合练习

10. 用一个亲自完成的实验说明：发现了什么问题 → 原始证据是什么 → 为什么这样修改 → 固定了什么条件 → 哪些案例改善或退化 → 最后是否保留改动。

## 自查完成条件

- 能脱离页面解释一次执行和两条评测链。
- 能指出至少一条 Trace 和一份实验对比作为证据；未运行则标“待实践”。
- 能解释评分的局限，而不是只复述总分。
- 卡住时回到对应章节，不因看过题目就更新掌握状态。
