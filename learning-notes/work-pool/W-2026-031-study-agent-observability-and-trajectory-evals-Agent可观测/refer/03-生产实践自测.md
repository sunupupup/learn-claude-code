# 第三阶段自测：生产实践进阶

> 学完再做：以一个 Pir 场景作答，说明选择理由、代价和验证方法；允许有多种方案，不要求背某家公司的做法。
> 复习入口：[生产实践进阶](./03-生产实践进阶.md)。

## 测量与证据

1. Agent 说“文件已更新”，工具也返回成功，你如何分别验证答案质量、轨迹合法性和真实业务结果？
2. 同一操作发生重试、异步等待或子任务时，如何关联记录，又避免把多次尝试误算为多个业务结果？
3. 原文、哈希、脱敏文本和受控内容引用分别适合什么用途？如何兼顾排障、评测、权限和保留/删除？
4. 使用采样后，怎样避免把“没有看到失败”误解为“没有失败”？哪些采集与导出故障也需要监控？

## 评测可信度

5. 一个线上问题怎样成为可信测试案例？需要固定哪些输入、环境、初始业务状态、预期结果和来源？
6. 什么适合代码规则，什么适合模型评委，什么仍需人工？用一个误报和一个漏报说明。
7. 怎样判断评委本身可靠？如果评委调用失败、返回格式错误，应怎样与被测 Agent 的业务失败分开记录？
8. 总体分数提高，但高风险操作成功率降低，你如何判断？需要哪些分组指标和不能被平均掉的约束？
9. 为什么同一个版本需要重复试验？pass@k 与 pass^k 分别关心什么？你的业务更看重哪一个？
10. 如何防止不断针对测试题修改提示词，最终只在已知样本上变好？怎样处理测试集版本、保留集和新分布？
11. 重跑有写入、扣费或媒体生成的任务，需要怎样隔离环境、管理幂等、清理资源和保留结果未知状态？

## 监控与发布

12. 为一个 Agent 任务定义业务成功率、延迟、成本、服务错误和评测覆盖口径；哪些是实测事实，哪些是评委估计？
13. SLI、SLO 与错误预算分别是什么？一个告警触发后，谁应该做什么，如何避免只增加噪声？
14. 离线评测通过后，为什么还需要有限灰度？请给出进入、扩大、暂停和回滚的条件，以及使用的对照。
15. 代码、模型、提示词、工具或评委变化时，如何定位当前版本并恢复？业务写入能否随版本回滚一起撤销？

## 综合演练

16. 为一个 Pir 改动做发布评审：问题与证据 → 固定基线 → 候选方案 → 重复评测 → 人工复核 → 回归门禁 → 灰度观察 → 回滚/保留 → 新案例回流。逐项写清负责人、输入、输出和通过条件。

## 自查完成条件

- 能说明方案的适用范围、取舍和失败处理，而非只列平台名。
- 能用证据解释“值得发布”，同时指出仍未确认的风险。
- 能把新问题转成后续回归，不只修好眼前一个案例。
- 没有实际发布与线上观测时，将综合结果标为演练。
