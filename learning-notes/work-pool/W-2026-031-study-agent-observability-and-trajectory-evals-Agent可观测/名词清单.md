# 名词清单

> 这份清单是本章的概念导航，不要求一次背完。先把整体分块看懂，再按学习进度逐步确认每个词。涉及具体 SDK、字段规范和产品行为时，以学习时核对的官方版本为准。

## 先看全章：有哪些知识块

- **Agent 执行链：**用户请求怎样经过模型、Harness、工具、工作区和子 Agent，最后结束或留下未知结果。
- **观测数据模型：**怎样把一次任务的路径拆成 Trace、Span、Event，并保留步骤间的因果关系。
- **相邻数据与证据：**Trace、日志、指标、业务状态、审计和权限策略各回答什么问题。
- **OpenTelemetry 导出链：**谁负责产生和整理观测数据，OTLP 如何把数据送到 Collector 或后端。
- **轨迹评测与回归：**如何用固定任务和明确断言检查 Agent 是否选对工具、顺序正确、没有越权或越界写入。
- **安全与可靠性：**观测数据如何保护隐私；失败、重试和响应丢失时如何避免漏记或重复副作用。

把这章的主线压成一句话：**Agent 负责执行任务，Trace 记录执行路径，OTLP 搬运观测数据，轨迹评测检查记录到的行为是否符合要求；真正阻止越权的仍是执行前的权限控制。**

## 一、Agent 执行链：被观察的对象

- **Agent（智能体；应用 / Harness 层）：**由模型参与决策，并能在程序设定的边界内使用工具推进任务的系统。它不等于模型本身。
- **Agent Run（一次 Agent 运行；应用 / Runtime 层）：**从接收一项任务到结束的一次执行过程。一次 Run 可能包含多次模型调用和工具调用。
- **LLM / Model Call（大语言模型 / 模型调用；模型接口层）：**应用把输入交给模型并接收输出的一次请求。模型可以提出下一步动作，但这不表示动作已执行。
- **Tool Call（工具调用请求；模型与 Harness 交界）：**模型生成的工具名称和参数。它只是请求；Harness 还要检查、授权并决定是否执行。
- **Tool Execution（工具执行；Harness / Runtime 层）：**程序实际调用函数、服务或命令的过程。读文件、改文件、发请求等真实副作用发生在这一侧。
- **Harness（执行控制层 / 工程脚手架）：**包围模型的程序，负责组装输入、控制循环、检查工具请求、执行权限策略、处理结果和限制预算。
- **Runtime（运行时；执行基础设施层）：**负责让 Agent 程序实际运行，并管理状态、并发、取消、超时、暂停或恢复的机制。产品中 Runtime 和 Harness 可能打包在一起，但概念职责不同。
- **Workspace Change（工作区变更；工具 / 文件系统层）：**Agent 执行期间对项目文件造成的实际变化，例如新增、修改或删除文件。模型说“我改好了”不是变更证据，Diff 或文件状态才是。
- **Subagent Run（子 Agent 运行；委派 / Runtime 层）：**父 Agent 委派出的另一段 Agent 执行。子 Agent 的文本摘要不一定包含它的所有工具轨迹或文件副作用。
- **Side Effect（副作用；业务 / 外部系统层）：**除了返回一个值，还改变文件、数据库、工单、订单或其他外部状态的操作。
- **Operation ID（业务操作编号；业务 / Runtime 层）：**用于识别一次真实业务动作的编号。它可能跨越多次网络尝试，用来查询“动作到底发生了没有”。

## 二、观测数据模型：怎样描述执行路径

- **Observability（可观测性；系统诊断能力）：**通过系统输出的数据，判断内部运行情况的能力。收到了遥测数据不代表系统已经安全或完全可诊断。
- **Telemetry（遥测数据；观测管线）：**程序产生并发给观测系统的数据总称，常见有 Trace、Metric 和 Log。
- **Trace（追踪；应用 / Runtime 观测层）：**一组能关联起来的操作记录，用于还原一次请求经过系统的路径。它通常由多个 Span 组成。
- **Span（跨度；Trace 中的操作单元）：**一次有开始和结束时间的操作，例如一次模型请求或一次工具执行。Span 可以记录结果状态和描述该操作的属性。
- **Root Span（根跨度；Trace 结构）：**Trace 的起点 Span，例如代表一次 Agent Run 的 Span。具体系统是否这样命名或建模需要看实现。
- **Parent / Child Span（父 / 子跨度；Trace 结构）：**一个操作及其内部子操作之间的层级关系，例如 Agent Run 包含模型请求和工具执行。
- **Span Event（跨度事件；Trace 内的时间点）：**发生在某个 Span 期间、具有明确时间点的记录，例如“权限判断为拒绝”。它不像 Span 那样表示一段持续时间。
- **Attribute（属性；Span / Event 的描述字段）：**描述操作的键值信息，例如工具名、结果状态或尝试次数。敏感内容和取值变化特别多的字段不应不加判断地记录。
- **Trace ID（追踪编号；关联标识）：**用于识别同一条 Trace 的编号，帮助接收端把相关 Span 归到一起。它不是用户身份、访问令牌或权限凭证。
- **Span ID（跨度编号；操作标识）：**用于识别 Trace 中某个 Span 的编号；父子关系会引用相关 Span ID。
- **Context Propagation（上下文传播；跨边界关联机制）：**把 Trace 的关联信息从一个组件或服务传到另一个组件，使不同地方产生的 Span 能被正确关联。它传播的是观测关联上下文，不是 Agent 的全部对话上下文。
- **Span Link（跨度链接；因果关联）：**把两个 Span 关联起来但不强行表示父子包含关系；可用于异步、并行或稍后才执行的工作。

## 三、相邻数据与证据：不要把问题混在一起

- **Log（日志；应用诊断数据）：**某个时刻发生的记录，常用于描述错误或程序消息。日志可以带 Trace ID 与 Trace 关联，但日志本身不自动形成 Span 的父子路径。
- **Metric（指标；聚合观测数据）：**按时间聚合的数值，例如错误率、运行耗时或调用次数。适合看趋势，不一定能还原某一个 Run 的完整过程。
- **State（状态；业务 / Runtime 数据）：**系统当前保存的事实，例如审批状态、任务是否完成、工单 ID。状态源通常比模型回答更适合判断业务动作是否真的生效。
- **Audit Record（审计记录；安全 / 治理层）：**回答谁在何时、以什么身份、依据什么决策做了什么操作。审计通常需要明确身份、授权和保留要求，不能只依赖一般调试 Trace。
- **Policy / AuthZ（策略 / 授权；安全控制层）：**在动作执行前判断当前主体是否允许执行某项操作。Trace 可以记录判断结果，但记录本身不能替代授权检查。
- **Event（事件；泛称）：**广义上表示某个事情发生了。Span Event 是 OpenTelemetry Trace 中的一种具体记录；业务 Event、日志行和 Span Event 不必然是同一种数据对象。
- **Evidence（证据；验证层）：**可独立检查的事实，例如文件 Diff、数据库状态或操作 ID。模型自述、Trace 字段和真实外部状态的证明力不同，需要分别判断。

## 四、OpenTelemetry 与 OTLP：数据怎样被送出去

- **OpenTelemetry（开放遥测生态；观测标准与工具）：**一套跨语言生成、传播、处理和导出观测数据的 API、SDK、协议及工具生态。它不规定 Agent 的业务权限规则。
- **Instrumentation（埋点 / 仪表化；应用代码或自动探针）：**让程序在关键位置产生 Span、Event 或 Metric 的做法。自动埋点方便，但未必了解 Agent 的业务含义。
- **API（应用编程接口；观测编程边界）：**程序用于创建或操作观测对象的接口定义。API 定义怎样调用，不一定负责批量处理和发送数据。
- **SDK（软件开发工具包；观测实现层）：**具体语言中的实现，负责采样、处理、批量和导出等行为。不同语言 SDK 和版本细节可能不同。
- **Semantic Conventions（语义约定；字段命名层）：**对常见操作的名称和属性含义作统一约定，让不同组件较容易互相理解。约定字段不等于强制授权，也不代表所有 Agent 字段都已稳定。
- **OTLP — OpenTelemetry Protocol（OpenTelemetry 协议；传输层）：**OpenTelemetry 用于编码并传输遥测数据的协议，可把数据从产生端发往中间节点或后端。它不决定记录什么业务行为，也不评判 Agent 是否正确。
- **Exporter（导出器；SDK 到接收端的发送组件）：**把 SDK 中的观测数据按所配置的协议和地址发出去的组件。
- **Collector（收集器；遥测中间层）：**可接收、处理、过滤或转发遥测数据的服务。是否部署 Collector 取决于系统需求。
- **Backend（观测后端；存储与查询层）：**接收并保存观测数据、提供检索或可视化的系统。它可以是自托管服务或商业产品。

## 五、轨迹评测与回归：怎样判断行为合不合格

- **Evaluation / Eval（评测；质量验证层）：**依据预先定义的任务和判定标准，检查 Agent 结果或过程是否满足要求。它不等于只看最终文字。
- **Eval Set / Evaluation Dataset（评测集；验证数据）：**一组固定或版本化的代表性任务，用于重复比较不同版本的 Agent。
- **Trajectory（执行轨迹；Agent 行为序列）：**Agent 实际经过的动作过程，例如模型调用、工具选择、参数、顺序、拒绝、重试和委派。
- **Trajectory Eval（轨迹评测；Agent 行为评测）：**检查执行轨迹本身是否符合约束，例如是否调用了授权工具、是否先审批再写入、是否超出允许工作区。
- **Oracle（判定依据；Eval 设计）：**用来判断一个用例是否达到预期的答案、状态或规则。Oracle 可以是程序断言、已知结果或经审核的人工标准。
- **Grader（评分器；Eval 执行器）：**根据 Oracle 对运行结果打分或判定通过 / 失败的程序、规则、模型或人工流程。
- **Deterministic Assertion（确定性断言；代码级验证）：**对可精确检查的行为作明确判断，例如“未经批准不得写文件”或“只允许一次创建请求”。相同输入和状态下应得到相同判断。
- **LLM-as-a-Judge（用模型作评审；辅助评分）：**让模型评价文本质量或语义是否充分。它可能有偏差，不应成为权限和副作用安全的唯一真值来源。
- **Baseline（基线；比较起点）：**用于与新版本比较的一组既有结果或指标。没有基线时，很难判断修改是改善还是退化。
- **Regression（回归；质量退化）：**修改模型、Prompt、工具或 Runtime 后，原本满足的行为变得不满足。
- **Regression Gate（回归门禁；发布控制）：**在发布前运行必要的检查，并根据失败规则阻止不合格变更进入后续环境。
- **Offline Eval（离线评测；预发布验证）：**用存下来的固定用例评测，不直接影响真实用户；但用例覆盖有限，不能代表所有生产输入。

## 六、安全、隐私与失败边界

- **Data Minimization（数据最小化；隐私治理）：**只记录排查问题和验证行为所需的信息，避免把完整 Prompt、工具参数、文件正文或秘密默认放入 Trace。
- **Redaction（脱敏；观测数据处理）：**在保存或导出前隐藏凭据、个人信息等敏感值；脱敏规则本身也要验证，不能只依赖约定。
- **Sampling（采样；数据量控制）：**只保留一部分 Trace 或事件，降低存储与处理成本。采样可能漏掉罕见失败，需要按风险设计保留策略。
- **High Cardinality（高基数；指标设计风险）：**某字段取值种类非常多，例如每次变化的请求 ID。把它做成指标标签可能导致查询与存储负担；详细 ID 更适合在受控 Trace 中按需检索。
- **Retention（保留期限；数据治理）：**遥测数据保存多久以及何时删除，需要与隐私、审计和排障要求协调。
- **Retry（重试；可靠性机制）：**失败后再次尝试某个操作。对只读请求和有副作用的写操作，重试风险不同。
- **Idempotency Key（幂等键；副作用控制）：**让重复提交的同一逻辑操作可以被识别，减少重试造成的重复创建或重复扣款。它不能保证所有下游都正确实现幂等。
- **Unknown Outcome（结果未知；分布式失败状态）：**请求超时或响应丢失后，系统无法确定副作用是否已发生。应通过操作编号或查询业务状态核实，而不是盲目再次执行。
- **Fail Open / Fail Closed（故障时放行 / 关闭；策略选择）：**某个检查服务不可用时，选择继续还是停止敏感操作。观测数据发送失败是否影响业务，要按风险区分；授权检查失败时的策略不能随意等同于普通 Trace 导出失败。
