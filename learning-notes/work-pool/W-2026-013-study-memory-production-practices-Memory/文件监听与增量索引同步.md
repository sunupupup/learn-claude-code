# 问题描述

本地 Agent 正在运行。它把 Markdown 作为记忆原文，并把文件切成片段，写入 SQLite 的全文索引供 BM25 搜索。我在编辑器里把 `memory/a.md` 中的「项目甲默认用 npm」改成「项目甲默认用 pnpm」并保存。此时，文件里已经是新内容，搜索仍可能查到旧内容。

- 文件保存后，程序怎么发现 `a.md` 变了？
- 索引器怎么找到这份文件对应的片段，更新受影响的记录并清除旧记录？
- 从保存文件到 `pnpm` 能被搜到，中间有哪些环节？如果 Agent 在更新前发起搜索，或已经拿到了旧结果，它会用到哪一版？


其实不光是Agent有这个问题

就比如我们IDE里面，在bash改了文件，IDE这边如何显示最新的内容呢 ？

# 解决办法

文件监听器

其实，目的很明显，下一次检索，能不能检索到最新的数据

1. 监听目录

Agent 启动时订阅 memory/ 的文件变更， Window有自带的ReadDirectoryChangesW

2. 刷新索引

到 memory/a.md 的变更通知后，把这个路径加入待更新队列

首先要合并通知，防止文件多次更改，然后读取文件最新的内容
在一次 SQLite 事务里替换该路径对应的旧索引记录。文件已删除时，就清掉它对应的索引。

一般不需要判断有没有正在运行的 session。

查了 OpenClaw 的默认 Memory Core：Agent 把记忆写进 Markdown，文件监听器触发后台索引更新，Memory Core 的索引器负责写 SQLite。 
这条 Markdown 同步链路无需等 session 结束

而且关于memory tool写入记忆，直接写md就行，索引的更新都是由监听器来完成


# OpenClaw的做法

1. Agent 保存 MEMORY.md 或日期笔记。 
这是记忆正文的写入。
https://docs.openclaw.ai/concepts/memory#how-it-works

2. 文件监听器收到变更，标记索引待更新。 

源码里 markDirty() 会调用 scheduleSync()。
官方文档给出的默认防抖是 1.5 秒，用于合并连续修改。

监听器源码：https://github.com/openclaw/openclaw/blob/81ab38df631ca077dbd68e7506579a0d2c5b2ba9/extensions/memory-core/src/memory/file-watcher.ts#L539-L596
官方索引文档：https://docs.openclaw.ai/concepts/memory-builtin#how-indexing-works

3. 索引器在后台更新数据库。
作者的测试直接修改 Markdown，然后检查 SQLite 中的记录是否更新。测试特意直接读数据库，避免一次 memory_search 掩盖监听链路的问题。
https://github.com/openclaw/openclaw/blob/81ab38df631ca077dbd68e7506579a0d2c5b2ba9/extensions/memory-core/src/memory/manager.watcher-filesystem.test.ts#L152-L178
