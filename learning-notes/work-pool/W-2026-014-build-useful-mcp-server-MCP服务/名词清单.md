# MCP 服务名词清单

> 查词入口，不是背诵清单或掌握证明。括号内标出英文全称/系统层次，并简述邻近概念区别。

## 角色与调用层

| 术语 | 初学者解释 |
|---|---|
| Host（宿主应用，Agent/Harness 层） | 管理对话、模型请求、可用能力、权限策略和结果回填的应用；MCP Client 常由它管理。它不是 MCP Server。 |
| MCP Client（协议客户端，MCP/Transport 层） | 代表 Host 与某个 MCP Server 交换 MCP 消息的组件；通常不负责业务 API 的最终授权。 |
| MCP Server（能力服务端，MCP/业务适配层） | 向 Client 暴露 Tools、Resources、Prompts，并把请求适配到业务系统；名字里的 Server 不要求一定远程部署。 |
| Tool Calling / Function Calling（模型工具调用，LLM/API 层） | 模型输出一个工具名和参数作为建议；由 Host 决定并实际执行。它不是 MCP 请求本身。 |
| 下游业务服务（API / DB 层） | 提供最终数据或动作的系统，例如 GitHub API、Jira API 或 PostgreSQL；MCP 只统一接入外壳。 |
| Gateway（网关，部署/安全层） | 代理或汇聚多个服务，可加路由、认证和审计；不是每个 MCP 项目必需，也不能自动补齐下游授权。 |

## 协议与能力

| 术语 | 初学者解释 |
|---|---|
| MCP（Model Context Protocol，应用互操作协议层） | Host 与外部能力提供者之间共享的发现和调用约定；不等于模型推理框架。 |
| JSON-RPC（JSON Remote Procedure Call，消息格式层） | 用 JSON 表达请求、响应、通知的方法约定；MCP 复用其请求/响应形态，但不等于普通 REST API。 |
| Protocol version（协议版本） | 说明双方按哪一版字段和生命周期理解消息；版本变化会改变 method 与协商方式。 |
| `server/discover`（能力发现方法） | 2026-07-28 规范新增的服务发现调用；对比旧版 `initialize` 握手，它不建立协议级会话。 |
| Tool（工具，动作能力） | 让 Client 请求 Server 执行一个命名操作，常见为查数据或触发动作；不保证只有读取权限。 |
| Resource（资源，可读内容能力） | 用 URI 表示可读取的数据，由 Host 决定何时读取/放入上下文；不是 Tool 的另一种拼写。 |
| Prompt（提示模板能力） | Server 提供可参数化的消息模板；Host 取回并决定怎么用于对话，不直接等同系统提示。 |
| Schema（数据契约/结构描述） | 说明参数或结果的字段和类型；Schema 有效不代表业务授权通过。 |
| Annotation（注解/提示元数据） | 帮助 Host 理解能力特性的辅助描述；本身不能证明安全或授予权限。 |

## 传输、状态与边界

| 术语 | 初学者解释 |
|---|---|
| stdio（标准输入输出传输） | Client 启动本地 Server 子进程，通过 stdin/stdout 交换消息；stdout 被日志污染会破坏协议。 |
| Streamable HTTP（可流式 HTTP 传输） | Client 经 HTTP 请求远程或本机服务，响应可流式返回；HTTP 连接复用与协议状态是两回事。 |
| Session / protocol-level session（协议会话） | 旧版 MCP 用握手和会话标识管理跨请求交互；2026-07-28 核心移除这类协议级会话。 |
| Stateless（无协议会话状态） | 服务无需靠前一条 MCP 请求识别协议上下文；不代表数据库写操作、长任务或业务进度没有状态。 |
| Multi-round-trip request（多轮请求） | 新版用多次完整请求/响应来处理需要用户补充输入的操作，区别于旧会话中的服务端主动反向请求。 |
| Subscription（订阅） | Client 请求持续接收某类变化通知；要按协议版本与传输核验，不能套用旧版通知/资源订阅方法。 |
| Trust boundary（信任边界，安全层） | 不同身份或权限范围间的界线；模型生成的参数和工具返回文本默认都不能越过服务端授权。 |

## 生产工程

| 术语 | 初学者解释 |
|---|---|
| Authentication / AuthN（身份认证） | 证明“调用者是谁”；不等于这个身份能操作任何对象。 |
| Authorization / AuthZ（授权） | 判断“这个身份此刻能对哪个对象做什么”；仅隐藏工具或筛选发现列表不能代替执行时检查。 |
| Idempotency（幂等） | 同一逻辑请求重做不会重复产生额外副作用；和网络层自动重试不是一回事。 |
| SLO（Service Level Objective，服务目标） | 为延迟、成功率、恢复时间等设定量化目标；一次运行成功不是 SLO。 |
| Trace（链路追踪） | 把一次模型任务、MCP 请求和下游 API 调用关联起来，帮助定位跨服务故障。 |
| Contract test（契约测试） | 检查双方报文/Schema 是否符合约定；不证明业务逻辑安全或模型选工具效果好。 |
| Conformance test（协议一致性测试） | 检查实现是否遵循某一固定版协议；和目标客户端端到端测试互补。 |
