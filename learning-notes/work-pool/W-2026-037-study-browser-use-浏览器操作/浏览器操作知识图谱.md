# 浏览器操作知识图谱

**地图负责导航；源码事实、具体默认行为和实验结论在学习时另行核验。**

## 完整技术链路

用户目标与成功标准 → 获取页面状态（结构/截图）→ 整理模型输入 → 模型选择动作 → Harness 分发工具 → 浏览器控制接口执行 → 等待并重新观察 → 判断继续、完成或结果未知。

这是通用观察框架，不代表每个浏览器 Agent 都使用相同接口。

## 问题与扩展方案

| 面对什么问题 | 改变哪个环节、怎么改 | 概念或方案 | 深入入口 |
| --- | --- | --- | --- |
| 页面有哪些可操作对象？ | 观察环节提取结构和语义 | DOM、可访问性树、布局 | CDP 官方协议 |
| 结构无法完整表达画面？ | 观察环节增加视觉信息 | 截图、视觉定位 | browser-use 项目候选 |
| 如何让浏览器执行动作？ | 执行环节发送命令并接收事件 | CDP、工具封装 | CDP 官方协议 |
| 目标元素变化或尚未加载？ | 定位和等待后重新观察 | 定位器、过期状态、超时 | 后续固定项目追调用链 |
| 多步操作如何维持同一身份？ | 保留浏览器环境状态 | 标签页、会话、Cookie | 后续源码与本地实验 |
| 点击成功但任务没完成？ | 以页面变化核对成功标准 | 完成验证、未知结果、重试 | 后续本地页面对照实验 |

## 概念之间的关系

- browser use 是能力；browser-use 是可选的具体开源项目，二者不等同。
- Harness（模型外围执行程序）组合观察、工具分发和结果回收；CDP 属于浏览器通信/控制层。
- DOM 描述网页元素结构；可访问性树强调角色与可访问语义；截图表达像素。它们可以组合，并非依次替代。
- 浏览器操作与桌面操作有交集；网页 DOM 不等于整个桌面结构。

## 主线与选学扩展

必学：输入/点击案例 → 页面观察 → 模型与工具职责 → CDP 命令/事件 → 会话与等待 → 动作后验证。

选学：复杂 iframe、Shadow DOM、下载上传、反自动化与远程浏览器；遇到具体问题再展开。
