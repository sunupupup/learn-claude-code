# 上下文压缩知识图谱

> 这是本任务的导航地图。技术判断需由官方资料、固定版本源码或可重复实验补证；当前仅建立问题链路，尚未确认各开源项目行为。

## 1. 完整技术链路

```text
应用组装活动上下文
  → 估算输入规模并调用模型
  → API 接受请求，或返回上下文超限
  → 区分普通错误与可恢复的长度错误
  → 冻结本次 Run 的消息、权限和上下文版本
  → 找到不破坏 Tool 调用/结果协议的压缩切点
  → 提取继续任务所需的目标、约束、进度、证据和副作用凭证
  → 生成摘要 / 结构化状态 / Artifact 引用
  → 重建并校验 messages
  → 在次数、时间、Token 与成本预算内重试
  → 验证结果；成功继续，失败则降级、停止或交由用户处理
```

## 2. 问题与扩展方案

| 面对的问题 | 改变环节与方案 | 关联概念 | 深入入口 |
| --- | --- | --- | --- |
| 历史持续增长，但尚未达到 API 限制 | 主动裁剪、旧 Tool Result 占位、大结果外置或阈值摘要 | proactive / auto / manual compaction | [s08](../../../s08_context_compact/README.md)；[压缩方式对比](../../../s08_context_compact/压缩方式对比.md) |
| 本地估算与供应商限制不一致，请求已被拒绝 | 从错误响应进入 Reactive Compact 恢复路径 | prompt-too-long、恢复预算、重试 | [C-2026-014](../../../specs/changes/C-2026-014-study-production-reactive-context-compaction.md) |
| 裁剪造成孤立 Tool Call 或 Tool Result | 按协议组选择安全切点，校验调用 ID 与结果 ID | Tool 配对、并行调用、部分结果 | 开源项目笔记与最小实验 |
| 摘要遗漏任务进度或执行凭证 | 分开保存自然语言摘要、结构化 Run State、业务状态和 Artifact | Checkpoint、幂等凭证、结果引用 | 后续状态契约模块 |
| 摘要器也无法处理超长输入或恢复仍失败 | 分块/分层摘要、确定性预裁剪、有限次重试与明确终止 | 恢复上限、降级、人工接管 | C-2026-014 Track A/C/D |
| 压缩和 Tool 执行、取消或权限更新并发 | 版本化快照与一致性边界；恢复时重新核对权限与副作用 | Context Version、Checkpoint、竞态 | C-2026-014 Track D |

## 3. 概念之间的关系

- **活动上下文**是当前一次模型调用可见的输入；消息历史只是其中一部分，System Prompt、工具 Schema 和其他上下文也可能占用预算。
- **Proactive/auto/manual compaction**在调用前或由模型/用户操作主动减少内容；**Reactive Compact**由真实的超限拒绝触发，是一条错误恢复路径，可以组合裁剪、摘要、状态恢复和重试。
- **Transcript**保存对话记录；它不自动等于可恢复的 **Checkpoint**，也不意味着模型能在下一次请求中检索所有原始内容。
- **摘要**提供语义压缩；**结构化 Run State**保存可验证进度；**Artifact 引用**指向外置原文；**业务状态**由权威业务系统确认。它们互补，不能互相冒充。
- **Tool Use / Tool Result 配对**属于消息协议正确性；**幂等键 / operation_id**属于副作用恢复证据；**上下文隔离**本身不提供权限或业务一致性。

## 4. 主线与选学扩展

**必学主线**：超限触发分类、协议安全切点、任务状态保留、重建后的消息校验、有界重试和停止条件。

**按需扩展**：分层摘要、事件日志投影、长任务 Durable Execution、并行 Tool 调用、权限版本变化、成本与质量 Eval、敏感 Trace 的保留治理。
