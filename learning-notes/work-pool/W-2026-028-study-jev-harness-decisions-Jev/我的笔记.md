这是一个专门做决策的模型

一开始，LLM为了支持结构化输出输出，有了两种技术
- Tool Calling
- Structured outputs  

但是这部分的决策，速度很慢、成本高
每个决策都需要再次调用相应的模型

Jev 登场了。Jev 是 TypeSafe AI 公司最新推出的模型。据该公司称，在分类任务上，Jev 的推理速度比同类大语言模型快 200 倍，成本则低 400 倍。

Jev 其实并非传统的大型语言模型，它并不负责生成文本。TypeSafe AI 团队将其称为“System One 模型”。

比如这是一个 问题的示例
```
{
  "model": "jev-latest",
  "state": "Hi, I've been trying to connect my Stripe account for 3 days and it keeps failing. I'm losing sales. Please help ASAP.",
  "questions": {
    "is_urgent": {
      "type": "noul",
      "instructions": "The message conveys urgency or time-sensitivity"
    }
  }
}
```

单纯判断问题是否紧急

```
{
  "is_urgent": {
    "type": "noul",
    "noul": 0.999
  }
}
```

支持三种问题
1. Choice：从一组中选择
2. Score：比如 关于一个问题的紧急程度，进行打分
3. Noul：返回 question 是否为真的概率


现在的一个场景：浏览器Agent

对于某些浏览器自动化的场景，现在通过 Jev 能很快指导下一步点击的内容

# 打分场景的case

输入
```
{
  "state": "The export button crashes the settings page in Safari. It works in Chrome, but a few of our customers only use Safari.",
  "questions": {
    "bug_severity": {
      "type": "score",
      "instructions": "How severe is the reported issue?",
      "criteria": [
        "Cosmetic; no impact to functionality",
        "Broken or degraded feature, but workaround exists",
        "Blocking issue; no workaround exists"
      ]
    }
  }
}
```


输出
```
{
  "model": "jev-1.13.0",
  "answers": {
    "bug_severity": {
      "type": "score",
      "score": 1.43,
      "confidence": 0.35,
      "legend": {
        "0": "Cosmetic; no impact to functionality",
        "1": "Broken or degraded feature, but workaround exists",
        "2": "Blocking issue; no workaround exists"
      },
      "probabilities": {
        "0": 0.0,
        "1": 0.57,
        "2": 0.43
      }
    }
  },
  "usage": {
    "input_tokens": 332,
    "output_tokens": 18
  }
}
```
