# 名词清单：副作用工具与业务安全

> 本表是查词入口，不表示已掌握。按本章链路分组，后续会随着提问和复述修订。

## A. 工具调用与分层

- **副作用（side effect）**：Runtime / 业务层中会改变系统外部状态的动作，例如新建工单、扣款或发送邮件；与只读查询不同，重复调用可能产生额外影响。
- **Harness（执行框架）**：Agent 应用层负责驱动模型、检查策略、调度工具、保存运行状态的代码；它不是下游业务服务。
- **Tool Adapter（工具适配器）**：Agent 与业务 API 之间的薄层，负责参数/返回结构映射及可信元数据传播；不能替代业务服务的最后授权。
- **业务服务（business service）**：订单、支付、客服等系统的领域服务；掌握业务状态并负责最终鉴权、一致性与操作记录。

## B. 身份与访问控制

- **AuthN / Authentication（认证）**：确认“调用者是谁”；与 AuthZ（是否能操作）不同。
- **AuthZ / Authorization（授权）**：判断某主体能否对某个资源执行某个动作；HTTP 已认证不等于有权看任意订单。
- **租户（tenant）**：多租户系统中的客户/组织边界；请求里的 tenant ID 若未从可信上下文绑定，不能直接信任。
- **委托身份（delegated / on-behalf-of identity）**：服务代表用户行动时携带“实际服务调用者”和“代表的用户”两种身份；不能简单把后台服务高权限借给 Agent。
- **ReBAC（Relationship-Based Access Control，关系型访问控制）**：按用户与资源之间关系授权，如客服可操作被分配客户的工单；不同于只按角色名称判断。
- **PDP / PEP（Policy Decision / Enforcement Point，策略决策/执行点）**：PDP 计算 allow/deny，PEP 把结果落实到请求上；只算出 allow 而调用方不执行，策略没有保护效果。

## C. 重复请求与未知结果

- **幂等（idempotency）**：同一业务意图重复提交，系统效果等同一次；不是“永远不能重试”，也不是请求字符串恰巧相同。
- **Idempotency Key（幂等键）**：将同一业务意图的重试关联起来的稳定标识；需定义创建者、用户/租户/动作作用域、参数冲突和保留期。
- **去重（deduplication）**：识别重复投递并抑制额外执行；通常靠持久化键和唯一约束，不可靠地依赖进程内缓存。
- **未知结果（unknown outcome）**：请求可能已被服务执行，但客户端未收到结果；超时只说明没按时收到响应，不说明业务失败。
- **Operation ID（操作编号）**：查询一次异步或可追踪业务操作状态的稳定凭证；它与 resource ID（订单/工单编号）用途不同。
- **对账（reconciliation）**：把本地记录与外部业务系统权威状态核对，修复状态不一致或未知结果；不同于无条件再次提交。

## D. 事务与恢复

- **事务（transaction）**：在一个受支持的数据资源内把多个写入作为一个原子提交/回滚单位；不能自动覆盖远程 API 或邮件发送。
- **补偿（compensation）**：流程失败后执行新的业务动作来缓解已发生步骤，如取消订单或退款；它不是把历史倒带。
- **Saga（长事务编排模式）**：多个本地事务组成的长流程，每步失败时运行对应补偿；每个补偿也可能失败，需要人工处理。
- **持久执行（durable execution）**：把运行进度/事件持久化，使进程重启或等待后可继续；持久记录不自动提供业务级 exactly-once。
- **Checkpoint（检查点）**：保存某个工作流的可恢复状态快照；重放是否会重新执行节点/步骤取决于具体框架语义。
- **Retry / Timeout（重试/超时）**：重试是再发起尝试，超时是时间上限；对写操作必须结合幂等、错误类型和状态查询设计。

## E. 审批与可观测性

- **HITL（Human-in-the-loop，人在回路）**：执行过程需要人审核或补充决定；审批应绑定待执行的对象和参数，且不替代最终授权。
- **参数快照/参数 Hash**：审批时对实际动作参数固定版本或摘要；批准后参数改变，则旧批准不应自动适用。
- **Trace（执行轨迹）**：关联一次 Agent Run 内模型、工具和工作流步骤的技术事件，主要帮助诊断。
- **Audit Log（审计日志）**：记录谁在何时基于何种决定执行了什么业务动作及结果，主要支持追责与审查；不等同于普通调试日志。
- **Tool Result Envelope（工具结果信封）**：结构化保存 status、operation/resource ID、幂等键和恢复策略，避免摘要让 Agent 忘记已发生的副作用。

## F. 开源许可证标记

- **OSI 开源许可证**：允许按许可证条件使用、研究、修改和再分发的许可证类别；有公开源码不必然代表开源。
- **Source-available（源码可见）**：可以读到源码但许可证限制某些使用方式；本章 Restate Runtime 为 BUSL-1.1，需要与 MIT SDK 分开判断。
- **商业托管功能**：由服务商运营的云功能或高级产品能力；不能仅凭开源 SDK/客户端推断该能力也开源。
