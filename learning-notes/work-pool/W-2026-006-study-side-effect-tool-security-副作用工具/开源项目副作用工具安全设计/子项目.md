# 开源项目副作用工具安全设计：候选、对照与学习路线

> 核验日期：2026-09-26。候选初筛只查官方仓库与维护者文档；没有固定 Commit、深读代码或运行项目。当前计划 10 个代表候选，其中 9 个仓库按核验到的 OSI 开源许可证发布，Restate Runtime 单独列为源码可见但受限。商业托管能力不按开源能力计。

## 为什么选这些路线

副作用安全不是单个 Agent SDK 能包办的问题，需要把“动作如何提出和审批”“运行如何跨故障恢复”“业务服务怎样授权和去重”“最终业务对象怎样被创建”分别观察。本组候选覆盖这四个层次：教学 Demo 帮初学者读场景；Agent SDK 展示工具审批入口；工作流项目展示等待和重放；策略系统展示 allow/deny 的决策结构；工单/电商产品让人看到真实业务域对象与流程。没有用同类框架堆数量，也不将其宣传语当成生产验证。

## 主项目与对照建议

- **默认主项目：OpenAI Agents SDK Python。** 初学者可从可见的审批调用路径开始，不需要先搭分布式工作流集群。首轮重点读官方 HITL 文档、`examples/agent_patterns/human_in_the_loop.py` 和 server-owned approval 示例；不要把它的 `RunState` 当作服务端认证/授权方案。
- **业务语义锚点：OpenAI 客服 Demo。** 用它理解常见支持场景里的查询、取消和补偿动作；它是 Mock Demo，不证明下游真实业务服务有幂等或交易安全。
- **窄对照：LangGraph。** 只对比“暂停之后恢复时，节点从哪里继续执行”；尤其关注 interrupt 所在节点重新运行的事实。再用 Temporal **或** DBOS 比较通用持久工作流，不同时部署全部框架。
- **场景应用：Zammad 或 Saleor 二选一。** 如果先学工单重复创建，选 Zammad；准备进入订单/结账流程时再看 Saleor。它们是领域应用，不是专门的 Agent 项目。
- **授权窄对照：OpenFGA 与 OPA 二选一。** 想从“谁和这个订单有什么关系”入手选 OpenFGA；想从结构化请求条件决定 allow/deny 入手选 OPA。策略引擎只产出判定，业务服务仍负责执行点。
- **Restate 仅作许可与执行模型比较。** 公开源代码不等于 OSI 开源；本次核验的核心 Runtime LICENSE 是 BUSL-1.1。其 Python SDK 仓库 MIT 不会改变 Runtime 许可证。

## 初学者学习路线

1. **先看场景，不看平台宣传**：读 OpenAI 客服 Demo 的 README/后端入口，圈出哪些是 Mock、哪些会改变状态。输出：查询、创建、取消、补偿四种动作表。
2. **理解审批发生在哪**：读 Agents SDK 官方 HITL guide 和最小例子，画出模型 Tool Call → `needs_approval` → interruption → reviewer decision → resume。输出：一个批准绑定 tool call 的状态图。
3. **理解恢复重放**：对照 LangGraph 官方 Interrupt 文档，标出 `interrupt()` 前面的语句会否重新运行。输出：副作用放在中断前/后的风险比较。
4. **加上持久执行**：Temporal Samples 先看 `hello_activity_retry`、`hello_cancellation`、`polling` 与 `openai_agents`；再选 DBOS 读一个 workflow/step 示例。输出：哪些代码会 retry、业务幂等必须由哪层提供。
5. **再接业务服务**：选 Zammad 或 Saleor 的一个只读和一个写操作，跟 API/领域逻辑/数据库状态；不连接真实实例，不发生产写请求。
6. **最后补策略**：选 OPA/OpenFGA 其一，设计“用户 + Agent Scope + 资源关系”的判定输入，并指出哪个服务必须做 Enforcement。
7. **本地故障实验（待用户选择后）**：只用内存或本地 DB 假服务，重复请求、制造响应丢失、恢复 Worker；断言资源只创建一次、未知结果走查询/对账、审计含 Actor 与 operation ID。

## 学习时固定的判断口径

| 证据类型 | 可以说明 | 不能说明 |
|---|---|---|
| 官方文档 | 维护者记录的预期用法与边界 | 某环境已实际满足安全/可用性目标 |
| 源码/测试（固定 Commit 后） | 该版本实现路径与测试覆盖 | 所有部署参数和下游系统行为 |
| 本地合成实验 | 这组输入、版本和环境下观察到的结果 | 生产规模、真实支付或客户数据的安全 |
| 产品案例/采用者 | 有机构公开称在使用 | 其内部安全控制、故障率或本任务具体不变量 |

许可证、维护状态和入口会变。真正开始每一个项目时重新核对当前 tag/Commit、LICENSE、最近 release/commit、维护文档和本章关心的源码路径；当前矩阵日期不是后续读源码时的版本固定依据。
