# 副作用工具安全知识图谱

> 地图入口：从一次 Agent Tool Call 到业务系统权威状态。本文说明问题如何引出机制及学习入口，不表示术语已掌握。

## 1. 完整技术链路

```text
用户意图 + 已验证身份/租户
  → 模型提出 Tool 名称与参数（不可信的动作建议）
  → Harness 校验 Tool allowlist、调用预算、风险策略
  → 高风险调用进入审批等待（审批绑定具体资源、参数摘要/版本）
  → Tool Adapter 做 Schema 校验并传播可信 Actor / on-behalf-of / trace / idempotency key
  → 业务服务重新做资源级授权与业务状态校验
  → 数据库事务/唯一约束写入操作记录与业务资源，或调用下游系统
  → 返回 operation/resource/status 凭证
  → Harness 保存可恢复状态；必要时暂停、恢复或由 durable workflow 编排
  → Tool Result 压缩只保留安全恢复所需字段，详情可通过稳定引用读取
  → Trace 关联调用过程，Audit 记录身份、决策、审批、参数摘要与结果
```

**放行不是授权执行，审批不是业务鉴权，持久化也不自动意味着 exactly-once。**

## 3. 概念之间的关系

- **模型 Tool Call → Harness 决策 → Tool Adapter → 业务服务**是职责链；不能互相代替。
- **策略引擎**（如 OPA/OpenFGA）可协助计算“允许吗”，但执行服务仍需正确接入并落实判定。
- **幂等**是业务接口/存储语义；Temporal、DBOS 等工作流可以重放步骤，但不能替外部业务系统发明幂等能力。
- **事务**适用于同一事务资源中的原子写入；跨服务流程通常用编排和补偿，不等于反向撤销已发生的一切副作用。
- **HITL 审批**是人的一次有范围决定；授权服务与业务服务仍要验证当前权限、对象状态及被批准参数。
- **Trace**偏执行过程定位；**Audit**偏事后回答谁因何批准/执行了什么。两者可以关联，不应把普通日志当作二者替代品。
- **OpenAI 客服 Demo、Zammad、Saleor**展示不同层次：教学流程、完整工单产品、真实电商业务域；产品完整度不构成安全正确性证明。

## 4. 主线与选学扩展

### 必学主线

1. 查询订单的资源授权与敏感字段最小化；
2. 创建工单的幂等、重复投递及超时未知结果；
3. 代下单的准备/确认/提交分段、审批参数绑定、并发状态变化和取消/退款补偿；
4. Agent Runtime 与持久工作流如何暂停/恢复，重放边界在哪里；
5. 用确定性状态（行数、operation 状态、审计事件、副作用次数）验收。

### 选学扩展

- 多区域数据库一致性、跨支付网关对账、复杂库存预占；
- Saga 长链、Outbox/Inbox、消息 Exactly-once 的协议细节；
- 风险评分、策略 PDP/PEP 拆分、实时撤销和审批人分离职责；
- 多租户隔离、支付合规与账务不可变流水。

遇到金融交易、跨区域或高并发订单系统时再深入，当前先掌握常见单业务服务和异步任务。
