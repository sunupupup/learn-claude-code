## 任务位置与目标

本任务位于 Agent Harness 的 Tool 调用之后，关注 Agent 与真实业务服务交界处的安全和可靠性。按“查询订单 → 创建工单 → 代用户下单”逐级增加副作用风险。核心心智模型：**模型提出动作，Harness 控制执行流程，业务服务做最终鉴权并保证业务状态安全。**

与相邻任务的分工：权限身份、委托和审批治理以前置任务 [C-2026-015](../../../specs/changes/C-2026-015-study-production-agent-permissions-and-approval.md) 为主，本章只引用必要结论；Tool Result 压缩与恢复边界见 [C-2026-012](../../../specs/changes/C-2026-012-study-tool-result-compaction-and-recovery.md)；MCP Server 的工具接口工程后续见 [C-2026-017](../../../specs/changes/C-2026-017-build-useful-mcp-server.md)。

## 初学者主线

1. 用“创建一张工单”分清模型建议、Harness 放行、业务服务写入三个事件。
2. 让用户理解为什么同一个请求重发会重复建单，以及幂等键保护的究竟是哪种“同一次业务意图”。
3. 分析“服务已建单但响应超时”：状态未知时先查权威业务状态或 operation，而不是盲目重试。
4. 将订单写入拆成准备/报价与最终提交，审批绑定展示给人的参数快照；等待审批期间再验证业务状态。
5. 通过一条 Agent Runtime 路径和一条持久工作流路径对比恢复语义，再用本地假业务服务验证副作用次数。
