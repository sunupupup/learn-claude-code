# CrewAI 与 AutoGen 多 Agent 协作名词清单

> 这是查词入口，不是要求背诵的清单。当前解释用于预习；项目中特定术语的准确行为要在对应版本官方文档和源码中核验。

## A. Agent 与编排基础

| 术语 | 初学者解释与边界 |
| --- | --- |
| Agent（智能体） | 在 LLM 应用层中，能根据目标和上下文决定下一步的执行单元。它不天然等于独立进程、独立模型或有权限隔离的服务。 |
| Multi-Agent（多智能体） | 多个 Agent 参与同一任务的应用组织方式。Agent 数量多不自动带来更高质量，必须有任务拆分和协调收益。 |
| Orchestration（编排） | 应用/Harness 层安排任务、控制步骤、传递状态并结束流程的逻辑。它与 Agent 内部的模型推理不同。 |
| Workflow（工作流） | 用显式步骤、分支或事件规定如何推进工作。可编排普通函数、单个 Agent 或多个 Agent，不等于多 Agent。 |
| Control Flow（控制流） | 决定接下来运行哪一步、交给谁、何时停止的规则。与传递了哪些数据（数据流）相邻但不同。 |
| Context（上下文） | 当前模型/Agent 可见的信息，如指令、历史和任务材料。上下文是否共享不决定文件、凭证或网络权限是否隔离。 |

## B. CrewAI 词汇

| 术语 | 初学者解释与边界 |
| --- | --- |
| CrewAI Agent | CrewAI 中配置目标、角色描述、模型和可用能力的 Agent 对象；角色说明是提示输入，不等于真实专业资质或权限策略。 |
| Task | CrewAI 中对一项工作的描述、预期输出及执行分配。它是框架任务对象，不自动等同持久任务队列或生产级事务。 |
| Crew | 由多个 Agent 与 Task 组成并按某个 Process 协调执行的团队抽象。 |
| Process | CrewAI 中 Crew 执行任务的协调方式，例如顺序或层级方式；具体选项和 API 需按学习时版本核验。 |
| Flow | CrewAI 中显式管理步骤、事件/分支和状态的流程抽象。官方概述中它可与 Crew 组合；它不是另一种 Agent。 |

## C. AutoGen 词汇

| 术语 | 初学者解释与边界 |
| --- | --- |
| AutoGen AgentChat | 面向对话式单 Agent/多 Agent 应用的较高层 API；官方将其描述为构建于 Core 之上。 |
| AutoGen Core | 更底层的 Agent 与消息/事件驱动编程基础；灵活度和需理解的运行时概念都更多。 |
| Message（消息） | Agent 或运行时之间传递的信息单元。消息交换不必然意味着共享完整会话历史或共享可变状态。 |
| Team / Group Chat | 由多个 Agent 按某种发言或选择规则一起处理对话的协作抽象；名称和具体策略以版本文档为准。 |
| Termination Condition（终止条件） | 限制对话/团队循环何时结束的规则。结束一次对话并不证明业务任务已完成。 |
| Maintenance Mode（维护模式） | 项目维护状态的一种描述，不等于代码不可用或立即停止维护；新项目选型还需查看维护者的迁移建议、发布和安全状态。 |

## D. 证据与生产边界

| 术语 | 初学者解释与边界 |
| --- | --- |
| Tool（工具） | Agent 可请求应用执行的外部操作。模型提出调用与应用实际执行成功是两个不同步骤。 |
| State（状态） | 流程/团队在执行中保留的数据。需确认状态由谁写、谁能读、失败重试后是否恢复。 |
| Handoff（交接） | 把某项工作或控制权交给另一 Agent/步骤；具体系统中可能只是任务分派，也可能是控制权变化。 |
| Trace（轨迹） | 记录一次运行中模型、Agent、步骤、工具和结果的关联事件，方便排查；记录轨迹不自动证明正确。 |
| Eval（评测） | 用任务、标准或指标比较行为质量。演示成功或单个样例不足以说明普遍效果。 |
| Idempotency（幂等性） | 同一操作重复请求时避免重复产生副作用的设计属性；在任务重试或响应丢失时尤其重要。 |
