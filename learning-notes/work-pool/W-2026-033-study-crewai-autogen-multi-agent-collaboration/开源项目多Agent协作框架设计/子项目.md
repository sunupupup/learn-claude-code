# 开源项目：多 Agent 协作框架

## 为什么学习这两个项目

本专题用两个公开框架作为观察样本，学习“多 Agent 协作”如何从概念变成任务、控制流、消息/状态传递和结果回收。项目文档和源码只能支持特定版本的事实，不直接证明生产稳定性或使用多 Agent 的收益。

## 项目分类与推荐顺序

| 顺序 | 项目 | 本专题角色 | 主要学习问题 |
| --- | --- | --- | --- |
| 1 | [CrewAI](CrewAI.md) | 先观察较直观的 Agent、Task、Crew 与 Flow 组合 | 任务如何声明和排序？Crew 与 Flow 如何分工？顺序/管理者协调中数据怎样传递？ |
| 2 | [AutoGen](AutoGen.md) | 再观察对话式团队抽象及其底层 Core 分层 | AgentChat 如何组织团队对话？Core 的消息/事件模型增加了什么控制能力？如何终止和回收结果？ |

AutoGen 只作为既有项目的学习样本。其官方材料目前标注 maintenance mode，并建议新项目关注 Microsoft Agent Framework；后者在本章只作短背景，不安排同等深度源码学习。

## 共同观察表

比较时使用同一任务，分别追踪：

1. 入口收到什么用户目标和完成标准？
2. 谁拆任务、分配 Agent 并控制下一步？
3. Agent 之间交换什么：消息、任务输出、共享状态还是会话历史？
4. Agent 能调用哪些工具，实际调用由哪一层执行？
5. 如何判断继续、交接、失败或停止？
6. 最终结果由谁合并和验证？什么运行证据可以检查？
7. 版本、API、源码与运行观察分别能支持哪些结论？

## 资料与版本策略

- 先从各项目笔记中的官方文档与仓库入口开始。
- 正式源码学习前记录读取日期、仓库、选定的 Tag/Commit、许可证及项目维护状态；本文件不预先固定版本。
- 按需在仓库外浅克隆源码；不把第三方源码、依赖或子模块放进本学习仓库。
- 每项结论标注 `documented`、`source-verified`、`observed-runtime` 或 `production-proven`，不混用证据级别。
