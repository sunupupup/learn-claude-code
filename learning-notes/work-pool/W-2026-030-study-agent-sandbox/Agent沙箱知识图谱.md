# Agent 沙箱知识图谱

## 1. 完整技术链路

用户目标 → 模型提出工具调用 → Harness 检查权限/必要审批 → 执行器选择受限环境 → 注入必要文件和能力 → 执行并约束资源 → 收集结果/产物 → 清理或受控复用 → 结果反馈模型。

**沙箱主要约束实际执行能触达什么；授权判断、隔离执行和业务服务校验要配合。** 远程 API 工具可能在沙箱外执行，必须逐个确认工具的执行位置和身份。上述是学习用通用框架，不代表所有产品使用相同部署方式。

## 2. 问题与扩展方案

| 面对的问题/场景 | 改变哪个环节、怎么改 | 概念或方案 | 深入入口 |
| --- | --- | --- | --- |
| 编码 Agent 误读或误删宿主文件 | 执行时仅暴露必要路径，区分只读输入与可写产物 | 文件系统隔离、挂载、最小权限 | s02 对照；资料 A |
| 执行生成的 Python 做数据分析 | 限制进程、内存、CPU、时间和输出量 | 资源限额、超时、进程树清理 | 资料 A；模块待学 |
| 安装依赖、运行仓库测试脚本 | 控制来源、联网范围和执行权限 | 不可信依赖、供应链、出站网络控制 | 模块待学 |
| 联网下载与调用内网服务 | 约束目标与数据出口，区分下载需求和外传风险 | 网络策略、代理、出口控制 | 模块待学 |
| 工具需要 API Key 或登录态 | 限定凭证范围、生命周期和交付位置 | 短期凭证、代理调用、日志脱敏 | W-005、W-006 |

## 3. 概念之间的关系

- **提示词与审批影响行为和授权；沙箱负责执行边界，三者互补。**
- 上下文隔离决定模型看到什么；目录组织决定文件放哪；执行隔离决定进程实际上能访问什么。Git worktree 属于版本控制工作目录组织，不自动提供安全隔离。
- 容器可组合命名空间（隔离资源视图）、控制组（资源统计与限制）及额外安全策略。权限和挂载方式会改变边界。[资料 A]
- gVisor 在用户态实现应用内核以降低应用直接接触宿主内核的范围；Firecracker 使用基于 KVM 的轻量虚拟机。它们是不同实现路线，不是依次替代的必然升级阶梯。[资料 B/C]
- 本地/远程描述部署位置；进程/容器/虚拟机描述执行机制，两组概念可以组合。远程并不自动等于安全。
- 创建、暂停、销毁属于生命周期；文件持久化和外部副作用属于状态管理。**销毁沙箱不等于回滚外部系统。**

## 4. 主线与选学扩展

必学：保护对象与信任边界 → 文件/网络/凭证/资源 → 常见机制对比 → 场景选择 → 生命周期与产物 → 失败对照。

选学：内核逃逸细节、系统调用兼容性调优、虚拟机快照底层、大规模预热池和调度。仅在遇到实际问题或用户主动选择时展开。
