# Agent 沙箱名词清单

本章按六个知识块查词：执行链路 → 文件与数据 → 网络与凭证 → 隔离机制 → 生命周期 → 失败与验证。前六块是必学主线，最后一块是按需扩展；这是查词入口，不是背诵清单，也不代表已经掌握。

[知识图谱](Agent沙箱知识图谱.md)负责流程与概念关系，[学习总览](LEARNING_NOTES.md)记录进度；详细案例和用户理解在后续模块笔记中保存。以下为通用概念，不声明当前设备或产品已配置这些能力。

## 1. 执行链路：谁提出动作，谁限制动作

| 名词 | 初学者解释与边界 |
| --- | --- |
| Tool Calling（工具调用） | 模型提出工具名称和参数，由应用中的工具处理程序真正执行；模型说“读取文件”不等于文件已被读取。 |
| Harness（Agent 工程执行框架） | 应用层组织模型循环、工具、策略和结果反馈的程序；它可以接入沙箱，但有 Harness 不代表自动具备隔离。 |
| Runtime（运行时） | 管理实际执行、资源和生命周期的部分；本章指 Agent/工具执行运行时，不指模型推理引擎。 |
| Executor（执行器） | 把工具请求变成进程、命令或远程调用的执行组件；执行器可以使用沙箱，也可能直接在宿主机运行。 |
| Sandbox（沙箱） | 执行层限制不可信代码能够访问哪些资源的环境或机制，例如让脚本只能读输入目录；限制要由执行系统落实。 |
| Isolation（隔离） | 将不同任务的资源或访问范围分开；上下文隔离管模型看见什么，执行隔离管程序能触达什么。 |
| Policy（策略） | 描述哪些主体可以对哪些资源做哪些动作的规则，例如允许读取项目、拒绝读取私人目录；写下规则还需要执行点落实。 |
| Authorization（授权）与 Approval（审批） | 授权判断主体有没有执行某动作的权限，审批记录人或审批系统对具体请求的决定；两者都不能代替执行时的资源限制。 |
| Least Privilege（最小权限） | 只给予当前任务需要的权限，例如分析文件无需获得整块磁盘的写权限；属于权限设计原则。 |
| Trust Boundary（信任边界） | 数据或请求进入另一个信任范围的位置，例如生成的脚本进入执行器；跨越边界时需要检查，不能仅凭内容自称可信。 |

## 2. 文件与数据：程序能看到什么、改动什么

| 名词 | 初学者解释与边界 |
| --- | --- |
| Host（宿主机） | 承载执行环境的机器或系统，例如运行容器的服务器；沙箱里可见的文件未必就是宿主机的全部文件。 |
| Workspace（工作区）与 CWD（Current Working Directory，当前工作目录） | 工作区是任务文件的组织范围，CWD 是进程解释相对路径的起点；仅设置 CWD 通常不会阻止进程访问其他绝对路径。 |
| Filesystem Isolation（文件系统隔离） | 在执行层控制程序能看见和访问的文件范围；不同文件夹名称本身不构成访问限制。 |
| Mount（挂载）与 Bind Mount（绑定挂载） | 挂载把文件系统资源接到某个路径，绑定挂载可把已有目录暴露给执行环境；允许写入宿主目录时，修改可能直接影响宿主文件。 |
| Read-only / Read-write（只读/可读写） | 表示资源允许的访问方式，例如输入只读、输出可写；只读能限制修改，但不能阻止读取或泄露内容。 |
| Path Traversal（路径穿越） | 利用路径跳出预期目录访问文件，例如通过父目录引用访问外部文件；属于文件访问校验要处理的问题。 |
| Symbolic Link（符号链接） | 文件系统中指向另一位置的链接；检查文件位置时要考虑它实际指向哪里，不能只看路径文字。 |
| Artifact（产物） | 任务产生并需要交付的文件，如报告、图片或代码补丁；临时文件不会自动成为已验证、已保存的产物。 |
| Persistent Volume（持久卷） | 生命周期可独立于一次执行环境的数据存储；销毁环境后数据可能仍在，清理与保留要单独定义。 |

## 3. 网络与凭证：能联系谁、以谁的身份行动

| 名词 | 初学者解释与边界 |
| --- | --- |
| Egress（出站流量） | 从执行环境发出去的网络通信，例如下载依赖或上传文件；允许联网还要考虑允许访问哪些目标。 |
| Allowlist（允许列表） | 明确列出允许访问的目标或资源，例如指定软件源；它表达策略，实际拦截需要网络或工具执行层支持。 |
| Proxy / Gateway（代理/网关） | 代执行环境转发请求的组件，可集中检查目标、身份和记录日志；只有请求确实经过它时，这些检查才覆盖该路径。 |
| Secret / Credential（秘密信息/凭证） | Secret 包含需要保护的信息，Credential 用于证明身份或取得访问权，例如 API Key；把密钥放进环境变量不等于不可信代码读不到它。 |
| Short-lived Credential（短期凭证） | 有较短有效期的访问凭据，减少泄露后的持续影响；仍需限制可访问的资源和动作。 |
| Session / Cookie（会话/Cookie） | 浏览器会话表示持续交互状态，Cookie 是浏览器保存并按规则发送的数据，可能承载登录凭证；分开下载目录不等于分开登录身份。 |
| Data Exfiltration（数据外泄） | 数据通过网络、工具输出等渠道流向未授权位置；限制文件写入并不能单独防止外泄。 |
| Remote API（远程应用程序编程接口） | 工具通过网络请求外部服务完成动作，例如创建工单；本地沙箱无法替代远端服务的授权检查。 |

## 4. 隔离机制：边界由什么技术实现

| 名词 | 初学者解释与边界 |
| --- | --- |
| Process（进程）与 Process Tree（进程树） | 进程是运行中的程序，进程树描述父进程和启动的子进程关系；单独起一个进程不代表它失去了访问宿主资源的权限。 |
| Container（容器） | 操作系统层组织隔离进程与资源的一种方式；常见 Linux 容器共享宿主内核，安全边界受权限、挂载和其他配置影响。 |
| Image（镜像） | 创建容器等环境时使用的文件与配置模板；镜像与实际运行中的容器不同，模板中也可能包含不可信程序。 |
| Namespace（命名空间） | Linux 内核机制，让进程看到各自的某类资源视图，例如进程编号或网络；它与限制内存用量不是一回事。 |
| cgroups（Control Groups，控制组） | Linux 内核用于统计、限制进程组资源的机制，例如 CPU 和内存；资源配额不等于文件访问权限。 |
| System Call（系统调用） | 程序向操作系统内核请求服务的入口，例如打开文件；它处于操作系统层，不是模型的工具调用。 |
| VM（Virtual Machine，虚拟机）与 microVM（微型虚拟机） | 虚拟机通过虚拟化运行客体系统，microVM 则精简设备与功能以减小开销；仍需管理共享目录、网络和凭证。 |
| gVisor | 通过用户态应用内核降低应用直接接触宿主内核范围的隔离实现；属于执行技术，不是完整 Agent 框架。 |
| Firecracker | 基于 KVM（Kernel-based Virtual Machine，基于内核的虚拟机）的 microVM 技术；负责虚拟化执行基础，不包办 Agent 的任务和权限管理。 |
| Local / Remote Sandbox（本地/远程沙箱） | 描述执行环境部署在哪里，例如个人电脑或远端服务器；部署位置与采用容器还是虚拟机是两个维度。 |

## 5. 生命周期：开始、持续、结束后留下什么

| 名词 | 初学者解释与边界 |
| --- | --- |
| Lifecycle（生命周期） | 执行环境从创建、运行到停止和清理的过程；任务回答完成与环境已清理是两个状态。 |
| Timeout（超时）与 Cancellation（取消） | 超时是超过时间限制，取消是请求停止；发出停止请求后仍要确认进程和子任务是否实际结束。 |
| Resource Quota（资源配额） | 限制任务可使用的内存、CPU、磁盘或其他资源；避免一个任务耗尽资源，也需要处理达到限额后的失败。 |
| Ephemeral Environment（临时环境） | 只为一次任务或短期使用而创建的环境；需要保留的产物应在清理前明确导出。 |
| Reuse（复用） | 多次任务使用已有环境以减少启动成本；要处理上次遗留的文件、进程、登录态和配置。 |
| Checkpoint（检查点） | 保存任务恢复所需的状态，例如完成步骤与产物位置；只保存对话不一定足以恢复执行。 |
| Multi-tenancy（多租户） | 一套平台服务不同用户或组织并隔离其数据、身份和资源；多个 Agent 不一定是多个租户。 |

## 6. 失败与验证：如何知道边界有效

| 名词 | 初学者解释与边界 |
| --- | --- |
| Side Effect（副作用） | 动作对外部状态产生的影响，例如修改文件、发邮件或写数据库；销毁沙箱不会自动撤销已发生的外部动作。 |
| Idempotency（幂等） | 同一操作按约定重复请求时不产生额外业务效果，例如重复提交同一订单请求不重复下单；需要业务系统支持，沙箱不自动提供。 |
| Rollback / Compensation（回滚/补偿） | 回滚撤销可回退的状态变化，补偿通过后续动作修正已发生的效果；例如邮件发出后通常无法通过删除环境收回。 |
| Race Condition（竞态条件） | 结果取决于并发操作的先后时机，例如多个任务同时改同一文件；独立模型上下文不能解决共享文件竞态。 |
| Audit Log（审计日志） | 记录谁、何时、基于什么权限做了什么及其结果；便于追查，但日志本身不能代替访问拦截。 |
| Failure Injection（故障注入） | 有意制造超时或权限拒绝等情况，观察系统如何恢复；要在受控实验范围中进行。 |
| Documented / Observed-runtime（文档证据/运行观察） | 前者说明资料记载的行为，后者说明特定环境中实际观测到的行为；二者都不能直接当作已完成生产验证。 |

## 7. 选学扩展：遇到相关问题再展开

| 名词 | 初学者解释与深入时机 |
| --- | --- |
| Sandbox Escape（沙箱逃逸） | 利用漏洞或配置问题突破隔离边界；研究高风险不可信代码执行时再深入具体攻击面。 |
| seccomp（Secure Computing，安全计算机制） | Linux 对系统调用施加限制的机制；分析容器限制或系统调用兼容性时再展开。 |
| Snapshot（快照） | 保存某一时刻的部分或完整环境状态以便恢复；研究快速启动时需明确是否包含内存、磁盘及敏感状态。 |
| Warm Pool（预热池） | 预先准备一批环境以缩短任务启动时间；任务量增大后再讨论容量、成本和复用污染。 |
