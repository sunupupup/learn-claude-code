# RAG 扩展：GraphRAG

## 面对什么问题？

> “订单服务依赖的数据库由谁负责？”答案分散在两份资料里，怎样串起来？

```text
D1：订单服务依赖订单数据库。
D2：订单数据库由李明负责。
```

**改变：除了保存片段，还保存实体与关系，检索时沿关系补齐证据。** 实体是订单服务、订单数据库、李明；关系是“依赖”和“负责人”。

## 完整技术链路

```text
原文 → 整理实体和关系，保留来源 → 建图
问题 → 找起点实体 → 沿相关关系查找 → 取回原文证据 → 交给 LLM 回答
```

**GraphRAG 泛指用图辅助检索生成；微软 GraphRAG 是一种具体实现。** 它的 Local Search 结合图与原文，Global Search 使用社区摘要回答全局问题；本 Demo 只展示最小图检索机制，没有复现微软的自动抽取、社区摘要或生成流程。[官方说明](https://microsoft.github.io/graphrag/query/overview/)

## 第一个 Demo：两跳找到负责人

代码：[graph_demo.py](experiments/graphrag-basic/graph_demo.py)。只用 Python 标准库，不安装图数据库、不调用模型。

在本笔记所在目录运行，复用已有 Python 环境：

```powershell
.\experiments\rag-basic\.venv\Scripts\python.exe -X utf8 .\experiments\graphrag-basic\graph_demo.py
```

```text
订单服务 --依赖--> 订单数据库 [D1]
订单数据库 --负责人--> 李明 [D2]
```

代码顶部只有两个观察参数：

| 参数 | 用途 |
| --- | --- |
| `start_entity = "订单服务"` | 手工指定查询起点，暂不做自动实体识别 |
| `max_hops = 2` | 最多走两条关系；改成 1 看少了什么 |

**重点：图负责串起关系，原文负责提供可引用的证据。** 程序会打印原文、规则得到的结果以及交给 LLM 的输入示意；没有伪装成真实模型生成。

## 改一个条件看区别

| 操作 | 应观察到什么 |
| --- | --- |
| 默认两跳 | 找到 D1、D2，关系链终点为李明 |
| `max_hops = 1` | 只有依赖关系，负责人证据不完整 |
| 起点改为不存在的服务 | 没有证据，不能凭空补出负责人 |

**简单文字匹配的对照只说明这个样例如何补查，不证明图检索比向量检索更好。** RAG 也可通过多次检索获得相同证据。

# 为啥会出现GraphRAG

# GraphRAG 多出来的部分

看同样两段原文：
chunk 1：订单服务依赖订单数据库。
chunk 2：订单数据库由李明负责。

向量索引保存的是：
chunk 1 → 向量 1
chunk 2 → 向量 2
向量用于计算：哪段文字和问题更相关？

图保存的是：
[订单服务] ──依赖──→ [订单数据库] ──负责人──→ [李明]

这里有：
- 3 个节点：订单服务、订单数据库、李明。
- 2 条边：“依赖”和“负责人”。

# 两个RAG的伪代码

## 普通RAG
, 负责的是：哪些 chunk 的内容与这个问题最相似？

```
问题 = "订单服务依赖的数据库由谁负责？"
取回数量 = 2

问题向量 = 转成向量(问题)

# 比较问题向量与各个 chunk 向量，取最相关的片段
候选片段 = 向量索引.搜索(问题向量, top_k=取回数量)

证据 = 读取原文(候选片段)
答案 = LLM回答(问题, 证据)
```

# 我的笔记

数据准备阶段，需要两份数据了
先切分文档
- 进入向量数据库
- 进入图存储

文档 → 切块
        │
        ├─ 生成片段向量
        │      ↓
        │  向量存储：向量 + 片段 ID + 原文或原文引用
        │
        └─ 抽取实体与关系、合并重复实体
               ↓
           图存储：实体 + 关系 + 来源片段 ID

# Graph 在检索过程中的参与

一种方案是

Query -> 向量数据库检索 -> 原文chunk内容
Query -> Graph分析实体 -> 根据实体关系 -> 原文chunk内容

然后两份实体内容一起给 LLM 再分析遍

当然也可以是

Query -> Graph分析实体 -> 重组Query语句 -> 向量数据库检索 -> 原文chunk内容
