首先知道，如果没有注意力机制会是如何？
做阅读理解，会通读整个文章，然后形成整体印象，然后去阅读问题、解答问题

有两个缺陷
1. 信息过载
2. 效率低下

如果使用注意力机制
1. 带着问题(query)去看文章
2. 如果问题是关于 “时间” 的，就会忽略文章中关于 “风景” 的内容
3. 判断哪些句子和“时间”的关联度最高，分配更高的“关注度”
4. 将被关注的内容整合，得到答案

注意力机制中关键的几个概念
1. 查询Query 模型处理的问题 “我们应该关注什么内容”
2. 键Key
3. 值Value



用问题Query，去和文章中的Key匹配，看没看哪边关联度最高
哪个Key匹配度高，就说明他的Value很重要

注意力机制的本质：
将一个查询Query 和一系列的 “键-值”对 （Key-Value）映射到一个输出的过程
输入、键值对、输出，全部都是向量（张量）

从而有了
QKV 的三个概念

Q: 生成下一个词，需要什么样的信息需求
K：输入序列中某个位置的信息
V：进行加权求和的向量

在 Self-Attention 中，Q、K、V 都来自同一个输入序列，只是分别经过不同的线性投影得到。

“Query 来自 decoder，Key 和 Value 来自 encoder”描述的是 Encoder-Decoder Cross-Attention（交叉注意力），不是这里的 Self-Attention（自注意力）。

图里 d_model = 4，所以"你"被表示成类似 [0.12, -0.87, 0.33, 0.56]

真实模型里这个值大得多：

模型	         d_model
GPT-2 Small   768
GPT-3         12,288
Llama 3 70B   8,192

d_model 越大，模型表示每个 token 的向量维度越高、表示容量通常也越大，但这不保证语义理解或模型质量一定更好；数据、架构和训练过程也会影响效果。更大的 d_model 通常还会增加参数量、计算量和显存占用。

d_model vs 量化（简要对比）：
- d_model 决定表格有多少列（每个 token 用多少个数字描述）
- 量化决定每个单元格的精度（每个数字用多少 bit 存储）
- d_model 是架构参数（设计时定死），量化是部署手段（后期可压缩）
- 权重的理论占用约等于“参数总量 × 每个参数的字节数”；总运行显存还包含 KV Cache、中间激活和推理框架开销。d_model 会影响许多权重矩阵和缓存维度，但不能单独决定总显存。
