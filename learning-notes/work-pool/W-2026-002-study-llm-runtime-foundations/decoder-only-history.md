# 为什么生成式语言模型常用 Decoder-only：简短演变史

记录日期：2026-09-14。定位：概念导读，约 5–8 分钟；不是训练实验或掌握验收。

## 从本轮问题出发

用户先问“什么是因果语言模型”，随后问“现在的模型是不是没有编码器了”，并明确：指的是语言主干采用 **Decoder-only（仅解码器）** 结构。

🟢 这个理解成立：这类主干没有独立的 Transformer 编码器，处理提示词和生成回答都使用同一套网络。

🟡 需要校准：“仅解码器”不等于只能说话、不能理解输入；也不等于所有模型都放弃了编码器。

**为什么会走向这条路线？因为“根据前文预测下一个 Token”能直接利用大量文本训练，又能把问答、翻译、代码等任务统一成文本生成；这条路线在扩大规模后取得了很好的实际效果。独立编码器因此不是完成这些任务的必需模块。** 这是对研究与工程选择的归纳，不是“这种结构在所有任务上最优”的定理。

## 1. 简短历史：先有两段式结构，后来分出不同路线

| 时间 | 代表工作 | 当时解决什么问题 | 结构上的意义 |
| --- | --- | --- | --- |
| 2014 | Seq2Seq | 把一个序列变成另一个序列，例如英文翻译成法文 | 用一套 LSTM 处理输入，另一套 LSTM 生成输出，形成编码器—解码器分工。[论文](https://arxiv.org/abs/1409.3215) |
| 2017 | 原始 Transformer | 在翻译等任务中，用注意力替代循环计算，改善训练并行性 | 仍保留编码器—解码器结构；Transformer 并不是一开始就只有解码器。[论文](https://arxiv.org/abs/1706.03762) |
| 2018 | GPT 与 BERT | 从大量无人工标注文本中预先学习，再迁移到具体任务 | GPT 采用仅解码器、预测后续文字；BERT 采用仅编码器，利用双向上下文学习表示。它们是两条分支，不是前后替代关系。[GPT 论文](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[BERT 论文](https://arxiv.org/abs/1810.04805) |
| 2019–2020 | T5 与 GPT-3 | 探索统一任务接口和更大规模的预训练 | T5 用编码器—解码器统一文本到文本任务；GPT-3 展示了大型自回归模型通过提示词和少量示例完成多任务的能力。[T5 论文](https://arxiv.org/abs/1910.10683)、[GPT-3 论文](https://arxiv.org/abs/2005.14165) |
| 2022 起的代表性进展 | InstructGPT 等指令跟随研究 | 让预训练模型更好地按照用户意图回答 | 示范数据微调与人类反馈训练改善交互行为；不是靠重新增加编码器变成助手。[论文](https://arxiv.org/abs/2203.02155) |

这里从 Seq2Seq 开始，是为了讲清编码器和解码器的分工。语言模型及“预测下一个词”的思想更早就存在，不是 GPT 首创。

## 2. 原来为什么需要编码器和解码器？

以原始 Transformer 的翻译任务为例：

```text
英文句子 → 编码器 → 每个输入位置的上下文表示
                              ↓ 交叉注意力
                      解码器 → 逐个生成法文 Token
```

**编码器（Encoder，模型结构层）**把输入转换为包含上下文信息的向量。原始 Transformer 编码器中，一个位置可以关注输入句子中前后的位置。

**解码器（Decoder，模型结构层）**根据已生成的目标文本，以及编码器输出，预测下一个目标 Token。

**交叉注意力（Cross-Attention）**是解码器读取编码器输出的连接机制。例如生成法语某个词时，关注相关英文位置。它与[自注意力](./transformer-self-attention.md)的区别是：读取的信息来自另一条序列。

这种分工很适合“给定一段输入，生成另一段输出”。但它不是理解输入的唯一方法。

## 3. 仅解码器为什么也能完成这些任务？

可以把输入和输出组织成一条连续序列：

```text
把 hello 翻译成中文。答案：你好
└──── 已知的提示词 ────┘└ 输出 ┘
```

预测答案时，模型能通过自注意力关注前面的提示词，所以不需要另一套网络先把问题“理解好”再交给它。

常见的 GPT 式 Decoder-only 块保留因果自注意力和前馈网络，不再设置原始 Transformer 中读取独立编码器输出的交叉注意力子层。它不是把编码器删掉、其余连接原封不动留下。

因果约束的意思是：一个位置不能读取后面的位置。**生成答案的位置位于整个提示词之后，所以可以利用整个提示词。** 但这不意味着提示词内部每个位置都能双向看见其他位置。

## 4. 为什么这条路线变得常见？

以下是基于上述工作的通俗归纳，需要把“有利因素”和“唯一原因”分开。

1. **训练数据容易构造。** 一段普通文本就包含训练答案：用前文预测下一个 Token，不必为每篇文章额外标注问答对。这叫自监督学习。不过 BERT、T5 也能使用无人工标注文本，这不是 Decoder-only 独有的优势。
2. **训练目标与生成用途衔接自然。** 预训练时练习接着写，使用时也逐个生成 Token；之后再通过指令数据等训练，让模型学会按要求回答。
3. **很多任务可以共用一个接口。** 翻译、摘要、问答、代码都能写成“提示词 → 后续文本”，不必为每项任务设计新的输出结构。T5 也证明这种统一接口不只属于 Decoder-only。
4. **结构统一，规模化路线取得了成功。** 一套主干处理上下文和输出，减少了独立编码器与解码器之间的组织复杂度；GPT-3 等结果又推动了后续投入。但仅凭结构名称，不能断言参数一定更少、推理一定更快或效果一定更好。

尤其不要记成“因为 Decoder-only 可以并行训练，编码器—解码器不可以”。**两者在常规 Transformer 训练中都能并行计算多个位置；自回归生成时，下一步依赖此前生成的结果，才通常需要逐步进行。**

## 5. 三条路线仍然并存

| 路线 | 常见用途或目标 | 不应产生的误解 |
| --- | --- | --- |
| Encoder-only，仅编码器 | 学习文本表示，用于分类、检索等 | 不是过时的“残缺模型” |
| Decoder-only，仅解码器 | 根据上下文持续生成文本 | 不等于没有理解输入的能力 |
| Encoder–Decoder，编码器—解码器 | 输入与输出明确分开的条件生成 | 没有被彻底淘汰，例如 2025 年的 T5Gemma 2 仍研究这条路线。[论文](https://arxiv.org/abs/2512.14856) |

这里比较的是语言主干。多模态模型有没有额外的视觉、音频编码器，是另一个问题；不据此推断未公开模型的完整结构。

## 6. 接回本 Work Pool：Prefill 和 Decode

在常见 Decoder-only 推理流程中：

```text
提示词 Token
    → Prefill：处理已知提示词，建立 KV Cache，得到下一 Token 的预测
    → 选出 Token
    → Decode：带着缓存处理新增 Token，继续预测
    → 重复直到停止
```

**Prefill（预填充）和 Decode（逐步解码）是推理执行阶段，不是编码器和解码器两套网络。** Prefill 可以并行处理已知提示词的多个位置，但仍遵守因果掩码。KV Cache 是注意力键、值向量的缓存，后续再学习它如何避免重复计算。

“解码”还可能指 Tokenizer 把 Token ID 转回文字；这是文本转换操作，也要与模型里的解码器区分。

本篇只补充概念导航，未运行模型或测量缓存。返回[学习主笔记](./LEARNING_NOTES.md)；下一步先理解 Prefill 与 Decode，不需要立刻深入训练工程。

## 术语速查

| 术语 | 中文与所在层次 | 本篇需要记住的边界 |
| --- | --- | --- |
| Token | 模型处理的离散文本单位 | 不一定对应一个完整词 |
| LSTM | 长短期记忆网络，循环神经网络的一种 | 早期 Seq2Seq 的网络部件，不是 Transformer |
| Causal LM | 因果语言模型，预测方式 | 依赖前文预测下一个 Token，不表示专门做因果推理 |
| Masked LM | 掩码语言模型，训练目标 | 利用可见上下文预测遮住的内容，BERT 是代表 |
| Decoder-only | 仅解码器，模型结构 | 与 Causal LM 不是同一分类维度，但常搭配使用 |
| Pre-training | 预训练，训练阶段 | 先从大规模数据学习通用规律 |
| Instruction tuning | 指令微调，后训练方法 | 用指令与回答等示例训练任务行为，不是切换网络结构 |

## 反思

1. **不确定性与选择依据：** 历史节点依据上文原始论文；“为何成为常见选择”是多因素归纳，不能用一项实验或结构名称证明所有模型都应如此选择。未核验的闭源结构不作判断。
2. **值得补足的知识：** 当前最关键的是分开“模型结构、训练目标、推理阶段”三个维度。后续用同一句提示词画出哪些位置可以互相看见，再进入 Prefill、Decode 与 KV Cache，会比背模型名称更有帮助。
