所以很明显，他就是 run bash 中间的一个中间件

RTK cuts up to 90% of the bash output your agent reads 
RTK 能将代理程序所读取的日志内容减少 90%。最多减少 90% 

但是实际节省token的数量其实并不好计算
因为要综合对比  原始bash输出 <-->  RTK过滤之后的输出

# RTK 原文回取能力

```
def run_bash(command):
    # 模拟执行前 Hook：只演示这一条命令的改写。
    if command == "git log":
        command = "rtk git log"

    result = subprocess.run(
        ["bash", "-c", command],
        capture_output=True,
        text=True,
    )

    # 注意：这里拿到的已经是 RTK 的输出！
    # git 原始输出留在 RTK 内部，这个函数没有拿到。
    return {
        "exit_code": result.returncode,
        "stdout": result.stdout,
        "stderr": result.stderr,
    }
```

RTK 对原有逻辑的侵入性比较大， 

Agent Loop 根本没有拿到原始 Git 输出，无法在这里对比 RTK 删了什么。 要恢复，必须另外使用 RTK 提供的原文回取能力

就是“保存输出 + 返回一个读取入口”。 我刚核对了 RTK v0.50.0 的源码。
例如某次测试失败，满足保存条件时，模型可能收到这样的结果：
Pytest: 18 passed, 2 failed
……精简后的错误信息……

[full output: rtk recall a1b2c3d4e5f6]
这里的 ID 是示意值。模型看到提示后，可以再调用 Bash：
rtk recall a1b2c3d4e5f6 --full
RTK 就从本地 SQLite 数据库读取已保存的内容并返回，不重新执行测试。还支持按行或关键词取回：
rtk recall a1b2c3d4e5f6 --lines 50
rtk recall a1b2c3d4e5f6 --grep "AssertionError"
接在 Agent Loop 里就是：
第一次工具调用 → 得到精简结果 + 回取命令
                         ↓
              模型觉得信息不够
                         ↓
第二次工具调用 → 执行 rtk recall → 得到已保存的详情

所以是 [full output: rtk recall a1b2c3d4e5f6] 这个，告诉了agent，这个结果是被我精简的，如果你想追溯，就调用 rtk recall a1b2c3d4e5f6

# RTK的使用方式：hook

通过 PerToolUse ,拦截 bash tool

模型发出工具调用：Bash("git status")
    ↓
PreToolUse Hook：在执行前拦截
    ↓
检查是不是目标工具、命令是否支持改写
    ↓
调用 rtk rewrite，得到 "rtk git status"
    ↓
把工具调用的 command 参数替换掉
    ↓
Bash 执行 RTK，由 RTK 执行实际命令并压缩输出
    ↓
模型收到压缩结果

# RTK

Prefix every shell command with `rtk`: `rtk git status`, `rtk cargo test`,
`rtk npm run build`, `rtk ls src/`. Keep the prefix inside chains:
`rtk git add . && rtk git commit -m "msg"`. Commands RTK has no filter for
run as-is, so the prefix is always safe.

# Command output

Command output here is condensed to save tokens, keeping every signal and
dropping costly noise. Treat it as the complete result: run commands
normally, and batch related commands into one call to avoid extra turns.
Truncated results state their recovery path in their own output. Re-run a
command as `rtk proxy <cmd>` only when its result is unusable: empty when
output was clearly expected, contradicting its exit code, or garbled.

## About RTK

RTK (Rust Token Killer) is a CLI proxy that filters command output to save
tokens; behavior and exit code are unchanged.

- `rtk gain` / `rtk gain --history` — token savings, overall and per command.
- `rtk proxy <cmd>` — run a command unfiltered, still tracked.
- `RTK_DISABLED=1 <cmd>` — skip RTK for one command.
- `rtk discover` — find past commands RTK could have condensed.
