## 推荐结构

实现位置：本目录下 `experiments/rag-basic/`。两个入口分别负责导入和提问；提供三份虚构制度 Markdown、配置示例、步骤式 README、必要中文注释。

推荐 Python + Qdrant 本地持久化 + 可配置的真实 Embedding/生成 API。先读取配置、准备代码和本地验证，不自动调用付费接口。Embedding 与生成服务分别配置，避免假设同一供应商一定同时支持两者。

| 选择 | 收益 | 代价/限制 |
| --- | --- | --- |
| 真实 API + Qdrant 本地（推荐） | 观察真实语义检索与生成；不用启动数据库服务器 | 需模型服务配置；运行调用可能计费 |
| 本地 Ollama + Qdrant 本地 | 推理留在本机 | 需已安装服务、合适的两个模型及硬件；下载另行明确 |
| 完全离线流程模拟 | 无凭证也能观察流程与存储 | 假向量或词频检索不能证明语义检索能力；模板输出不能冒充生成模型 |

## 两个阶段

导入：读取 Markdown → 按段落切分（过长段落再限长）→ 给片段编号并附来源 → Embedding → 保存向量、原文和来源。

提问：读取已有索引 → 校验 Embedding 配置匹配 → 将问题向量化 → 相似度检索 Top-k → 打印候选原文与分数 → 组装问题和证据 → 调用生成模型 → 打印回答与来源。

文档没有变化时提问不重复导入。首次 Demo 暂不支持自动增量更新，明确通过新快照重建处理变更；不默认覆盖现有有效数据。没有索引、空文档、配置不一致等情况应明确报错；无候选时停止生成。候选存在但无法回答时，提示模型明确说明缺乏证据，验证时检查其实际行为，不宣称提示词保证拒答。

## 必要术语与观察点

| 术语 | 中文含义与系统位置 | Demo 中看什么 |
| --- | --- | --- |
| RAG / Retrieval-Augmented Generation | 检索增强生成；应用整体流程 | 查资料再回答 |
| Ingestion | 数据摄取；离线数据准备层 | 哪些文件被读取 |
| Chunk / Chunking | 文本片段 / 切分；预处理层 | 原文被分成哪些片段 |
| Embedding | 嵌入、文本向量化；表示层 | 输入片段、向量维度与部分数值；不是训练生成模型 |
| Vector dimension | 向量维度；表示层 | 每条向量包含多少个数，不是文本 Token 数 |
| Vector store / Collection | 向量存储 / 集合；存储层 | 保存在哪个集合、包含多少条记录 |
| Payload / Metadata | 附带数据 / 元数据；存储层 | 原文、来源路径、片段编号；不只保存向量 |
| Query | 查询；请求层 | 用户输入的完整问题 |
| Retrieval | 检索/召回；搜索层 | 实际取回了哪些候选 |
| Cosine similarity | 余弦相似度；检索打分 | 分数代表向量接近程度，不是事实正确概率 |
| Top-k | 排名前 k 个候选；检索参数 | 取回多少条，不代表 k 条都能回答 |
| Context / Prompt | 上下文 / 提示；模型输入层 | 证据原文、问题、回答要求分别是什么 |
| Generation / LLM | 生成 / 大语言模型；生成层 | 模型如何基于文本证据组织回答 |
| Citation | 引用；输出与核验层 | 回答是否能指回支持它的片段 |
| Token | 模型处理文本的单位；模型接口层 | 与字符数、向量维度不同；后续观察用量 |

Embedding 模型负责文本到向量，生成模型负责上下文到回答。文档和问题必须采用匹配的检索编码空间；本 Demo 使用相同模型和一致配置。仅维度相同不代表空间相同。

## 输出与验收

1. 导入输出文件数、片段数、向量维度及来源样例；进程退出后存储仍存在。
2. 提问输出问题、候选编号/分数/原文、完整教学提示和模型答案。
3. 用相同问题改变 Top-k，比较上下文变化。
4. 用资料不包含的问题检查无答案行为；明确区分空检索和候选不足以支持答案。
5. 检查更换 Embedding 配置时拒绝混用索引。

测试替身可以验证流程，但真实语义检索、模型答案和计费情况必须通过真实调用另行记录。本地 Qdrant 使用精确检索，不借此声称演示了 HNSW 近似索引。
