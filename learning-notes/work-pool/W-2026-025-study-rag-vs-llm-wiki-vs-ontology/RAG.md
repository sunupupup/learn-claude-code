# RAG：准备数据、使用数据、维护数据

**RAG（检索增强生成）：先查资料，再把问题和相关原文交给 LLM 生成回答。**

## 完整技术链路

| 部分 | 做什么 |
| --- | --- |
| **准备数据** | 解析、清洗 → 切块 → 向量化 → 入库 |
| **使用数据** | 问题 → 检索 → 整理候选资料 → 交给 LLM 生成回答 |
| **维护数据** | 发现新增、修改、删除 → 同步片段和向量 → 清理旧数据 |

**重点：维护数据在资料变化时运行，不是每次问答结束后的最后一步。**

## 查到资料后，还会做什么？

```text
用户问题
  → 查询改写（可选，可能用 LLM）
  → 召回：向量检索、关键词检索等
  → 结果融合（多路结果合并，并整合排名）
  → 重排序（可选，更细地判断相关性）
  → 上下文组装：选择原文、保留来源、控制长度
  → LLM 生成回答
```

- **融合**：整合多路检索结果，可以使用排名算法。
- **重排序**：对“问题 + 候选片段”重新评估相关性，可以使用专门的模型。

**重点：融合和重排序不一定需要聊天 LLM，也不是每个 RAG 都必须有。**
