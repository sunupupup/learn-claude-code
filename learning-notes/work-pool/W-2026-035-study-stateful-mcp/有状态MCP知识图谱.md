# 有状态 MCP 知识图谱

## 完整技术链路

```text
用户提出编辑目标
→ 模型理解意图并选择工具
→ Harness 关联当前编辑任务、传递明确 ID
→ MCP Server 校验目标与权限、读取编辑操作记录
→ Notion 保存实际页面内容
→ Server 记录成功、失败或未知结果
→ Harness 收回结果，决定后续查询或交互
```

**协议可以无状态；跨请求的业务状态通过显式 ID 关联。模型记得操作过程，不等于外部系统保留了执行现场。**

| 多次请求需要关联 | 请求携带对象 ID，服务端查找对象 | 显式句柄 Handle | 模块笔记：技术调研 |

## 概念之间的关系

- **协议状态与应用状态是不同层次**，不是前后替代的两代技术。
- **Handle 是关联方式**，数据库或 Durable Objects 是保存和管理状态的实现选择。
- **Tasks 是任务交互契约**，MRTR 是多轮输入交互模式；两者可以组合，不自动提供完整崩溃恢复。
- **幂等记录是应用状态的一种**；不是所有幂等操作都需要额外去重记录。
- **有状态、持久化、可恢复执行是逐项检查的能力**，不能互相替代证明。

## 主线与选学扩展

必学主线：状态分层 → Harness 与 Server 分工 → 显式 ID → Notion 编辑操作单 → 超时、重试与幂等。

选学扩展：固定 SDK 源码、分布式状态存储、并发领取、崩溃恢复、任务过期与清理。遇到具体实现需要再展开。
