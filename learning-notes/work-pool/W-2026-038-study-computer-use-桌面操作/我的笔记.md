# 底层技术 (都属于Windows SDK的范畴)

| 底层技术 | 负责什么 |
|---|---|
| **Windows.Graphics.Capture** | 捕获窗口画面；插件说明支持窗口被遮挡时截图 |
| **UI Automation，UIA** | 读取系统控件的角色、文字、状态，并提供部分控件操作能力 |
| **SendInput** | 向系统注入鼠标、键盘输入 |

Windows.Graphics.Capture，就是 Windows 提供的一套“获取窗口或屏幕画面”的系统 API。 截图、录屏、窗口共享都可以用它，它属于操作系统的图形捕获层

`Windows.Graphics.Capture`：负责捕获窗口／屏幕
  → Direct3D 图形表面：承载这一帧的像素数据
  → 程序读取、转换并编码
  → PNG／JPEG 等截图

它只负责“取得像素”，不知道哪里是按钮、文字是什么意思，也不负责点击。


`UI Automation，UIA`， 提供 UIA Client API 
桌面应用也可能提供一棵“界面元素树”
通过 UIA 获取界面元素树，找到目标控件，再读取它的属性或调用它支持的操作。


`SendInput` 各种键鼠事件
就是 Windows 的原生鼠标、键盘输入模拟接口。 程序把一组输入事件交给 SendInput，Windows 再将它们加入系统输入流。
包括鼠标点击、拖拽、键盘输入等

# Codex 的 Computer Use

暴露了一个MCP，然后后提供了很多的tool

提供了下面的能力

| 类别 | 实际方法 | 作用 |
|---|---|---|
| 找应用和窗口 | `list_apps`、`list_windows`、`get_window` | 明确要控制哪个窗口 |
| 启动和激活 | `launch_app`、`activate_window` | 启动应用、切换窗口 |
| 获取状态 | `get_window_state` | 获取截图、无障碍信息 |
| 点击 | `click` | 按坐标或控件索引点击 |
| 键盘输入 | `type_text`、`press_key` | 输入文字、发送快捷键 |
| 滚动和拖拽 | `scroll`、`drag` | 操作指定窗口中的位置 |
| 控件操作 | `set_value`、`perform_secondary_action` | 设置可编辑控件的值，执行展开等辅助动作 |


大部分时候依赖于 get_window_state、click、type_text、press_key


模型
  → MCP 工具入口（js）
  → 桌面操作 API（获取状态、点击、输入等）
  → Windows 底层能力
       ├─ Graphics Capture：获取画面
       ├─ UIA：读取和操作控件
       └─ SendInput：模拟鼠标键盘
