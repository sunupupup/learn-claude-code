# 个人助手名词清单

按知识块查词。看过解释不等于已经掌握。产品是否仍提供某能力，以版图里的证据日期为准。

| 知识块 | 名词 | 初学者解释与边界 |
| --- | --- | --- |
| 类别边界 | Personal Agent（个人助手） | 主要服务一个人的日常事务，常接消息、日程、邮件或文件。它不是「任何会调用工具的程序」的统称。 |
| 类别边界 | Coding Agent（编程 Agent） | 主要改代码、跑命令、交补丁，工作对象通常是仓库。个人助手可以调用它，但二者的成功标准不同。 |
| 类别边界 | Agent Framework / SDK（框架 / 开发包） | 给开发者写 Agent 的库，例如编排循环和工具。框架本身不是用户每天对话的那个助手。 |
| 类别边界 | Chatbot（聊天机器人） | 以对话回复为主。没有工具、记忆或主动任务时，它还不是这里说的个人助手。 |
| 入口与触发 | Channel（渠道） | 用户真正发消息的地方，如终端、网页、微信、邮件。渠道负责进出消息，不负责把任务做完。 |
| 入口与触发 | Gateway（网关） | 常驻程序，把多个渠道收成统一事件再交给 Agent。没有网关时，人通常得自己打开一次会话。 |
| 入口与触发 | Session（会话） | 一次连续上下文。个人助手可以有很多会话；用户不一定希望自己管理每一个。 |
| 入口与触发 | Trigger（触发） | 不是用户当场打字、而是邮件、日程、CI 之类自己到来的事件。触发之后仍要决定要不要打扰人。 |
| 行动边界 | Proactivity（主动性） | Agent 在没有新指令时自己开始一件事。主动的前提是有边界：不该做时保持安静。 |
| 行动边界 | Permission（权限） | 允许碰哪些账号、文件和外部系统。模型觉得该做，不等于程序已经授权。 |
| 行动边界 | Handoff（移交 / 转人工） | 不确定或超出授权时停下来问人，而不是继续执行。 |
| 产品形态 | 开源可自托管 | 源码和许可证允许自己部署、阅读实现。开源不自动等于更安全或效果更好。 |
| 产品形态 | 闭源托管产品 | 主要通过厂商的网站或 App 使用，外部通常看不到完整实现。产品演示不能代替内部证据。 |
