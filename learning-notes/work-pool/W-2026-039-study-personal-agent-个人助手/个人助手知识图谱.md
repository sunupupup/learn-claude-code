# 个人助手知识图谱

**个人助手是面向一个人日常生活的 Agent 产品；开源或闭源只说明能不能读源码和自己部署，不说明它更强。**

## 完整技术链路

一个人的目标（例如「发票邮件记下来，别的别吵我」）→ 渠道或网关收到消息/邮件/日程 → 认出是哪一个人、哪一段上下文 → 取出该看的记忆和技能 → 决定回复、追问、等待或调用工具 → 有副作用时先看授权 → 核对结果 → 只在需要时通知用户 → 留下可纠正的记录。

这是学习用的主链路，不是某个产品的真实实现。

## 概念之间的关系

- 个人助手、编程 Agent、客服 Agent 可以共用模型、工具循环和记忆，但用户、成功标准和授权不同。
- 框架是零件。用框架做出来的产品，仍要单独看它是个人助手还是别的形态。
- 开源实现和闭源产品是对照来源，不是升级路线。闭源产品适合看它对外承诺什么；开源项目才追得到调用链。
- 持续在线是运行方式。一个开着的进程如果只是闲置聊天，还没有主动性和恢复。
- 已有专题的分工：Memory 笔记看记什么；Context 缓存笔记看这些内容怎样进提示词；本专栏看产品类别和「要不要行动」。

## 主线与选学扩展

必学：类别边界 → 带证据日期的版图 → 渠道/触发和单次会话的差别 → 一个开源样本的一条消息链路 → 一个不该行动的边界。

选学：所有闭源产品的功能清单、全部 IM 渠道、Super-agent 的分片和自愈、把个人助手接上编程 Agent 的完整系统。
