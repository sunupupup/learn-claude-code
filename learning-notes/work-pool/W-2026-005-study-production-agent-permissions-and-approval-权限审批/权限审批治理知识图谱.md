# Agent 权限与审批治理知识图谱

> 地图说明从 Agent 的意图到受控副作用的完整链路。具体项目只能证明各自实现；地图中的流程是通用设计框架，不等同于任何单一框架已经完整实现。

## 1. 完整技术链路

```text
用户/租户身份与认证凭证
        ↓ 绑定本次 Run、Agent 和委派范围
模型提出 Tool Call（调用名称 + 参数；只是意图）
        ↓ Runtime 验证调用结构、主体与目标资源
授权策略 PDP：allow / ask / deny
   ├─ deny → 结构化拒绝原因；不执行
   ├─ allow → 最小权限执行上下文
   └─ ask → 持久化待处理请求 → 授权审批者 → 批准/拒绝/过期/撤销
                                      ↓ 绑定 request_id、调用指纹、范围、有效期
                               恢复前再次校验授权
                                      ↓
执行器 PEP → Sandbox / 网络与文件边界 / 短期凭证 → 工具副作用
        ↓
审计事件 + Trace + 结果/未知状态 + 撤销与评测
```

多 Agent 情况下，委派要沿链路传递“谁代表谁、可做哪些动作、作用于哪些资源、到何时有效”，而不是把 Lead 的身份或凭证无条件复制给 Teammate。

## 3. 概念之间的关系

- **认证**为主体提供可验证身份；**授权**将已知主体、动作、资源、条件计算成决定。身份提供者（如 Keycloak）不自动知道 Agent 本次工具调用是否应该执行。
- **策略引擎**（OPA/Cedar）评估规则；**关系授权服务**（OpenFGA/SpiceDB）评估资源关系。都能参与 `allow/deny`，但数据模型和擅长问题不同，可组合而非线性替代。
- **审批流程**（OpenAI Agents SDK、LangGraph、PydanticAI）负责暂停与恢复工作流；它通常需要应用绑定 reviewer 身份、限制审批范围，并在工具执行时再做授权。
- **Temporal** 提供更底层的可靠长流程编排。它可以承载审批等待、计时和恢复，但本身不是 Agent 授权策略或身份提供者。
- **沙箱**约束动作执行时能触达的资源；即使授权允许，沙箱仍可进一步限制；审批允许也不能让沙箱边界失效。
- **Tool Schema** 描述模型能提出什么形状的调用，不意味着通过策略或已经执行。模型生成、审批 UI、策略 PDP 和执行器是不同信任边界。
- **最小权限委派**是从调用者身份向 Agent/Teammate 传递有限能力，不是深层嵌套 Agent 自动继承全量凭证。

## 4. 主线与选学扩展

### 必学主线

1. 身份、Tool Call、授权决定和副作用之间的边界；
2. 简单 `allow / ask / deny` 风险矩阵与策略请求元组（主体、动作、资源、条件）；
3. 审批状态机、请求绑定、持久化暂停与安全恢复；
4. 多 Agent 委派、短期凭证、撤销和最小权限；
5. 沙箱与策略互补、执行入口二次校验；
6. 审计证据和常见失败场景：重放、过期、崩溃、部分执行、Confused Deputy。

### 选学扩展

- 多区域、强一致关系授权和 Zanzibar 规模设计：在权限数据规模/传播延迟成为实际问题时深入；
- Cedar 形式化分析、OPA 部署拓扑和策略热更新：需要复杂策略验证或跨服务策略治理时深入；
- 微 VM/gVisor 内核边界、硬件 TEE：运行不可信代码或多租户隔离时与 W-030 合并深入；
- WebAuthn、人类审批的双人控制、法规留存和企业身份联邦：在真实高风险业务/合规场景明确后学习。
