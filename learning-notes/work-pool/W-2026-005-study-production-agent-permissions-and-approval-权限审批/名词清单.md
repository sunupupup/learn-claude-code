# Agent 权限与审批治理名词清单

> 这是查词入口，不是学习完成证明。每个词标注所在层次，并简单说明相邻概念的边界。

## 身份与权限基础

| 术语 | 初学者解释与相邻概念 |
| --- | --- |
| 主体（Principal） | 安全判断里的“谁”，可以是用户、服务账号、Agent 运行实例；Agent 名字只是标签，不自动等于可验证身份。 |
| 认证（Authentication, AuthN） | 验证主体是谁，例如校验登录凭证；它回答“你是谁”，不回答“你能不能删这条记录”。属于身份/应用基础设施层。 |
| 授权（Authorization, AuthZ） | 判断某主体能否对某资源执行某动作；发生在策略/应用执行边界，依赖身份但不同于登录。 |
| 租户（Tenant） | 同一应用中的客户或隔离域；授权决策需确保跨租户资源不能因 Agent 委派而串用。 |
| Run / Session | 一次 Agent 执行或一段会话的运行上下文；它不是永久身份，也不是自动权限容器。 |
| 服务账号（Service Account） | 程序使用的非人类身份。若 Agent 共享它，需把调用用户和代理主体一同记录，避免行为归属不清。 |
| 工作负载身份（Workload Identity） | 给运行中的服务/进程验证身份的机制；SPIFFE/SPIRE 属于此类，和浏览器用户登录体系不同。 |
| 短期凭证（Short-lived Credential） | 很快过期、范围受限的密钥/令牌，缩小泄露窗口；它仍需撤销、轮换和审计设计。 |

## 策略与资源模型

| 术语 | 初学者解释与相邻概念 |
| --- | --- |
| 能力 / Tool Schema | 描述 Agent 可以提出哪些调用及其参数格式；Schema 可校验形状，不能证明调用已获授权。 |
| PDP（Policy Decision Point，策略决策点） | 计算 `allow/deny` 的组件，可内嵌或独立服务；它给出决定，执行仍由别处完成。 |
| PEP（Policy Enforcement Point，策略执行点） | 在操作真正发生前拦截并落实 PDP 决定的代码点；缺少 PEP 会出现“问了策略但照样执行”。 |
| PIP（Policy Information Point，策略信息点） | 提供策略所需的身份、资源或环境属性；数据过期/伪造会污染授权决定。 |
| PAP（Policy Administration Point，策略管理点） | 管理/发布授权规则的位置；不同于运行时作单次决定的 PDP。 |
| ABAC（Attribute-Based Access Control，属性授权） | 按主体、资源、动作或环境属性作决定；例如只能读取自己部门的报告。 |
| RBAC（Role-Based Access Control，角色授权） | 通过角色授予一组权限，容易理解但角色数量会膨胀；可以和 ABAC 组合。 |
| ReBAC（Relationship-Based Access Control，关系授权） | 通过“用户属于团队、团队拥有项目”等关系判断权限，适合资源共享和层级访问。 |
| 最小权限（Least Privilege） | 只给完成当前任务必要的能力/范围/时间；不等于“什么都拒绝”，而是按需缩小授权。 |
| 能力委派（Delegation） | 一个主体有限授权另一个主体代办；区别于简单复制父 Agent 的访问令牌。 |

## 审批与运行时状态

| 术语 | 初学者解释与相邻概念 |
| --- | --- |
| HITL（Human-in-the-Loop，人类介入） | 人在工作流关键点审核或补充输入；是一种流程交互，不自动提供认证或完整授权。 |
| 审批范围（Approval Scope） | 一次批准覆盖哪次调用、参数、资源和有效期；比“以后都允许”更窄更安全。 |
| 中断 / 挂起（Interrupt / Pending） | Runtime 保存执行进度并等待外部决定；不是把线程睡眠当作可靠恢复。 |
| Checkpoint（检查点） | 可恢复的状态快照/事件记录；保存状态不等于确保有权恢复或快照可信。 |
| 幂等键（Idempotency Key） | 重试同一请求时识别它仍是同一个逻辑操作的标识；和 request ID、业务副作用去重有关。 |
| TTL（Time To Live，存活时间） | 请求/凭证/审批在多长时间后失效；过期后应拒绝执行或重新审批。 |
| 撤销（Revocation） | 让尚未执行的授权/凭证失效；对已完成外部副作用通常不能自动“撤回”。 |
| Durable Execution（持久化执行） | 进程重启后仍能从持久事件/状态继续长流程；不是数据库授权或业务事务本身。 |

## 隔离、凭证与审计

| 术语 | 初学者解释与相邻概念 |
| --- | --- |
| Sandbox（沙箱） | 限制程序能访问哪些文件、网络、进程和资源；属于执行隔离，与策略决定是否允许是两道防线。 |
| Side Effect（副作用） | 改变系统外部状态的操作，如发邮件、删数据、部署；读取参数或生成文本通常不构成同类变更。 |
| Secrets（密钥/凭证） | API Token、云密钥等敏感授权材料；不应直接作为普通 Prompt 内容或长期挂在 Agent 进程里。 |
| 审计事件（Audit Event） | 记录谁何时基于什么策略批准/执行了什么；不同于只有模型输入输出的普通 Trace。 |
| Trace（追踪） | 把一个 Run 的模型、工具和状态事件串起来排查问题；Trace 可能泄露敏感参数，且不天然等同审计证据。 |
| Confused Deputy（混淆代理人） | 代理服务拿到高权限后，被低权限调用者诱导去执行越权动作；防护需把原始主体和委派范围带到执行点。 |
| Replay Attack（重放攻击） | 重用旧批准/请求让操作再次发生；用一次性 ID、过期、参数绑定和幂等控制降低风险。 |
| TOCTOU（检查与使用之间的竞态） | 检查权限到实际执行之间，资源或授权可能变了；高风险操作可在副作用入口重新检查或使用版本条件。 |
