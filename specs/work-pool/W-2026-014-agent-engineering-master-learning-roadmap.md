## 共享补充线：LLM 基础桥接

两套计划都增加一条轻量的 LLM 基础线，用来补齐 Agent 工程所需的模型心智模型；它不替代 Agent 主线，也不把目标扩张为模型训练工程师。8 周版只要求能解释机制、做小实验并把结论用于 Agent 设计；24 周版再增加一个极小模型实验和原始论文切片。

### 必须掌握的最小范围

- **生成基础：**token、词表、logit、softmax、概率、temperature、top-p、停止条件；能解释“模型为什么是在预测下一个 token”，以及采样参数如何改变结果。
- **训练基础：**交叉熵和 perplexity 的直觉；预训练、SFT、RLHF/DPO 的目标差别；知道指令遵循、幻觉和偏好行为分别可能从哪里产生。这里只做原理导入；严格 JSON、约束解码、LoRA/SFT、Eval 和部署回滚的实操统一进入 [W-2026-003 后训练对照实验](W-2026-003-study-strict-json-output-post-training.md)，不在本路线重复设计。
- **Transformer：**Embedding、Q/K/V、Self-Attention、残差连接、归一化、FFN、位置编码/ RoPE；不要求先推完整反向传播，但要能用小数字手算一次注意力权重。
- **推理基础：**输入/输出 token、上下文窗口、KV Cache、延迟、吞吐、成本；理解 Tool Calling 和结构化输出本质上仍是模型生成加程序校验与执行。
- **知识与适配：**Embedding、余弦相似度、切分、检索、重排；能比较 Prompt、RAG、Fine-tuning 的适用边界。
- **质量与失败：**perplexity 不等于业务质量；能区分模型能力、指令、检索、上下文、工具和 Runtime 的失败，并为每类失败设计一个可验证实验。

### 十个桥接课题

每个课题安排 60–90 分钟理解、30–45 分钟小实验或复述；8 周版每周最多增加 3 小时，不挤占当天主任务。

| 顺序 | 课题 | 必交的小成果 |
| --- | --- | --- |
| 1 | Token、概率、logit 与下一个 token | 用一个短句说明 token 切分、候选概率和输出选择 |
| 2 | Softmax、temperature、top-p、交叉熵与 perplexity | 用固定 logits 做两组采样对照，并写出 perplexity 不能证明什么 |
| 3 | Embedding 与相似度 | 手算两个向量的余弦相似度，解释它为什么不是答案正确率 |
| 4 | Transformer block：Q/K/V、Attention、残差、FFN | 用 2–3 个 token 的小矩阵手算一次注意力，并画数据流 |
| 5 | 位置编码、上下文窗口和长上下文限制 | 说明顺序信息从哪里来，以及上下文变长的质量/成本代价 |
| 6 | 预训练、SFT、RLHF/DPO 与模型行为 | 用同一 Agent 问题区分“模型不会”“模型不遵循”和“应用没约束” |
| 7 | 推理、Tool Calling 与结构化输出 | 画模型输出、Schema 校验、工具执行、结果续接的边界 |
| 8 | RAG、重排、Fine-tuning 与 Prompt 的取舍 | 为研发证据助手选择一种方案并写出不选另外两种的理由 |
| 9 | KV Cache、上下文预算、延迟、吞吐与成本 | 用一次真实运行记录输入/输出量，区分模型耗时和工具耗时 |
| 10 | 评测、校准与失败诊断 | 给一个失败样本定位主要故障层，并设计确定性断言和人工评审项 |

- **Plan A：**本周 s13–s20 只做第 1 课题的 30 分钟导入，不增加课程负担；第 2–5 周完成课题 2–8；第 6–7 周结合 Codex 完成课题 9；第 8 周完成课题 10 和一次口头总复述。

- **共同停止线：**暂不把完整反向传播推导、分布式预训练、CUDA 优化、量化内核和大规模后训练列入必修；只有在模型适配或推理平台成为明确目标时才进入 24 周选修项。

### 通过标准

完成桥接线后，应能独立回答：一次模型调用实际看到了什么；temperature 改变了哪一层；为什么合法 JSON 不代表语义正确；RAG 为什么可能比 Fine-tuning 更合适；输入 token、输出 token、KV Cache 和工具等待如何影响成本/延迟；一次 Agent 失败应先查模型、指令、检索、上下文、工具还是 Runtime。只会背术语、没有小实验或失败定位，不算完成。

## 教练如何带学：明确任务，同时保留你的独立判断

1. 每次给一个主任务：读哪些文件、观察什么、改什么、提交什么、什么算通过。
2. 每次先让用户解释现有链路或提出伪代码，再进入实现；不默认把完整参考答案和全部代码提前交付。
3. 用户可直接要求讲解、提示、结对编码或完整实现，届时按明确要求调整，不以教学形式阻碍授权工作。
4. 验收时要求一次独立解释、一项行为证据；项目周再要求一次独立修改或失败诊断。
5. 看懂资料但没有实验时，只记录“理解/静态阅读”；运行过模拟测试时不记录为真实模型、数据库或用户使用通过。
6. 我会主动指出范围膨胀和知识缺口；建议调整速度时说明具体证据，由用户决定是否切轨。
7. 长期推动发生在用户继续对话的学习回合中；本计划不自动创建提醒、后台任务或定时消息。

每日汇报只需四项：今天完成了什么、运行/代码证据在哪里、哪里卡住、自己怎样理解。没有按天数完成不补造结果，下一回合直接针对缺口调整。

## 任务卡 3：第 3 周，做“证据不足时会补查”的研发助手

### 具体用户需求

“结合我选定的 Agent 学习资料，说明任务为什么不能仅由模型声明 completed，并列出依据和目前资料无法确认的部分。”

把这个场景泛化为：用户问一个研发问题，Agent 先检索；摘要不够时按需读取来源的完整相关段落，必要时改写查询再检索，最终给出有依据的回答或明确证据不足。

资料先选择 8–12 篇：已有文档加用户选定的章节说明/学习笔记快照。保留来源、版本和访问属性；不盲目摄取整个工作目录、密钥、日志或所有聊天记录。首先使用资料已明确支持的问题，不让答案依赖未摄取知识。

### 本周只增加两个相关机制

1. **read_source 工具：**输入已有 chunk_id，程序定位其原始文档和相关段落并再次检查权限；模型不传任意文件系统路径。返回来源 ID、版本/内容摘要标识、段落位置、正文和是否被截断。
2. **有限补查循环：**保留 search_knowledge，加 read_source；初始建议每次请求最多四次模型调用、三次工具执行，只允许串行工具调用。参数是学习预算，可由实验调整，不是行业标准。

一次检索为空后允许最多一次改写查询补查；仍无证据则明确结束。不得删除预算、授权或来源检查来“让循环跑起来”。多轮新行为只在新项目开启，原 D1 仍是一次检索的对照基线。

最终回答引用必须来自本轮工具真正返回、且模型可见的证据。引用 ID 合法只能证明来源存在，不能证明结论被来源支持；语义支撑另外人工抽查。证据不足时可以输出可支持的部分，并明确尚缺资料。

### 需要改动的职责

以原 agent.py、contracts.py、tools.py、model.py 和 output_validation.py 为阅读参照，在新项目中分别落到循环、状态、工具契约、协议续接和证据校验。当前“第二次工具调用必须拒绝”的测试不能原样代表新行为；新增项目要验证“合法补查允许，超过预算拒绝”，原基线测试继续保留。

### 六天任务单

| 天 | 指挥任务 | 验收 |
| --- | --- | --- |
| 1 | 写成功、补查、仍无依据三条消息/状态链；明确 read_source 契约 | 先交伪代码与三条预期轨迹，再编码 |
| 2 | 实现 read_source 的程序部分与来源映射 | 有效 ID 成功；未知 ID、不可访问来源被拒绝；模型不能指定任意路径 |
| 3 | 接入有限循环和真实工具结果续接 | 至少一条真实 search → read_source → answer 轨迹；重复或越预算请求能终止 |
| 4 | 更新输出与证据校验，定义部分有依据/无依据的表现 | 伪造 ID 拒绝；原文不支持的主张能在人工检查中被识别 |

**24 周深入项：**研究多来源冲突、数据更新、索引版本、混合检索或重排，先选其中一个；对比检索召回、答案质量与调用成本。增加跨轮权限变化或引用失效实验，并说明适用规模。不得把所有检索技术一次性装入项目。

## 任务卡 4：第 4 周，做“经过确认才保存、保存后能核对”的报告

### 具体用户需求

“把刚才的回答整理成研发分析报告，包含问题、结论、来源、未知项和建议验证步骤。我看完预览后再保存，并能确认保存的是我认可的那一版。”

报告保存由确定性程序在用户确认后执行；本轮不需要让模型任意调用通用写文件工具。模型生成内容、用户批准、程序写入、文件验证是不同阶段。

### 必做行为

- 先显示报告预览；确认绑定该份内容的 hash/版本。确认后内容发生变化需要重新确认。
- 导出目录由程序配置，文件名由程序生成，模型不能控制任意路径；规范化后仍要检查实际路径边界。
- 重复导出同一份已批准内容返回同一产物，不追加重复正文；复用被冻结内容，不重新调用模型生成“差不多”的报告。
- 写入后重新读取，核对内容 hash、必要章节与引用列表，再标记导出 verified。
- 区分内容准备完成和报告导出状态。原问答 completed 不证明报告已保存；verified 证明产物一致性，不证明所有语义绝对正确。
- 写入失败或响应丢失时先检查已知目标产物，不能无条件重做有副作用动作；存在但内容不符时明确报冲突，不覆盖用户数据。
- 检索暂时不可用、参数非法、权限拒绝、预算耗尽、保存失败分别可观察。错误展示后由用户主动 Retry/Fix 或继续；不加入隐藏的自动修复循环。

### 六天任务单

| 天 | 指挥任务 | 验收 |
| --- | --- | --- |
| 1 | 设计预览、批准、写入、验证四段流程，列出失败出口 | 状态图能区分回答完成、保存失败、产物已验证 |
| 2 | 实现预览和确定性报告格式，再接入受限目录导出 | 未批准不写；报告内容和路径可检查 |
| 3 | 增加内容绑定、重复请求复用和文件重读验证 | 连续提交两次得到同一产物；内容变更不能复用旧批准 |
| 4 | 注入“写入成功但返回前失败”，再执行恢复检查 | 通过文件与 hash 找回结果；无重复副作用，未知不伪装成功 |
| 5 | 覆盖伪造来源、越界路径、提示注入和不可用工具 | 危险动作被程序拒绝，关键日志能解释原因 |
| 6 | 用助手处理至少三个自己的实际学习问题 | 保存输入、人工评价、一个失败或不足，开始第一轮反馈记录 |

故障注入是受控实验，不能当作原项目真实事故。8 周只保证单用户、串行导出的范围，不宣称解决分布式 exactly-once；多进程并发和崩溃一致性作为深入项。

关联专题：[工具副作用安全](W-2026-007-study-side-effect-tool-security.md)、[任务完成验证](W-2026-013-study-task-completion-verification.md)。只实施本任务需要的规则，不搭通用审批或验证平台。

**24 周深入项：**增加暂停/恢复、持久操作记录、并发重复导出、进程崩溃、撤销或版本回滚中的两项；为每项写不变量与故障实验。用户体验可加最小页面，但必须解释实际状态而非只显示模型文字。

## 任务卡 5：第 5 周，做“资料变长也能保留关键证据”的助手

### 具体用户需求

“资料越来越多、来源原文很长时，回答仍能抓到关键依据，说明缺什么；不能把权限约束、来源或未完成目标挤掉，也不能无限增加调用。”

先做确定性上下文预算与证据保留，不立即做模型摘要、长期记忆和复杂多 Agent。

### 对照实验

准备十个冻结问题：三个短资料问题、三个关键证据靠后或跨段的问题、两个存在噪声/重复来源的问题、两个资料不足的问题。保留两个额外问题用于最终验收，不参与调参。

- **基线：**沿用第 4 周的证据装配策略，固定相同模型、索引快照、问题与预算。
- **候选策略：**去重、按相关性与当前问题选择证据段落、对单来源与总量设置上限，保留来源 ID、查询目标、未解决问题和工具状态；原文可通过受限 read_source 再取。
- 无法全部容纳时明确标注截断和证据不足，不悄悄丢掉授权约束或把不完整材料写成确定结论。
- 当前模型适配器用 previous_response_id 续接。仅缩短本次输入不能证明历史已缩短；先查清服务端上下文如何续接，再选择显式重建完整输入或经过官方文档支持的压缩方式，并验证模型实际收到的内容。
- 若只能测字符/字节数，标为估算，不写成精确 Token。实际 usage 可获得时记录；不可获得则说明测量限制。

### 六天任务单

| 天 | 指挥任务 | 验收 |
| --- | --- | --- |
| 1 | 从实际使用中选长文本与失败问题，固定数据/问题/版本 | 十个对照问题、两条保留问题；调参前先写好预期证据 |
| 2 | 记录基线质量、可见证据量、模型/工具调用数、耗时 | 分开计索引准备与查询耗时；定位主要问题层 |
| 3 | 实现去重、段落选择、上限和来源保留 | 用组装输入的可观察结果证明约束仍在，工具协议关系有效 |
| 4 | 同一组问题运行基线与候选 | 检查回答质量与来源支撑，不能只拿 Token 下降当成功 |
| 5 | 处理第 4 周实际反馈，跑回归和保留问题 | 接受/放弃该策略的理由、第一轮改进证据 |
| 6 | 整理个人使用方式并演示 | 能从干净启动到一次有依据回答、一次导出、一次失败定位 |

8 周目标是做出一次有证据的上下文取舍；若基线已经够用、候选没有收益，记录“不采用”也算有效实验。语义质量人工评审，确定性条件用程序检查，真实模型的随机结果记录运行次数与波动。

关联专题：[System Prompt 与上下文](W-2026-011-study-system-prompt-production-context-governance.md)、[工具结果压缩与恢复](W-2026-006-study-tool-result-compaction-and-recovery.md)。[Reactive Compaction](W-2026-012-study-production-reactive-context-compaction.md) 只在有超限证据时深入。

**24 周深入项：**加入模型摘要与确定性选择对照、摘要失真与重取原文、跨会话记忆写入/删除中的一个；至少两轮对照，不把摘要压缩、服务端历史和本地裁剪混为一谈。

## Plan A 后三周：Codex 与项目收口

## 反思

1. **此前决策的修正：**用户要的是可以随时调整的双轨方案，我此前把 8 周视为替换 24 周，误删了有效备选。本版恢复两套完整排期与深入细节；以后切轨只更新当前模式、剩余范围和日期，不删除另一套。
