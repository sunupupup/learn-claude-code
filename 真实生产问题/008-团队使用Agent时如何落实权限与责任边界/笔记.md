# 团队使用 Agent 时，如何落实权限与责任边界

## 真实问题描述

- **状态**：已登记，待后续专门学习；本次保存新的理解及问题入口，不开始工程实现。
- **最重要的新理解**：Harness（模型外围执行程序）的配置不仅提升和扩展 Agent 能力，也是组织规则的执行入口：把团队的权限、流程、风险边界和责任追踪要求，落实到 Agent 的实际运行中。
- **知识归属**：Agent Governance（智能体治理与控制），关联身份与访问管理（IAM）、策略执行、审批审计和平台工程；关注团队如何受控地使用能力。
- **假设场景一：权限不同，却共享同一套能力**。团队的开发、测试和运维都使用 coding agent，接入仓库、数据库和部署 MCP；若仅靠个人配置或提示词约定，查询人员也可能获得修改或部署能力，误操作可能影响共享资源。
- **假设场景二：团队规则无法统一生效**。管理员要求只接入批准的服务、限制数据外发，并在人员调岗后撤销权限；若个人设置可覆盖团队要求，或已运行的会话仍保留旧授权，规则可能形同虚设。
- **假设场景三：出了问题无法还原责任**。Agent 执行了一次部署或删除，日志只有工具名和输出，没有关联请求人、身份、审批人、审批参数及执行结果，难以确认谁授权、谁执行、操作是否成功，也难以决定恢复方式。
- **正常预期**：不同身份和项目获得适当能力，组织策略有明确优先级并在执行时生效，敏感操作经过必要授权，事后能查明操作与结果；以上是学习用问题推演，尚未复现事故。
- **与现有主题的关系**：[007](../007-MCP工具过多时除了动态加载还能怎么办/笔记.md) 关注工具规模与使用效率，本题关注权限和责任边界；工具黑白名单是两者的交汇点。

## 解决办法

以下只登记研究关键词，具体产品实现、约束力度与验证方法待后续核验。

- **身份与访问管理（IAM）**：将用户、角色、项目和资源范围关联，分别限制工具可见范围与实际执行权限。
- **集中策略与配置优先级**：统一下发团队配置，明确组织、项目和个人配置的覆盖规则，以及策略更新和撤销的生效时机。
- **执行层权限检查**：在 Harness 执行入口与下游服务的相应边界校验权限；提示词中的行为建议不能替代程序约束。
- **操作审批**：让敏感操作在执行前获得相应授权，审批绑定实际动作及完整参数，研究参数变化或授权过期时如何处理。
- **审计与结果追踪**：关联请求人、执行身份、审批记录、工具参数和执行结果，区分尝试、成功、失败与结果未知。
- **后续学习主线**：组织要求 → Harness 配置 → 实际执行检查 → 审批与审计证据；模型、预算和数据流向也可成为组织治理的配置对象。

产品实际采用的主要是下面几种机制，通常会组合使用。
1. 通过团队身份获取组织配置
真实例子：Claude Code。
管理员在组织后台设置策略；成员使用符合条件的组织凭证登录后，客户端自动获取配置。当前文档说明：启动时获取，会话中每小时刷新。服务端托管配置适用于 Claude Teams／Enterprise 的受支持场景。官方文档
这回答的是：
客户端凭成员的组织身份，知道应该获取哪一套规则。

但“每小时刷新”也意味着不能直接认为管理员改完，所有运行中的会话立即更新。
2. 通过公司设备管理直接下发
**MDM（设备管理）**是公司 IT 管理电脑配置的机制，例如 Windows 的 Intune／组策略。
它可以把策略写入系统级位置，而不是让每个成员自己复制一份配置。Claude Code 支持系统配置文件、Windows 注册表和 macOS 管理策略；Cursor 也支持下发团队账号限制及 Hooks。Claude Code、Cursor
这回答的是：
即使个人不主动配置，公司也能把设置部署到受管理设备。

系统权限还可以保护配置，防止普通用户直接修改。
3. 产品明确区分“管理员限制”和“个人设置”
这里才涉及你一开始说的优先级和覆盖。
- Cursor：团队运行设置优先于个人和项目配置。官方文档
- Claude Code：托管配置处于高优先级，个人配置和启动参数不能覆盖受管理的值；不同类型字段还有各自的合并规则。官方文档
- Codex：明确分成可被用户覆盖的“默认配置”，以及用户不能覆盖的“强制要求”。所以管理员需要选择正确的配置渠道和字段。官方文档
这回答的是：
规则到达个人之后，个人能否用自己的设置把它改掉。

4. 对配置更新失败、离线和旧缓存进行处理
这也是产品必须专门实现的机制。
例如 Copilot 的 forceRemoteSettingsRefresh 可以要求启动时重新下载策略；下载失败时，限制有关操作或阻止功能使用，避免继续依赖旧配置。要从设备第一次启动就生效，需要通过设备管理或本地托管文件提前部署。官方文档
所以，“保障应用到个人”包括身份识别、配置下发、优先级保护、刷新和失败处理，不能只靠一份共享文件。
