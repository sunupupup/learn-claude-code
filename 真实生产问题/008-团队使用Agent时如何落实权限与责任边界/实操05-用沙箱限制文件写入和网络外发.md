# 实操 05：用沙箱限制文件写入和网络外发

> **具体防护场景：** 防止 Agent 运行生成脚本时任意访问宿主文件，或向未批准的网站外发数据。通过沙箱限定可读写路径，并让外部网络代理只允许指定程序读取 GitHub API，拒绝该通道的写请求和未授权外连。

## 场景

Agent 可以在自己的工作目录生成代码，但网络只允许 `/usr/bin/curl` 读取 GitHub API，不允许它通过该 API 发出写请求或连接任意网站。

## 配置代码

使用 **NVIDIA OpenShell**。需要已经安装 OpenShell 并启动 Docker；以下使用官方默认沙箱的目录与用户，不是原生 Windows 的 Hook。

**文件：`github-readonly.yaml`**。

```yaml
version: 1

# 保留默认沙箱必需的文件访问路径；不把宿主整个用户目录挂进来。
filesystem_policy:
  include_workdir: true
  read_only: [/usr, /lib, /proc, /dev/urandom, /app, /etc, /var/log]
  read_write: [/sandbox, /tmp, /dev/null]
landlock:
  compatibility: best_effort
process:
  run_as_user: sandbox
  run_as_group: sandbox

network_policies:
  github_api:
    name: github-api-readonly
    endpoints:
      - host: api.github.com
        port: 443
        protocol: rest
        enforcement: enforce
        # HTTP 请求级检查：GET / HEAD / OPTIONS，不授予写入方法。
        access: read-only
    binaries:
      - path: /usr/bin/curl
```

**管理员在宿主机创建沙箱**：

```bash
openshell sandbox create \
  --name governed-agent \
  --keep \
  --no-auto-providers \
  --policy github-readonly.yaml
```

命令打开沙箱内的终端。Agent 的工具进程应在这个沙箱里运行，不能一边受限、一边还给它宿主的无限制终端。

**管理员更新网络策略时，在宿主另一个终端执行**：

```bash
# policy set 替换整个策略，所以 YAML 保留完整的文件与进程段。
openshell policy set governed-agent --policy github-readonly.yaml --wait

# 查看运行记录和拒绝原因，不把日志回忆交给模型。
openshell logs governed-agent --since 5m
```

已有沙箱断开后，可重新连接：

```bash
openshell sandbox connect governed-agent
```

`best_effort` 是官方示例的兼容设置。需要文件隔离不可降级时，应使用 `hard_requirement` 并确保列出的目录存在、内核支持；文件和进程设置变化需要新沙箱，不能当作网络配置热更新。

## 能起到的作用

- 网络策略由外部代理执行；本配置只给指定 curl 程序到 GitHub API 的只读访问。
- 文件访问受沙箱策略约束；默认工作目录可写，不代表已经按 UI/UX 语义区分代码。
- 这里没有放开模型服务域名。要让真实 Agent 在里面运行，需另配模型 Provider；不能把这份 curl 例子说成完整 Agent 部署。
