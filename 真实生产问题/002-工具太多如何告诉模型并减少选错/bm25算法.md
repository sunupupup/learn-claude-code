# 我的笔记

## Codex中的bm25

1. 将所有工具的名称、介绍等文本分词，建立“词 → 工具 ID”的倒排索引。分词器负责切词，BM25 负责后续评分。
2. **一个词出现在越少的工具介绍中，区分能力通常越强，匹配时贡献越大**。同时还考虑它在当前介绍里的出现次数，以及介绍的长度。
3. search_tool 的 query 也经过相同的分词处理，通过倒排索引找到候选工具 ID。
4. 用 BM25 给候选工具算分、排序，取前几个，再按 ID 找回完整工具定义。

## 

bm25中有些这影响到搜索结果

| 配置／设定 | Codex 实际值 | 作用 |
|---|---|---|
| **检索文本** | 名称、描述、服务信息、参数名等，按来源拼接 | 决定哪些信息能被搜到 |
| **分词语言** | `English` | 使用英文分词、停用词和词干规则 |
| **文本处理** | 默认开启规范化、转小写、去停用词、词干提取 | 让不同写法更容易匹配 |
| **`k1`** | 库默认 **1.2**，Codex 未覆盖 | 控制词频加分的饱和速度；越大，重复出现的词越能继续贡献分数 |
| **`b`** | 库默认 **0.75**，Codex 未覆盖 | 控制文本长度校正；越大，越重视长短差异 |
| **`avgdl`** | 根据目录自动计算 | 全部工具检索文本的平均分词数量 |
| **`limit`** | 默认 **8**，搜索调用可以传入 | 最多返回多少个检索条目 |
| **最低分数阈值** | 这条路径没有额外配置 | 根据共享词找到候选，再按分数排序截取 |

## k1 和 b 参数介绍

k1 和 b 都是 BM25 算法的参数，不是 Codex 独有的。 它们通常作用于整个索引，不是每个工具单独设置。
k1：一个词重复出现，值得继续加多少分？
假设两个工具介绍都包含 invoice：
- A 出现 1 次。
- B 出现 10 次。
BM25 不会让 B 仅凭重复，就获得 A 的 10 倍贡献，而是让加分逐渐饱和。
- k1 小：更快饱和，“出现过”就已经贡献了大部分分数。
- k1 大：饱和更慢，出现多次的工具更容易获得额外分数。
Codex 所用库默认 k1=1.2。
b：工具介绍长短不同，要校正多少？
假设其他条件相近，两个介绍里的 invoice 都出现 1 次：
- A 总共 20 个词。
- B 总共 200 个词。
这个词在 A 中更集中。BM25 可以通过长度校正，让 A 中的这次命中贡献更大。
- b=0：不考虑文本长度。
- b 越大：长度校正越强；相同词频下，长文本受到的折减更明显。
- b=1：在这套公式中，完整采用相对平均长度进行校正。
Codex 所用库默认 b=0.75。参数与公式源码

| 参数 | 主要解决的问题 |
|---|---|
| `k1` | 别因为一个词反复出现，就无限加分 |
| `b` | 别因为介绍写得长、容纳了更多词，就天然占便宜 |
