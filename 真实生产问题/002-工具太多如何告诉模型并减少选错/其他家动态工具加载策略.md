# 方法1：query时就加载合适的tool

代表：LangChain 的 LLMToolSelectorMiddleware。

用户 query + 当前上下文
  ↓
工具选择模型查看工具名称、描述
  ↓
选出相关工具
  ↓
主模型只收到选中的完整工具定义


它支持：
- max_tools：限制选择数量。
- always_include：始终保留某些工具。
- 使用单独的模型负责选择。

## 方法3：工具变成代码接口，模型按需阅读和调用

代表：Anthropic 官方介绍的 **Code Execution with MCP 架构**

这边就是 think in code的思想，用脚本代替工具

初始：目录探索／代码执行能力
  ↓
模型查看有哪些服务
  ↓
只读取需要的工具接口文件
  ↓
写代码调用工具、循环处理结果
  ↓
把必要结果返回模型

其实说实话，很简单的思想
```js
export async function getDocument(input) {
  return callMCPTool('google_drive__get_document', input);
}
```
把别人的mcp，当成是函数直接调用

但是这种就是死代码了，mcp变了，得手动改代码

！！但是，RSI说不定能解决！！

MCP 提供能力 → 代码接口方便组合 → Agent 自动维护这些接口和脚本。


## 方法4：工具集变成CLI

用 --help 按需发现能力，

例如，把 GitHub 的工具集合封成一个 CLI：

```bash
# 第一层：发现有哪些能力
github-cli --help
# 输出：issues、pulls、repos……

# 第二层：只了解当前需要的能力
github-cli issues --help
# 输出：list、get、create……

# 第三层：了解具体参数
github-cli issues list --help

# 执行，返回方便程序处理的结构化结果
github-cli issues list --label bug --json
```
