# MCP 工具的发现方式

## 问题要点

- **三件事**：程序知道服务入口、客户端取得工具列表、模型看见工具定义；三者不必同时发生。
- **职责分工**：宿主程序（Host）管理连接与加载策略，MCP 客户端连接服务、获取工具；模型可提出需求，由程序执行。

## 解决办法

- **服务入口目录**：宿主从配置、内置集成或服务注册目录取得连接线索；有目录不等于已连接，模型也不会自动知道目录。
- **启动预加载**：宿主启动时连接已配置服务、获取工具定义，再筛选并提供给模型。
- **按需连接**：先提供服务简介或搜索入口，由模型需求或程序规则触发，再连接目标服务、获取工具定义。
- **延迟提供定义**：可先连接并取得工具列表，模型需要时再提供完整定义；延迟加载不等于延迟连接。
- **必要边界**：连接与加载时机属于宿主策略，不能当作 MCP 统一默认行为；具体 Pi 桥接与其他产品实现待验证。
- **关联问题**：工具如何裁剪、搜索并减少选错，见 [002](../002-工具太多如何告诉模型并减少选错/笔记.md)。
