# s02 问答验收记录设计

## 目标

在 `s02_tool_use/LEARNING_NOTES.md` 文末新增一次带日期的问答验收记录，保存学习者的原始理解、正确部分、认知偏差和最终记忆结论，而不是复制完整聊天。

## 结构

新增 `## 十三、问答验收记录（2026-08-25）`，包含：

1. 本轮结论与学习状态；
2. `TOOLS` 与 `TOOL_HANDLERS`；
3. 非法 `glob` 参数的完整调用链；
4. `tool_use_id` 配对、消息顺序与 session 隔离；
5. 多工具调用和“未执行也必须返回结果块”；
6. Tool 参数定义、JSON Schema 与 Pydantic 的关系；
7. 结构校验、业务校验、权限策略和工具内部防护的分层；
8. 仍需巩固的三个记忆点。

每题采用“我的回答摘要 / 正确部分 / 需要校准 / 最终结论”的紧凑结构。

## 关键校准

- `tool_use_id` 是消息协议的关联字段，不是 session 或租户安全边界；跨 session 混入消息还需要独立的会话、身份和权限隔离。
- 学习者关于未执行的 B 工具意图正确：不能伪造成功结果，但仍必须返回一个表示未执行原因的 `tool_result` 错误块。上轮评审只应纠正“结果块”和“真实执行结果”的措辞差异。
- Tool 参数定义是概念，JSON Schema 是当前 API 中表达参数定义的形式；Pydantic 是 Python 运行时模型和校验工具，可以生成 JSON Schema。
- 业务规则和安全权限不应全部称为“额外参数校验”。权限回答“谁是否获准执行”，工具内部防护负责限制实际副作用。
