## 使用方式

1. 按顺序打开一个阶段文件，确认目标、范围与前置条件；只实现当前阶段。
2. 在同一套代码上增加能力，允许必要重构，不另起一套工程。
3. 先跑通当前阶段，再验证既有主流程；每个功能阶段结束都应可运行、可演示。
4. 实际验证后再勾选验收项，填写命令、结果、证据和未支持能力。状态依次为未开始、进行中、待验收、已完成。
5. 讲解关键函数和数据流，用户理解并确认后再继续。关键代码配简洁中文注释。
6. 启动重要实现前遵循[仓库 Spec 规则](../../../specs/README.md)。Spec 跟踪变更，引用本目录的阶段要求，不重复复制整份计划。

## 共同边界

- 从模拟业务接口开始；模拟成功不等于真实退款或真实生产接入通过。
- 模型提出操作，程序落实身份、权限、参数和确认边界。基本身份与归属校验从阶段 1 开始，阶段 5 系统补齐。
- 测试、基础日志和循环保护从早期阶段开始，后面再统一组织与完善。
- 后续阶段的数据库、框架、部署方式尚未选定，到需要时再决策。
- 本目录只是细化既定项目的路线，不自动启动其他 Work Pool 任务。
