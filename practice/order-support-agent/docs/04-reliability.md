## 学习目标

理解超时不等于失败，并保证重试围绕同一次业务操作展开。

## 需要实现的功能

- [ ] 首次提交前生成并持久化 operation_id/幂等键，恢复和重复点击复用它。
- [ ] 模拟退款服务实现原子去重：同键同参数复用结果，同键不同参数拒绝。
- [ ] 为确认与提交增加并发控制；不依赖先查询再插入这种非原子去重。
- [ ] 明确成功、失败、处理中和结果未知，增加按业务操作查询结果的能力。
- [ ] 区分查询重试与写操作重试，限制超时和次数；结果未知时查询或用原键重试。
- [ ] 覆盖创建成功但响应丢失、服务崩溃后核查及订单状态变化。

## 验收标准

- [ ] 4.1：并发两次确认，持久化退款申请数量严格等于 1。
- [ ] 4.2：故意在创建申请后丢失响应：页面显示结果未知，最终通过原操作核查到同一申请。
- [ ] 4.3：未知结果期间重启并重试，仍只有原申请；不新建幂等键。
- [ ] 4.4：同键不同订单或金额被拒绝，不修改已有申请。
- [ ] 4.5：订单页面暂未更新时，不据此断言退款申请失败。
- [ ] 4.6：阶段 3 的等待恢复流程仍通过。

## 本阶段边界

继续使用模拟退款服务，不覆盖真实支付清算与补偿体系。

## 术语速查

幂等（idempotency）指同一次操作重复请求不会重复产生业务效果；tool_call_id 不是稳定的业务操作标识。
