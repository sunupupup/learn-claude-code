# 阶段 3：持久化与恢复

[返回阶段索引](./README.md)

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 2](./02-business-flow.md)，用户确认进入本阶段。

## 学习目标

让等待用户的任务脱离旧进程和旧连接，重启后仍能继续。

## 需要实现的功能

- [ ] 选择持久化方式，保存会话、messages、待确认操作与必要的执行进度。
- [ ] 通知前端展示确认卡片前，先保存 checkpoint。
- [ ] 保存操作归属、原始 tool_call_id、执行参数、确认内容与状态；回传确认绑定原操作。
- [ ] 刷新读取已有待确认操作；确认、拒绝、取消有明确状态转换。
- [ ] 恢复时校验身份和当前订单条件，不依赖旧 HTTP 连接或内存事件。

## 验收标准

- [ ] 3.1：待确认时刷新，卡片订单和金额一致，待确认记录数量不增加。
- [ ] 3.2：待确认时重启后端，仍能加载原操作并接受用户决定。
- [ ] 3.3：用户拒绝后再次刷新，不重新显示可执行的旧确认。
- [ ] 3.4：订单条件变化时阻止按旧内容执行，需要时重新确认。
- [ ] 3.5：数据库记录可对应原工具调用；阶段 2 主流程仍可演示。

## 本阶段边界

本阶段只验证等待确认处的恢复；执行中崩溃和响应丢失由下一阶段处理。

## 术语速查

Checkpoint 是恢复所需的位置与数据；它可以是一组数据库记录，不必引入重型工作流框架。
