## 学习目标

对应 [S1-01～S1-06 用户故事与 E1 异常场景](./user-stories.md)。先读用户输入与预期反应，再实现下面的功能。

看清模型输出如何被程序识别、执行，以及工具结果如何进入下一次模型请求。

## 需要实现的功能

- [x] 确定语言、模型接入方式和依赖管理；记录选择理由。
- [x] 提供命令行入口、模型配置示例和启动说明；密钥从环境读取，不写入代码或日志。
- [x] 定义模拟订单查询工具的名称、描述和参数；先使用唯一匹配订单。
- [x] 由程序注入固定的模拟登录身份，工具检查订单归属；模型不能指定代表哪个用户。
- [x] 实现工具调用分发、参数校验、调用与结果的 ID 对应、内存 messages（对话历史）。
- [x] 记录脱敏后的模型输入、工具参数与结果；设置有限模型调用预算。

## 验收标准

- [x] 1.1：询问订单状态：真实模型提出查询调用，模拟工具返回订单，最终回答与返回事实一致。
- [x] 1.2：检查第二次模型请求：包含前次工具调用和匹配的工具结果。
- [x] 1.3：无匹配订单时明确告知未找到，不编造订单。
- [x] 1.4：未知工具、非法参数不会直接执行；达到调用上限后停止并给出可理解提示。
- [x] 1.5：按 README 从新终端启动成功；缺少配置时给出明确错误且不输出密钥。

## 本阶段边界

仅模拟业务接口、内存状态；不实现网页、退款、跨进程恢复。

## 术语速查

工具调用（tool call）是模型提出的结构化请求；Harness 是负责调度、检查和执行的程序。
