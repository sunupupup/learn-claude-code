## 学习目标

把订单查询扩展成完整的模拟售后流程，区分判断、确认与业务执行。

## 需要实现的功能

- [ ] 增加多订单候选、用户选择、截止时间澄清和物流查询。
- [ ] 提供带来源和版本的售后规则文档，先用简单关键词检索。
- [ ] 模型解释规则；程序校验归属、金额与订单状态等硬条件。含糊或冲突条款进入人工处理。
- [ ] 增加模拟催单和退款申请；确认卡片展示具体订单、范围、金额与操作含义，金额由后端计算。
- [ ] 提供最小网页，支持聊天、订单选择和确认/拒绝；本阶段等待状态可保存在内存。

## 验收标准

- [ ] 2.1：多笔耳机订单时先选择，不擅自选一单。
- [ ] 2.2：截止时间不明确时先澄清；无预计送达时间时不声称赶不上或保证能到。
- [ ] 2.3：预计能赶上：确认具体订单后提交催单。
- [ ] 2.4：预计赶不上且符合条件：确认后创建模拟退款申请；拒绝确认不执行。
- [ ] 2.5：页面区分申请提交与退款到账，不根据模型措辞宣告业务成功。
- [ ] 2.6：阶段 1 查询主流程仍可运行。

## 本阶段边界

不支持服务重启恢复，不接入真实退款；无需向量数据库或多 Agent。

## 术语速查

副作用是工具造成的业务状态变化；用户确认表达操作意愿，不代替业务资格校验。
