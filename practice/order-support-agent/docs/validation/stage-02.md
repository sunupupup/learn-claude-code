## 真实模型故事

| 场景 | 实际结果 |
|---|---|
| 两笔耳机订单，截止明日 20:00，选黑色 | 先显示候选；选单后查询物流和规则，生成 299 元退款卡；确认后生成 RF 申请编号 |
| 白色耳机，截止明日 20:00 | 预计明日 18:00，生成催单确认；点击确认生成 EX 工单编号 |
| 直接退白色耳机，然后取消 | 生成卡片，取消后无申请编号 |
| 充电线无预计送达时间 | 明确无法判断，列出催单、退款或等待选项，不自动退款 |
| 白色耳机“周五出差” | 询问确切日期与最晚收货时刻，不自动提交 |
| 定制键帽退款 | 查询规则返回缺失，说明需要人工核查，不产生确认或申请 |

本次一组故事通过，非多次采样稳定成功率。报告在被 Git 忽略的 .local/stage-two-live.json。无预计时间故事实际收到 75 个正文 delta，首个正文事件约 1.213 秒，done 约 1.590 秒（从响应头到达后计时），证明事件先于最终完成抵达，而非前端假流式。

## 故障与边界

离线断言包括：流被截断时即便参数 JSON 合法也不执行；外部 Origin 被拒；.env 不经静态接口暴露；用户不能伪造金额、身份或其他会话确认；订单金额变化使旧确认失效；重复确认复用原申请；取消后不能重新确认同一操作；同会话并发请求返回冲突。

一次真实催单故事初始未出现卡片：模型查询范围过宽或在唯一匹配后再次询问是否为该单。保留失败响应后，补充商品别名、唯一选定结果与 prompt 说明，再完成真实回归；测试允许模型返回多个候选后用户选择的合法路径。
