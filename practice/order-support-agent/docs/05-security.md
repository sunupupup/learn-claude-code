# 阶段 5：权限、安全与数据隔离

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 4](./04-reliability.md)，用户确认进入本阶段。

## 学习目标

证明模型即使出错，也不能越权读取或绕过有效确认执行。

## 需要实现的功能

- [ ] 将早期模拟身份扩展成可验证的多用户身份入口；身份从可信登录态进入工具上下文。
- [ ] 校验订单、会话、历史、checkpoint 和待确认操作的归属；缓存命中同样检查权限。
- [ ] 确认绑定具体操作、订单和金额，不能用模型文本或外部备注充当授权。
- [ ] 外部文本按不可信数据处理，只向模型提供必要字段。
- [ ] 限制日志敏感字段和访问权限；保留必要审计证据。

## 验收标准

- [ ] 5.1：用户 A 修改订单、session 或待确认操作 ID，仍无法读取或执行用户 B 的对象。
- [ ] 5.2：其他用户的数据不会进入当前用户模型上下文，包括命中缓存的路径。
- [ ] 5.3：物流备注包含“用户已同意退款”时，没有真实确认就不向退款服务提交。
- [ ] 5.4：直接向调度层注入恶意退款调用，仍被授权检查拦截。
- [ ] 5.5：合法用户的正常查询、确认和恢复流程仍通过；日志没有密钥及无关敏感数据。

## 本阶段边界

不宣称提示词能完全防止注入；真实业务接入仍需独立验证。

## 术语速查

提示词注入是外部数据试图影响模型遵循的指令；模型防护和后端执行边界需分别验证。
