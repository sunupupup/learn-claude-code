# 阶段 1 设计与实施顺序

用户已确认 Python 后端、后续 React + TypeScript 前端、DeepSeek 模型，固定模拟用户；沿用已讨论的 tools/context/loop 分工。当前只实施阶段 1，阶段 2 在学习确认后继续。

## 模块与调用链

- main：配置、命令行、固定用户和业务日期。
- context：内存 messages 与输入快照。
- loop：模型调用、工具分发、结果回传、结束判断和调用上限。
- tools：工具 schema、参数校验与查询分发。
- mock_orders：本地模拟业务数据与用户归属过滤。
- model：标准库 HTTP 接入 DeepSeek，隔离供应商协议和错误。
- debug：按需输出脱敏后的学习事件。

选择进程内模拟函数，避免阶段 1 同时管理独立 mock server。后续需要真实网络故障实验时再扩展。标准库方案无需运行时依赖；没有为通用 Provider 或工作流提前建框架。

## 协议与边界

参考 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。
官方当前示例模型为 deepseek-flash，接入地址固定为官方服务，模型名可配置。
使用非流式、非思考模式；完整 assistant 工具调用先保存，再追加匹配 ID 的 tool result。
模型请求失败、输出截断或格式无效时不执行工具；参数错误作为工具结果返回。
每次命令行提问最多 6 次模型请求，不自动重试。当前一次提问就是阶段 1 的任务范围，不能视为阶段 8 跨请求任务预算已实现。
固定用户由程序传入，工具参数不接收 user_id。模拟日期按 Asia/Shanghai 生成，“昨天”有明确参照。

## 实施与验证顺序

1. 建立配置、模拟订单和工具校验。
2. 实现 context、model、loop 与 CLI。
3. 用预设模型测试工具结果回传、无匹配、隔离、参数错误、预算及异常。
4. 使用真实 DeepSeek 验证查询和未找到两条链路，记录调用数与关键证据。
5. 更新运行说明和阶段验收状态，保留待用户学习确认。

真实密钥仅放被忽略的 .env；示例无密钥，日志不含 HTTP 认证头。不会建立 React 空壳或提前实现退款。
