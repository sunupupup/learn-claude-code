# 阶段 8：观测、成本与执行预算

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 7](./07-evaluation.md)，用户确认进入本阶段。

## 学习目标

从整体异常定位到一次具体模型输入和工具执行，并可靠限制资源。

## 需要实现的功能

- [ ] 采用项目约定 session → trace → run → span，并记录模型、prompt、工具与程序版本。
- [ ] 关联实际模型输入输出、工具结果、上游请求 ID、缓存命中和数据时间；遵循脱敏规则。
- [ ] 统计首正文、答案开始、整轮耗时、模型与工具耗时、token、费用和重复调用次数。
- [ ] 明确任务边界并保存任务级模型调用计数：同一任务跨用户澄清、确认和重启不重置预算。
- [ ] 执行模型最多 6 次、输入输出预算、工具超时与重复调用限制；时间预算区分用户等待与实际执行。
- [ ] 预算耗尽后不发第 7 次请求，有效待确认操作仍按授权流程处理，结果用模板展示。

## 验收标准

- [ ] 8.1：故意不回传工具结果，可通过追踪定位缺失发生在哪次请求。
- [ ] 8.2：分别制造慢工具与重复模型调用，能从记录区分原因。
- [ ] 8.3：第 6 次产生退款请求：确认后受控执行，用模板展示结果，模型调用总数不超过 6。
- [ ] 8.4：刷新或重启不会绕过同一任务预算；无预算继续分析时解释限制并提供人工入口。
- [ ] 8.5：执行超时但退款结果未知时仍保留核查入口，不宣告失败。

## 本阶段边界

不要求一开始部署完整监控集群；费用估算与供应商实际账单需区别标注。

## 术语速查

Trace 是一次前端请求链路，run 在本项目指一次循环，span 是具体步骤；任务可以跨多个 trace，须另有稳定关联。
