# 阶段 7：系统化测试与评估

[返回阶段索引](./README.md)

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 6](./06-context.md)，用户确认进入本阶段。

## 学习目标

分别证明模型选择是否合理和后端边界是否可靠。

## 需要实现的功能

- [ ] 整理前面阶段的固定回归案例，加入语气、商品和订单数量变体。
- [ ] 分开组织可确定的后端测试和真实模型评估；模拟模型测试不能替代真实模型评估。
- [ ] 覆盖查询、歧义、无预计时间、规则缺失冲突、注入、越权、重复点击、超时、恢复与预算耗尽。
- [ ] 记录模型、prompt 和代码版本；允许重复运行观察波动。
- [ ] 按错误严重性设门槛：越权、未授权执行和重复申请必须阻止发布；其余阈值实施时明确。

## 验收标准

- [ ] 7.1：提供可重复执行的测试/评估命令，报告通过、失败及未执行案例。
- [ ] 7.2：业务断言检查数据库申请数量和归属，不只检查 HTTP 状态或工具返回文本。
- [ ] 7.3：分别报告模型受诱导情况与后端阻断情况，不能合并成单个安全通过率。
- [ ] 7.4：故障用例失败时可以定位输入、执行记录及业务状态。
- [ ] 7.5：修复后运行针对性案例及主干回归；真实模型评估注明运行次数和波动。

## 本阶段边界

测试从第一阶段开始，本阶段才系统整理；有限案例不等于已证明所有输入安全。

## 术语速查

Eval 是评估模型或 Agent 行为的案例与评分过程；回归测试用于检查修改是否破坏已有能力。
