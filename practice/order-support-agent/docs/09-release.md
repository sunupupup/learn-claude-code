# 阶段 9：发布、回滚与前端收尾

[返回阶段索引](./README.md)

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 8](./08-observability.md)，用户确认进入本阶段。

## 学习目标

让可恢复任务在服务更新后仍有明确处置方式。

## 需要实现的功能

- [ ] 准备部署配置、健康检查、版本信息和数据库变更策略。
- [ ] 设计小范围发布和新流量切回旧版的操作步骤；记录发布版本关联。
- [ ] 实现优雅退出，停止接新请求并处理在途请求，不把连接结束视为任务完成。
- [ ] 明确旧任务版本兼容策略；不兼容时旧任务留在旧版处理，暂不自动迁移复杂 checkpoint。
- [ ] 前端统一显示处理中、待选择、待确认、已提交、未知、失败和人工入口，由后端状态驱动。

## 验收标准

- [ ] 9.1：按文档在测试环境部署并完成查询、确认与恢复主流程。
- [ ] 9.2：模拟新版异常，将新流量切回旧版并核验实际服务版本。
- [ ] 9.3：待确认任务在重启或兼容升级后仍能处理，不丢失或重复执行。
- [ ] 9.4：不兼容升级有可演示的旧任务路由或明确阻止升级的策略。
- [ ] 9.5：实际演练退出与恢复，验证业务记录而非仅观察进程退出。
- [ ] 9.6：前端不会因模型说“退款成功”而覆盖后端的“申请已提交”或“结果未知”。

## 本阶段边界

部署方式到本阶段再选，不预设 Kubernetes；不接真实资金，不承诺完整生产认证。
