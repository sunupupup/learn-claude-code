# 阶段 6：上下文管理与记忆

[返回阶段索引](./README.md)

## 状态与前置条件

- 状态：未开始。以下均为计划，不代表已经实现或验证。
- 前置条件：完成并理解[阶段 5](./05-security.md)，用户确认进入本阶段。

## 学习目标

区分保存了什么与本次真正发送给模型什么。

## 需要实现的功能

- [ ] 建立独立上下文组装逻辑，当前任务保留详细证据，其他任务保留必要摘要。
- [ ] 按需检索规则并记录版本、来源；区分当前事实与过期查询结果。
- [ ] 压缩历史时保留未完成事项和用户明确要求；订单 ID、金额、授权读取结构化记录。
- [ ] 配置输入预算，保持工具调用与结果对应，不以摘要代替确认记录。
- [ ] 明确历史数据保留范围和期限，支持查看脱敏后的实际模型输入。

## 验收标准

- [ ] 6.1：长会话压缩后回复“白色那个”，仍选择正确候选订单。
- [ ] 6.2：切换订单再返回，原待处理任务仍可找到，不误用另一单的规则和金额。
- [ ] 6.3：超出输入预算时受控压缩或明确结束，不无限扩张上下文。
- [ ] 6.4：被移出的规则能按需重新取得，并标明版本。
- [ ] 6.5：确认与幂等流程不因摘要缺失或模型误记而改变。

## 本阶段边界

先不自动提取跨会话长期偏好，不引入通用记忆平台。

## 术语速查

Context 是本次模型请求实际看到的信息；持久化历史不等于全部注入模型。

- 验收结果与证据：待验证，逐项对应上面的编号。
- 已知限制与遗留问题：待记录。
- 关键代码阅读入口：待实现后补充文件与函数。
