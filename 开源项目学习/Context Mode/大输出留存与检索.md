### 场景复现

| 方案 | 返回文本大小 | 文本 token 数¹ | 是否包含完整故障证据 |
|---|---:|---:|---|
| 普通执行，直接返回全部日志 | 7.4 MB | 1,700,006 | 有，但输出非常大 |
| `ctx_execute` 留存＋`ctx_search` 搜索 | **1,900 字节** | **543** | 有 |
| 不用 MCP，Python 直接筛选相关行 | **567 字节** | **125** | 有 |


一个分析日志的场景

```json
{
  "language": "python",
  "code": "from pathlib import Path\nprint(Path('test-output.log').read_text(encoding='utf-8'), end='')",
  "intent": "payment failed"
}
```

ctx_execute 完整的执行流程

```
ctx_execute 执行代码，得到大量日志 stdout
同时拿到本次检索目标 intent = "payment failed"
    ↓
发现输出超过 5,000 字节
进入 intentSearch，不直接返回全部日志
    ↓
将日志切成多个文本块
给每块生成标题
    ↓
把来源标签、块标题、块正文写入 SQLite
由 FTS5 建立全文索引
    ↓
用 intent = "payment failed"
搜索刚刚存进去的日志
    ↓
选出最多 5 个匹配块
    ↓
每块只取：
标题＋正文第一行的前 120 个字符
    ↓
附上来源标签、可搜索词和继续搜索的提示
返回给模型
    ↓
此时：完整日志留在数据库，模型只收到少量线索
    ↓
模型根据线索，调用 ctx_search 搜索 "payment"
    ↓
ctx_search 查询已有索引，找出匹配块
    ↓
截取命中词附近的原文
    ↓
返回包含 SignatureMismatch、密钥版本等信息的片段
    ↓
模型拿到具体证据，分析错误原因
```

### 关于切块

结果不能是一整块内容
需要切分成小块

进入 SQLite， 然后使用 FTS5

FTS5 是 SQLite 自带的全文检索扩展，全称 Full-Text Search 5。你可以把它理解成嵌在 SQLite 里的轻量文本搜索引擎。

所以它借用了 SQLite 已有的搜索能力，不需要自己从零写一个搜索引擎。

支持关键词检索
