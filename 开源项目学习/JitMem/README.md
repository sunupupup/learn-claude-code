## 学习模块

- [记忆检索与任务指导](记忆检索与任务指导.md)：新任务到来后，历史轨迹怎样变成执行模型收到的指导？已初始化。


论文主要讲四件事：
1. 过早总结，容易丢信息。
   做完任务就总结“经验”，当时不知道下次会问什么，可能把以后需要的细节删掉。

2. 根据当前任务整理记忆。
   同一份历史记录，处理“退款失败”时提取失败原因，处理“重复退款”时提取防重办法。记忆内容随当前任务变化。

3. 先整理，再交给执行模型。
   检索相关历史 → 一个专门的模型整理出简短指导 → 放进执行模型的提示词。执行模型不用直接读一大堆历史记录。

4. 可以训练“整理记忆的模型”。
   看它生成的指导有没有帮助当前任务成功，用这个结果训练它；执行任务的模型保持不变。这样比“写下一条记忆，等未来某天才知道有没有用”更容易获得训练反馈。论文

## 滞后 总结记忆的 时机

JitMem 主张：原始记录先保留。等下次真的遇到超时，再从里面提取“先查退款结果，避免重复退款”这条有针对性的提醒。

**常规Agent**
```
任务 A 结束
  → Harness 保存任务 A 的执行数据
  → Harness 调用 LLM，输入“任务 A 的执行数据”
  → LLM 提取记忆
  → Harness 保存记忆

任务 B 开始
  → Harness 检索相关记忆
  → Harness 把“任务 B 的要求＋记忆”发给执行模型
```

**JitMem**
```
任务 A 结束
  → Harness 保存任务 A 的执行数据

任务 B 开始
  → Harness 检索相关执行数据
  → Harness 调用 LLM，输入“任务 B 的要求＋相关执行数据”
  → LLM 提取记忆
  → Harness 把“任务 B 的要求＋记忆”发给执行模型
```

前者先提取、保存记忆，后面直接用；JitMem 先保存执行数据，用的时候再根据当前任务提取记忆。

区别在于 
常规做法是A结束后，立刻，总结记忆
Jim-Mem是A结束后，B收到Query后，先总结记忆，再处理B的任务

好处
能够带着新一轮的Query，来进行总结
**提取记忆时已经知道当前任务，需要保留什么、选取什么就更有依据。**
**提取记忆时能看到当前任务，确实有帮助。**
**生成什么记忆，由当前 query 决定。同一份历史数据，可以生成不同的记忆。**


| 实验设置 | ALFWorld 任务成功率 | WebShop 任务成功率 |
|---|---:|---:|
| JitMem 完整做法 | **60.5%** | **11.7%** |
| 提取记忆时，不提供当前任务 | 57.4% | 7.1% |
| 提前提取记忆，只保存提取后的内容 | 58.8% | 4.9% |

## 训练 生成记忆的模型 进化

生成记忆的模型主要用 Qwen3-8B，关闭 thinking 模式。

它让模型生成记忆，再通过“执行模型用了这份记忆后，任务做得怎么样”来训练。

论文采用 GRPO（组相对策略优化，一种强化学习训练方法）：把每份记忆对应的任务分数，与这一组的平均分比较

让模型做任务，收集执行数据，判断成功后，把成功任务的数据放进历史库。 但收集的是整个执行过程，不只是最终结果。

这是个很独立的环节
