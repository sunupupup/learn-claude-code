# screenshot-to-code：从截图上传到页面预览

本文作为源码阅读地图：先按整体工作流追踪一次生成，再深入生成阶段的 Agent Loop（智能体循环）。

- 阅读场景：一张截图、新建页面、先观察一个候选结果；多个候选并行生成以后再看。
- 固定版本：`a8139779f7c5ae231b7f2a86fa7f83ddc5f7badc`；读取日期：2026-11-05。
- 证据状态：以下关键入口与分支已静态核验；尚未安装依赖或运行项目，不代表生成效果或稳定性已验证。
- 临时源码：[源码目录](源码/README.md)；[学习问题与笔记](截图到代码与视觉反馈.md)。

## 1. 总体结构：固定工作流中嵌入 Agent Loop

Workflow（工作流）是由程序预先安排的处理阶段；Agent Loop 则让模型根据工具执行结果继续选择行动。两者可以嵌套。

本项目的外层是固定工作流，其中“代码生成”阶段进入 Agent Loop。模型选择允许的工具和参数，Harness（模型外围的执行与支撑程序）执行工具、维护状态并控制循环。

```text
浏览器：选择截图，点击生成
          ↓
前端发送图片、文字要求、目标技术栈等参数
          ↓
后端固定工作流
  建立连接 → 接收并校验参数 → 广播初始状态
          ↓
  组装模型输入 → 选择模型 → 进入生成阶段
          ↓
  ┌──────────── Agent Loop ────────────┐
  │ 调用模型                          │
  │    ↓                              │
  │ 本轮是否请求工具？                 │
  │    ├─ 有：执行工具                 │
  │    │      ↓                       │
  │    │   结果交回模型 → 再调用模型    │
  │    └─ 无：整理结果并退出循环        │
  └───────────────────────────────────┘
          ↓
  正常完成：发送最终代码与完成消息 → 收尾、关闭连接

生成期间：代码持续传回浏览器 → 更新前端状态 → 渲染预览
```

## 2. 按工作流阅读源码

### 第一步：浏览器准备截图和生成参数

选择文件后，前端把图片读成 Data URL（包含图片类型与编码数据的字符串），保存在前端状态中。点击生成时，将图片、补充文字和设置组织为请求。

依次阅读：

1. [UploadTab.tsx](源码/frontend/src/components/unified-input/tabs/UploadTab.tsx)：`fileToDataURL`、`handleGenerate`；观察文件如何变成图片数据，以及点击生成时交出哪些参数。
2. [App.tsx](源码/frontend/src/App.tsx)：`doCreate`、`doGenerateCode`；观察请求参数与本次生成记录如何建立。
3. [generateCode.ts](源码/frontend/src/generateCode.ts)：`generateCode`；观察 WebSocket（持续保持的双向通信连接）如何连接 `/generate-code`，并发送参数。

本步问题：截图、用户文字与生成设置，分别保存在哪里，又怎样被发送给后端？

### 第二步：后端执行固定的接入与准备步骤

先读 [generate_code.py](源码/backend/routes/generate_code.py) 底部的 `stream_code`。它按顺序注册以下处理阶段：

| 阶段 | 职责 |
| --- | --- |
| `WebSocketSetupMiddleware` | 接受连接，并在收尾时关闭连接。 |
| `ParameterExtractionMiddleware` | 接收请求，提取并校验参数。 |
| `StatusBroadcastMiddleware` | 告诉前端候选数量和初始生成状态。 |
| `PromptCreationMiddleware` | 组装模型输入消息。 |
| `CodeGenerationMiddleware` | 选择模型，启动生成阶段并收集结果。 |
| `PostProcessingMiddleware` | 调用后处理阶段；当前 `PostProcessingStage.process_completions` 直接返回，先视为预留入口。 |

Middleware（中间件）在这里是工作流中的处理环节：处理当前阶段，再调用下一阶段。不要把每个阶段都理解为一次模型调用。

本步问题：哪些动作由程序固定安排，真正调用模型的阶段从哪里开始？

### 第三步：把截图与要求组织为模型输入

从 `PromptCreationMiddleware` 进入 `PromptCreationStage.build_prompt_messages`，再看 [prompts/pipeline.py](源码/backend/prompts/pipeline.py) 的 `build_prompt_messages`。

本次只沿“新建 + 图片输入”分支阅读 [create/__init__.py](源码/backend/prompts/create/__init__.py) 和 [create/image.py](源码/backend/prompts/create/image.py)。修改历史、导入已有代码与视频分支暂不展开。

本步问题：图片内容、用户要求、目标技术栈和系统指令，分别怎样进入模型消息？

### 第四步：生成阶段运行 Agent Loop

回到 [generate_code.py](源码/backend/routes/generate_code.py)：`CodeGenerationMiddleware` → `AgenticGenerationStage.process_variants` → `_run_variant` → `runner.run`。

`process_variants` 可以为多个候选分别启动生成任务。本次先选一个候选追踪；多个候选不是这条主线的前置知识。

[runner.py](源码/backend/agent/runner.py) 的 `Agent` 直接继承 `AgentEngine`，循环主要在 [engine.py](源码/backend/agent/engine.py) 的 `_run_with_session` 中：

1. 调用模型，接收这一轮输出。
2. 若存在工具调用，由 [tools/runtime.py](源码/backend/agent/tools/runtime.py) 执行。
3. 将工具执行结果加入会话，进行下一轮模型调用。
4. 若没有工具调用，进入结果整理；程序的轮数和费用限制也可能让执行提前停止。

`create_file`、`screenshot_preview`、`edit_file` 是模型可以选择的工具，不是每次必须按顺序执行的固定步骤。当前先把整个 Loop 看成生成阶段，完成外层流程阅读后再逐项深入。

本步问题：进入 Loop 的输入是什么，生成期间和正常结束时分别交出什么结果？

### 第五步：代码持续返回前端并显示为页面

这一步会与第四步交错发生，不必等 Loop 完全结束。后端可在 `create_file` 参数流到达时发送代码预览，也会在工具更新代码后和正常完成时发送 `setCode`。

依次阅读：

1. [generateCode.ts](源码/frontend/src/generateCode.ts)：收到 `setCode` 后调用 `onSetCode`。
2. [App.tsx](源码/frontend/src/App.tsx)：`onSetCode` 调用 `setCommitCode`，更新当前生成记录中对应候选的代码。
3. [PreviewPane.tsx](源码/frontend/src/components/preview/PreviewPane.tsx)：读取当前选中候选的代码，交给预览组件。
4. [PreviewComponent.tsx](源码/frontend/src/components/preview/PreviewComponent.tsx)：对代码更新做节流和 Babel CDN 地址规范化，再写入 `iframe.srcdoc`，由浏览器渲染。

iframe 是网页内部嵌入的小页面窗口；这里的预览来自代码在浏览器中的渲染。`commit` 在这些前端状态中表示应用内部的生成版本记录，不等于执行了一次 Git 提交。

本步问题：后端发回的代码字符串，在哪里变成用户能看到的页面？

## 3. 先区分两种“预览”

| 对象 | 谁生成画面 | 结果交给谁 | 对应入口 |
| --- | --- | --- | --- |
| 用户看到的页面预览 | 前端浏览器渲染代码 | 用户 | `PreviewComponent.tsx` 的 `iframe.srcdoc`。 |
| 模型使用的视觉反馈 | 后端截图工具渲染当前代码并截图 | 模型；工具摘要也供前端展示 | [screenshot_preview.py](源码/backend/agent/tools/screenshot_preview.py) 的 `run_screenshot_preview`。 |

用户已经看到预览，不表示模型已经看过它。模型获得渲染截图后是否继续修改，需要结合实际工具调用与运行结果观察。

## 4. 学习顺序

先按第一步到第五步追一次输入与结果；第四步暂时只看生成阶段的入口和出口。外层流程清楚后，再回到 `AgentEngine._run_with_session`，深入模型调用、工具执行、状态更新、视觉反馈和停止条件。

每一步只回答三个问题：输入是什么、谁负责处理、输出交给谁。学习进度与个人理解由用户在[模块笔记](截图到代码与视觉反馈.md)中维护。
