系统提示词里面提到了这些最后要出具的关键内容



| 内容 | 用途 |
|---|---|
| `## Progress` | 总任务清单，开始时都未完成，标记每个任务的状态
| `## TODO N — 标题` | 每项任务的详细内容 |
| `**Goal:**` | 该任务要达到什么结果 |
| `**Status:**` | 执行步骤的复选框 |
| `**Verify:**` | 后续执行者应该怎样验证 |
| `**Done when:**` | 什么条件满足后才算完成 |


根据用户的query，得到一份 Pi Long Task TODO Markdown

query -> input text -> TODO markdown -> 内存状态

实际例子

# 用户Query：
```
帮我给注册功能加上邮箱格式校验、密码至少 8 位的校验，并补测试。
别加新依赖，也别提交代码。
```

# Input Text

```json
{
  "inputText": "为注册功能增加邮箱格式校验和密码至少 8 位的校验，并补充相关测试。不新增依赖，不提交代码。",
  "goal": "阻止无效注册，同时保持已有正常注册行为不变。",
  "commit": false
}
```



# TODO Markdown
```markdown
# Pi Long Task TODO

总体目标：阻止无效注册，同时保持已有正常注册行为不变。

共享约束：不新增依赖，不提交代码；沿用现有注册流程、校验方式和测试框架。

Global instructions:
- Long task goal: 阻止无效注册，同时保持已有正常注册行为不变。


## Progress
- [ ] TODO 1 — 增加邮箱校验及测试
- [ ] TODO 2 — 增加密码长度校验及测试

---

## TODO 1 — 增加邮箱校验及测试

**Goal:** 注册时校验邮箱格式。

**Status:**
- [ ] 实现邮箱校验并补充测试

**Verify:**
- 运行相关测试，确认有效邮箱通过、无效邮箱被拒绝。

**Done when:** 邮箱校验和相关测试完成且验证通过。

## TODO 2 — 增加密码长度校验及测试

**Goal:** 注册密码至少 8 位。

**Status:**
- [ ] 实现密码长度校验并补充测试

**Verify:**
- 运行相关测试，覆盖少于 8 位、恰好 8 位和超过 8 位。

**Done when:** 密码长度校验和相关测试完成且验证通过。
```

# 内存状态

其实内存状态，还是上面的md转来的
不用太纠结这个对象
其实很大程度，还是上面md的更新
Task[] 只是 md 的另外一种表现形式，更加结构化清晰的表达，方便取数据

```js
interface Task {
  taskId: string;             // TODO 编号，例如 "1"
  title: string;              // 任务标题
  stableId?: string;         // 可选的稳定标识
  section: string;            // 该任务完整的 Markdown 正文
  startLine: number;          // 在整份清单中的开始行
  endLine: number;            // 结束行
  done: boolean;             // 整个任务是否完成
  progressDone?: boolean;    // Progress 总览中的勾选状态
  statusCheckboxes: boolean[];// Status 步骤的勾选状态
  statusItems: {
    text: string;            // 步骤文字
    done: boolean;
  }[];
}
```
