# 我的笔记

Pi 的沙箱，主要是依赖于扩展接入

Pi 的 project trust（项目资源信任）不是沙箱，打开一个 Pi 项目的时候，里面有一堆扩展，会弹出“是否信任”

Namespace 沙箱：同一套内核，给进程划分不同环境。
虚拟机沙箱：运行另一套内核，两套内核使用同一台电脑的硬件。

个人开发、部署运维 可能确实这种 独立虚拟的 用的很少是
但是云厂商这种，卖隔离的资源，还是得有独立的内核
还是用 另外一种 非 namespace 的虚拟化技术

# @anthropic-ai/sandbox-runtime 包介绍

它是 Anthropic 开源的一个软件包，用来让程序在操作系统沙箱中执行命令。

作用是实现最简单的本地沙箱

给本机执行的命令，加上沙箱限制

比如 Pi 执行 `python analyze.py`

普通流程：
Bash → 启动 Python → Python 读取文件

加上沙箱:
沙箱工具先建立限制 → 启动 Bash → Bash 启动 Python

他是通过mount namespace机制实现的
它管理的是“路径与内容的对应关系”，由此决定暴露、隐藏和映射。

还有其他的namespace隔离机制配置
Network Namespace：网络环境也独立。
PID Namespace：进程编号和可见范围也独立。

大概这几个方面

| 概念 | 在这个扩展里做什么 |
|---|---|
| **Plugin / Extension（插件／扩展）** | 整个 `sandbox` 扩展，是加载进 Pi 的一个 TypeScript 模块 |
| **Tool（工具）** | 扩展注册一个同名 `bash` 工具，替换原来的执行入口 |
| **Hook（事件回调）** | 在会话开始、用户执行命令、会话结束时执行对应逻辑 |
| **沙箱库** | `@anthropic-ai/sandbox-runtime`，负责准备限制、包装命令 |

## session_start 初始化沙箱

扩展监听 session_start 事件

```js
pi.on("session_start", async (_event, ctx) => {
    // 读取配置，并初始化沙箱运行时
    await SandboxManager.initialize(配置);
});
```

有这些个配置：

| 配置 | 作用 |
|---|---|
| `enabled` | 是否启用沙箱 | 
| `network.allowedDomains` | 允许访问的域名 | 一般允许一些 github、npm、py的域名
| `network.deniedDomains` | 禁止访问的域名 | 
| `filesystem.denyRead` | 禁止读取的路径 | 不准读 ~/.ssh ~/.aws 等
| `filesystem.allowWrite` | 允许写入的路径 | 允许写入当前目录、和某些 /tmp目录
| `filesystem.denyWrite` | 禁止写入的路径 | 一般不准写入 key、env、pem 等文件
``

## 执行函数

这个是实际的执行函数 
```js
import { SandboxManager } from "@anthropic-ai/sandbox-runtime";
function createSandboxedBashOps(): BashOperations {
	return {
		async exec(command, cwd, { onData, signal, timeout }) {
			if (!existsSync(cwd)) {
				throw new Error(`Working directory does not exist: ${cwd}`);
			}

			const wrappedCommand = await SandboxManager.wrapWithSandbox(command);

			return new Promise((resolve, reject) => {
				const child = spawn("bash", ["-c", wrappedCommand], {
					cwd,
					detached: true,
					stdio: ["ignore", "pipe", "pipe"],
				});

				let timedOut = false;
				let timeoutHandle: NodeJS.Timeout | undefined;

				if (timeout !== undefined && timeout > 0) {
					timeoutHandle = setTimeout(() => {
						timedOut = true;
						if (child.pid) {
							try {
								process.kill(-child.pid, "SIGKILL");
							} catch {
								child.kill("SIGKILL");
							}
						}
					}, timeout * 1000);
				}

				child.stdout?.on("data", onData);
				child.stderr?.on("data", onData);

				child.on("error", (err) => {
					if (timeoutHandle) clearTimeout(timeoutHandle);
					reject(err);
				});

				const onAbort = () => {
					if (child.pid) {
						try {
							process.kill(-child.pid, "SIGKILL");
						} catch {
							child.kill("SIGKILL");
						}
					}
				};

				signal?.addEventListener("abort", onAbort, { once: true });

				child.on("close", (code) => {
					if (timeoutHandle) clearTimeout(timeoutHandle);
					signal?.removeEventListener("abort", onAbort);

					if (signal?.aborted) {
						reject(new Error("aborted"));
					} else if (timedOut) {
						reject(new Error(`timeout:${timeout}`));
					} else {
						resolve({ exitCode: code });
					}
				});
			});
		},
	};
}
```


## Pi 的 Gondolin 插件
Gondolin 这个插件，会启动一台本地 Linux 微型虚拟机，再把工具操作转交给它。

| | 前面的 `sandbox` 扩展 | Gondolin 扩展 |
|---|---|---|
| 执行环境 | 宿主机上的受限进程 | 本地 Linux 虚拟机 |
| 内核 | 共享宿主机内核 | 虚拟机有自己的 Linux 内核 |
| Pi 本身 | 留在宿主机 | 也留在宿主机 |

创建独立的linux虚拟机

但还是能共享宿主环境的文件

如果只需要某个项目 
> 宿主机 ~/my-project → 虚拟机 /workspace

排除某个文件也能单独拦截

### @earendil-works/gondolin

用的是这个sdk 

```js
import { RealFSProvider, VM } from "@earendil-works/gondolin";

const created = await VM.create({
    vfs: {
        mounts: {
            "/workspace": new RealFSProvider(localCwd),
        },
    },
});
```

一个精简的 Linux 系统镜像，包含启动和运行命令所需的基本程序、库与配置。
Gondolin 默认使用基于 Alpine Linux 的镜像。具体包含 Python、Node.js 等哪些工具，要看所选镜像，不能默认认为都有。

它使用 QEMU 拉起一个镜像的,和 VMware、VirtualBox 属于同一类工具。
加载虚拟机自己的内核


docker哪种方式是靠Namespace拉起镜像的
没有自己的内核

“有自己的内核”和“使用 Namespace”的关键区别，是这些请求交给谁处理：
| | Namespace 隔离 | 虚拟机隔离 |
|---|---|---|
| 程序的请求交给谁 | 宿主机的同一个内核 | 虚拟机自己的内核 |
| 怎样隔离 | 同一个内核，为不同进程安排不同的资源视图 | 启动另一套内核，由它管理虚拟机里的程序 |


内核也是一套独立的cpu调度软件

/boot/vmlinuz-版本号     ← 内核镜像
/lib/modules/版本号/    ← 配套的内核模块，例如部分驱动
