# pi-long-task 插件

它是 Pi 的第三方扩展，专门把较大的编程请求拆成 TODO，再逐项交给执行会话处理，记录进度、重试和结果。项目也有公开源码。项目说明

有两大块内容, pi_goal_task 、 pi_long_task，两个 tool
它们是**内层执行＋外层目标循环**的关系

| 部分 | 接收什么 | 主要负责什么 |
|---|---|---|
| **`pi_long_task`** | 一个具体请求，或已有 TODO | 生成/读取计划，逐项执行，记录结果和重试 |
| **`pi_goal_task`** | 一个希望达到的目标 | 生成 TODO，调用执行层，审查结果；有缺口再安排下一轮 |

pi_goal_task：目标循环
    │
    ├─ 生成一份 TODO
    ├─ 调用 pi_long_task 背后的执行协调器
    │      └─ 逐项执行 → 记录进度 → 收集结果
    ├─ 审查目标是否达成
    └─ 未达成则安排下一轮；完成或触及限制则结束

模型看到工具描述后,，如果判断这项工作是偏长的任务，那就交给 pi_long_task，主动生成工具调用。


工具参数
| 参数 | 类型 | 必填？ | 含义 |
|---|---|---|---|
| `inputText` | 字符串 | 否 | 要处理的需求描述，或者 TODO 的文本内容 |
| `commit` | 布尔值 | **是** | 是否允许提交完成的代码改动 |
| `goal` | 字符串 | 否 | 本次执行希望达到的总体结果 |

# pi_goal_task 工具

## pi_goal_task 工具定义

这边的描述，多了内容

```js
pi.registerTool({
  name: "pi_goal_task",
  label: "Pi Goal Task",
  description:
    "Run a goal-oriented long-task loop: generate TODO markdown from a high-level goal, execute it,review goal completion, and repeat until complete, cancelled, timed out, or max iterations isreached. Pass the tool cancellation signal to stop the loop.",
  async execute(_toolCallId, params, signal, onUpdate, ctx) {
  },
});
```

看了工具的描述， 似乎没有太特殊的，毕竟是prompt级别的
似乎预期更加 high level了点，多了 “high-level goal”
具体还是得看 goal 到底比 long task 多了什么更加goal级别的harness内容

重点关注下面几个内容
1. 目标澄清：目标模糊时，如何补充可执行的目标规格。
2. 目标验收：一份 TODO 做完后，谁判断整体目标是否达成，依据什么。
3. 反馈到下一轮：未达成时，如何把剩余工作转成下一份 TODO。
4. 循环控制：保存哪些跨轮状态，什么时候继续、停止。

## pi_goal_task 参数定义（PiGoalTaskParams）

| 参数 | 必填 | 用途 |
|---|---|---|
| `goal` | **是** | 整体目标，驱动反复生成 TODO、执行、审查 |
| `minIterations` | 否 | 至少进行几轮“生成 → 执行 → 审查”，才允许因达成目标而结束 |
| `maxIterations` | 否 | 最多进行几轮，默认 **50** |
| `timeoutMs` | 否 | 整个目标循环的时间上限，默认 **48 小时** |
| `commit` | 否 | 是否允许协调器提交完成的改动，默认 **true** |

### 10. 汇总结果与最终 tool 输出

是按照 currentIteration 
的方式来进行迭代的，但是这个只是一个数组，代表，这个goal 被迭代了多少次了
其实 每次迭代 ， 都是goal + 某些之前的记录
又生成了 新的 todo markdown ，然后去 execute 

pi_goal_task 是围绕同一个目标，带着历史结果和审查反馈，反复执行“生成任务清单 → 执行长任务 → 审查目标”的循环，直到目标达成或触及停止条件。

goal 约等于 多次递归长任务的，递归的时候会带上原来的goal + 上次的某些结果

```js

let state = createGoalLoopState();

// goal循环的全局状态
while (state.status === "running") {

  // 单纯记录迭代次数  
  const current = state.iterations.find((item) => item.iteration === state.currentIteration);

  // 生成TODO markdown
  // reviewed_incomplete 代表上一轮review之后，任务没完成
  // pending 状态似乎偶现？上次的todo生成，偶然没完成
  if(current.status === "reviewed_incomplete" || current.status === "pending"){
    const runGoalTodoGenerationLongTask = ()=>{
      payload = {
        gaol, state,
        // 这边就在继承之前的内容了
        // 把之前所有轮次的状态、TODO 文件路径、执行状态与摘要、review 决定与理由、剩余工作，汇总成一段文本。
        additionalContext: buildPreviousIterationContext(state),
        ...
      }
    }
    const generation = await runGoalTodoGenerationLongTask();
  }

  if (current.status === "todo_generated") {
    const execution = await runGoalTodoExecutionLongTask();
    executionResults.push(execution);
  }


  if (currentStatus === "todo_executed") {
    const review = await runGoalReviewSession();
    reviewResults.push(review);
    // 这边把整个state更新了
    state = review.state;
  }
}

state.status = "complete";
```
