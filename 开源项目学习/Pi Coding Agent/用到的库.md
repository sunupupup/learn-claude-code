# Pi 用到的库

基于 Pi **v1.0.0 / `a13d35a742c6`** 的静态源码整理，示例未实际运行。

Pi 自己实现模型接入、Agent 循环等核心能力，再拆成可复用的库；底层复用厂商 SDK 和通用组件。

## 多模型统一接入

他是自己适配的，Provider（厂商配置） 和 API（协议适配） 分开了
不是每个模型一个适配器：多个模型、甚至不同厂商，可以复用同一种 API 协议适配。

但是 底层用的还是每家自己的sdk

@anthropic-ai/sdk、openai、@google/genai、@aws-sdk/client-bedrock-runtime

## pi-ai 库

模型统一层 pi-ai	统一消息、工具、流式事件、模型信息，以及不同 API 的转换

**Pi 自己做的“统一模型接入库”：让上层通过一套消息结构和调用接口，使用不同厂商的模型。**

```text
上层：统一的消息、工具定义
             ↓
pi-ai：选择模型和厂商、处理认证
             ↓
对应 API 适配器：转换请求格式 
             ↓
厂商 SDK → 模型服务
             ↓
适配器：把响应转换成 Pi 统一的消息和事件
```


| 概念 | 含义 | 例子 |
|---|---|---|
| **Model，模型** | 具体调用哪个模型及其能力、限制 | 模型标识、上下文长度 |
| **Provider，服务提供方** | 向谁请求，以及如何认证 | OpenAI 的地址、凭据、模型目录 |
| **API，接口协议** | 请求和响应按什么格式交换 | Responses、Anthropic Messages |

具体的能力
- 统一数据结构
- 模型管理
- 认证
- 请求适配
- 响应适配
- 用量、成本


```ts
import type { Context } from "@earendil-works/pi-ai";
import { builtinModels } from "@earendil-works/pi-ai/providers/all";

// 建立模型集合，注册 Pi 内置的服务提供方。
const models = builtinModels();

const model = models.getModel("openai", "gpt-4o-mini");
if (!model) throw new Error("没有找到模型");

// 使用 Pi 的统一消息格式，不直接组织 OpenAI 请求体。
const context: Context = {
  systemPrompt: "请用中文简洁回答。",
  messages: [
    {
      role: "user",
      content: "什么是 Agent？",
      timestamp: Date.now(),
    },
  ],
};

// 等待完整响应；认证由 Provider 解析，这里可读取 OPENAI_API_KEY。
const response = await models.completeSimple(model, context);

for (const block of response.content) {
  if (block.type === "text") console.log(block.text);
}
```


| 方法 | 结果形式 | 参数形式 |
|---|---|---|
| `completeSimple()` | 等待完整响应 | 统一简化参数，如 `reasoning` |
| `complete()` | 等待完整响应 | 通用参数及适配层支持的 API 专有参数 |
| `streamSimple()` | 流式事件 | 统一简化参数 |
| `stream()` | 流式事件 | 通用参数及适配层支持的 API 专有参数 |

`complete()` 内部就是 `stream(...).result()`；`completeSimple()` 对应 `streamSimple(...).result()`。完整响应也可能包含工具调用，不代表业务任务已经完成。

对于支持推理的 OpenAI 模型，大体可以这样理解：能调推理强度，但不会返回完整的内部推理内容。
例如 OpenAI Responses 的 `reasoningSummary` 可请求推理摘要；摘要不等于完整内部推理，是否支持取决于模型。Pi 会将支持的摘要输出适配到统一消息/事件。

## pi-agent-core 库

pi-agent-core	模型—工具循环、工具执行、事件通知、中途消息和取消等控制
怎样循环调用模型、执行工具、更新状态？

它是 Harness（模型外部的执行与管理设施）的执行核心；会话持久化、审批界面、上下文压缩和缓存保温等仍由外层组织。
| 能力 | 做什么 |
|---|---|
| **循环执行** | 根据模型响应继续调用工具和模型 |
| **运行状态** | 维护消息、当前模型、工具、正在执行的状态等 |
| **工具调度** | 参数校验，串行或并行执行，处理结果 |
| **事件通知** | 告诉外层：消息开始、文本增量、工具开始、工具结束 |
| **中途控制** | 取消运行、插入引导消息、排队后续消息 |
| **扩展入口** | 在请求前、工具调用前后等位置接入自己的逻辑 |

```js
const agent = new Agent({
  initialState: {
    model,
    systemPrompt: "你是一个助手。",
    tools: myTools, // 工具需要带实际执行实现。
  },

  // 注入模型调用能力，Agent 核心负责围绕它组织循环。
  streamFn: models.streamSimple.bind(models),
});

await agent.prompt("读取配置文件，告诉我数据库地址。");
```

实际调用链：

```text
Agent.prompt()
  → runPromptMessages()
    → runAgentLoop()
      → runLoop()
```

它包装了一个可以运行的、有状态的 Agent 对象。

工具调用经过：查找工具 → 参数校验 → `beforeToolCall` → `tool.execute()` → `afterToolCall` → 回传结果。外层可通过钩子实现权限和审批；进程内 `await` 等待不等于可跨重启恢复的持久化暂停。

## pi-coding-agent 库

pi-coding-agent	怎样组合成可交互、可管理会话、可扩展的编程助手？

coding-agent 就是最主要的入口
Pi 这个编程助手如何启动、运行
它提供 pi 命令行，并把其他库组合成完整应用。

阅读入口：`packages/coding-agent/src/cli.ts` → `main.ts` → `core/sdk.ts` 的 `createAgentSession()` → `new Agent(...)` → `new AgentSession({ agent, ... })`。

先从产品层追调用链，遇到模型接入再进入 `pi-ai`，遇到执行循环再进入 `pi-agent-core`。终端显示和输入由自有库 `pi-tui` 提供。

源码入口（相对本地 Pi checkout）：
- `packages/ai/README.md`、`packages/ai/src/models.ts`
- `packages/agent/src/agent.ts`、`packages/agent/src/agent-loop.ts`
- `packages/coding-agent/src/core/sdk.ts`
