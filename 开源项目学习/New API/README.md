# New API

可自部署的 AI 网关，连接多家上游模型并提供统一访问入口；本次重点观察跨协议转换、模型适配与不兼容能力的处理。

- 官方仓库：https://github.com/QuantumNous/new-api
- 学习对象：网关本体；重点为 `relaykit/` 与 `relay/channel/`，并核验宿主装配。
- 固定源码：`3e2ce2c8856e32ca7054d673f8cd059ae466e80c`；读取日期：2026-10-17。
- 许可证：[GNU AGPL v3](https://github.com/QuantumNous/new-api/blob/3e2ce2c8856e32ca7054d673f8cd059ae466e80c/LICENSE)；子模块和第三方组件声明使用前另核验。
- 起点资料：[RelayKit 说明](https://github.com/QuantumNous/new-api/blob/3e2ce2c8856e32ca7054d673f8cd059ae466e80c/relaykit/README.md)；[动态工具加载旧笔记](../../真实生产问题/002-工具太多如何告诉模型并减少选错/其他家动态工具加载策略.md)。

## 学习模块

建议先选第 1、5 项，其余按需选择；均为已初始化。

1. [协议转换与模型适配](协议转换与模型适配.md)：首选：请求如何在 Chat Completions、Responses、Anthropic Messages 和 Gemini 之间转换？
2. [消息角色与指令转换](消息角色与指令转换.md)：system、developer 和历史消息的角色及插入位置，转换后是否保留？
3. [工具调用与结构化输出适配](工具调用与结构化输出适配.md)：工具定义、调用、结果和输出约束，怎样跨协议转换？
4. [流式事件转换](流式事件转换.md)：上游流式片段如何转换为客户端事件并正确结束？
5. [不兼容字段与转换损耗](不兼容字段与转换损耗.md)：目标协议或模型无法表达某个字段时，如何决定拒绝、丢弃、改写或降级？
6. [缓存与增量能力适配](缓存与增量能力适配.md)：协议转换后，缓存边界与中途新增指令、工具的语义还能保留吗？
7. [渠道路由与故障重试](渠道路由与故障重试.md)：请求怎样选择上游，何时重试或切换渠道？
8. [用量统计与计费](用量统计与计费.md)：不同协议的 token、缓存读写和流式用量怎样统一？
9. [鉴权与日志隔离](鉴权与日志隔离.md)：客户端身份、上游凭证与调用日志分别在哪处理？
