# 上下文压缩方式对比

> 本文用于对比 `s08_context_compact/code.py` 中的四层压缩策略及其生产边界。章节学习过程与掌握状态见 [`LEARNING_NOTES.md`](./LEARNING_NOTES.md)。

## 一、核心判断

上下文压缩不是越多越好。选择策略时，先回答：

1. 结果是否真的大到值得压缩？
2. 当前推理是否还需要完整正文？
3. 原始内容能否**安全、低成本地重新获取**？
4. 重新获取时，内容是否仍与原来一致？
5. 内容是否包含关键业务状态、不可逆副作用或审计证据？
6. 完整内容是否已有稳定、受权限控制的外部引用？

🔴 **已验证理解**：能安全、低成本地重新获取的内容，可以只保留占位提示；不能轻易重现但后续可能需要的内容，应先持久化，再在 Context 中保留摘要和引用。

## 二、四层策略总表

| 层级 | 处理粒度 | 主要触发条件 | 压缩后保留 | 原文是否持久化 | 典型恢复方式 |
| --- | --- | --- | --- | --- | --- |
| L1 `snip_compact` | 整段 Message | 消息条数超过上限 | 一条 `[snipped N messages]` Message | 否 | 依赖剩余历史或其他记录 |
| L2 `micro_compact` | 旧 `tool_result.content` | Tool Result 变旧且正文较长 | 原 Tool Result Block＋通用占位符 | 否 | 安全时重新调用工具 |
| L3 `tool_result_budget` | 当前一批超大 Tool Result | 最新 user 消息中的结果总量超预算 | 原 Tool Result Block＋路径＋预览 | 是 | 按路径读取完整结果 |
| L4 `compact_history` | 整个活跃历史 | 前三层后估算大小仍超阈值 | 一条 LLM 摘要 Message | 是，先写 transcript | 读取 transcript 或重新获取来源 |

`reactive_compact` 不是第五种内容表示，而是 API 实际返回 `prompt_too_long` 后触发的应急摘要路径。

## 三、L1：消息级裁剪

### 适用场景

- 对话轮次很多；
- 开头包含任务入口或基础约束；
- 最近消息包含当前工作状态；
- 中间大量历史已经不再直接参与当前任务。

### 教学代码伪代码

```text
if 消息条数 <= max_messages：
  原样返回

head_end = 3
tail_start = 消息总数 - (max_messages - 3)

if 头部最后一条消息包含 tool_use：
  向右扩大头部，保留紧随的 tool_result 消息

if 尾部第一条消息包含 tool_result
   and 它前一条消息包含 tool_use：
  tail_start 向左移动一条

删除 [head_end, tail_start) 中间区域
插入一条 user 占位消息：[snipped N messages]
```

### 主要风险

- 删除的是整段历史，原文没有由 L1 自动持久化；
- 可能删除中间形成的决定、约束和关键证据；
- 当前边界保护只检查相邻消息类型，没有逐个校验 `tool_use_id`；
- 占位 Message 的 `role: user` 是本项目选择，不是所有协议的强制规则。

## 四、L2：旧 Tool Result 占位

### 适用场景

适合完整内容已经不再活跃使用，并且能够安全、低成本地重新获取的工具结果，例如：

- 稳定文件的读取结果；
- `glob`、目录枚举等廉价只读结果；
- 输入固定、结果确定的纯计算；
- 更希望获得当前状态的 `git status` 等查询。

实时搜索、实时价格和会变化的文件虽然是只读结果，但重新调用后可能与原结果不同，不能默认视为可重现。

### 教学代码伪代码

```text
收集 messages 中所有 tool_result block 的原对象引用

if 结果数量 <= KEEP_RECENT：
  原样返回

保留最近 KEEP_RECENT 个结果

for 每个更旧的结果：
  if content 长度 > 120：
    将 content 原地替换为：
    [Earlier tool result compacted. Re-run if needed.]
```

### 压缩效果

```text
压缩前：tool_result.content = 完整旧结果
压缩后：tool_result.content = 通用占位提示
不变项：消息角色、Block 类型、tool_use_id 和调用轨迹骨架
```

### 主要风险

- “旧”不等于“不重要”，当前代码没有语义判断；
- 原文没有落盘，无法保证恢复到当时的结果；
- `Re-run if needed` 不适合转账、发信、创建资源等副作用工具；
- 如果工具结果来自短期资源，之后可能已经无法重新获取。

## 五、L3：大 Tool Result 外置

### 适用场景

- 大型文件内容；
- 构建、测试或运行日志；
- 数据库批量查询与导出；
- 网页抓取快照；
- 代码分析报告；
- 截图、PDF、音视频或其他大型 Artifact；
- 重新调用昂贵、缓慢或结果可能变化的工具。

### 教学代码伪代码

```text
只检查最后一条 user 消息中的 tool_result blocks
计算这些结果 content 的总长度

if 总长度 <= 200_000：
  原样返回

按结果长度从大到小排序

for 每个大结果：
  if 总长度已经进入预算：
    停止
  if 当前结果长度 <= 30_000：
    跳过

  将完整内容写入：
  .task_outputs/tool-results/<tool_use_id>.txt

  将原 content 替换为：
  文件路径 + 前 2000 字符预览

  重新计算总长度
```

当前函数参数名使用 `max_bytes`，但教学实现实际通过 Python `len(str(...))` 统计字符数量，不是真正的字节或模型 Token。

### 主要风险

- 文件存在不代表模型会自动读取，需要显式恢复工具；
- 路径需要权限、生命周期、清理和敏感数据保护；
- 当前 L3 标记以后变旧时，可能又被 L2 换成通用占位符，导致模型失去磁盘路径；
- 生产实现应保留更短的稳定 `result_ref`，不要让 L2 删除恢复入口。

## 六、L4：LLM 历史摘要

### 适用场景

- L1-L3 完成后 Context 仍然过大；
- 长任务需要保留目标、决定、进度和未完成事项；
- 规则式裁剪无法判断哪些自然语言信息最重要。

### 教学代码伪代码

```text
将完整 messages 写入 transcript JSONL

从 messages 构造摘要输入
要求 LLM 保留：
  当前目标
  关键发现与决定
  已读取或修改的文件
  剩余工作
  用户约束

调用一次 LLM 生成摘要
用一条 [Compacted] user Message 替换活跃 messages
```

### 主要风险

- 摘要是有损且非确定性的，可能遗漏或误写信息；
- 多次“摘要的摘要”可能积累漂移；
- transcript 落盘不等于模型当前仍能访问；
- 当前实现只把序列化历史的前 80000 字符交给摘要模型，不是真正处理全部原始字符；
- 应使用 Eval 检查目标、约束、决定、文件修改和待办事项是否被保留。

## 七、Reactive：API 报错后的应急压缩

### 适用场景

程序的大小估算认为尚未超限，但模型 API 实际返回 `prompt_too_long` 或类似错误。

### 教学代码伪代码

```text
尝试调用模型 API

if API 返回上下文过长
   and reactive 重试次数未超限：
  保存 transcript
  生成历史摘要
  保留摘要和最近约 5 条消息
  重新调用 API
else：
  抛出错误
```

Reactive 是最后兜底，不应替代正常 Token 预算和主动压缩。

## 八、生产策略选择伪代码

```text
function choose_compaction(tool, result, context):
  if result 很小 and 已包含后续所需事实：
    return KEEP_FULL

  if tool 有副作用：
    receipt = 提取 status、operation_id、resource_id、
             idempotency_key、retry_policy、result_ref
    持久化完整结果或查询业务系统权威状态
    return KEEP_RECEIPT(receipt)

  if result 可安全重跑
     and 重跑成本低
     and 不要求恢复当时快照：
    return PLACEHOLDER_WITH_RERUN_HINT

  if result 很大
     and 后面可能需要原始细节：
    ref = 持久化完整结果
    return KEEP_REFERENCE_AND_PREVIEW(ref)

  if 自然语言历史仍有高价值但无法规则裁剪：
    return LLM_SUMMARY_WITH_TRANSCRIPT

  return KEEP_FULL
```

## 九、场景速查

| 场景 | 推荐策略 | 原因 |
| --- | --- | --- |
| 20 字符的计算结果 | 直接保留 | 压缩收益小 |
| 很旧的稳定文件内容 | L2，占位并允许重读 | 只读、便宜、可恢复 |
| 500KB 测试日志 | L3，落盘＋路径＋预览 | 太大，后续可能需要定位错误 |
| 实时搜索结果 | L3 或带时间戳摘要 | 重跑后内容可能变化 |
| 创建工单成功 | 保留操作凭证，完整详情外置 | 避免重复创建，需要资源 ID |
| 转账超时且状态未知 | 禁止直接重跑，查询权威状态 | 可能已经产生副作用 |
| 80 轮自然语言讨论 | L1 后必要时 L4 | 需要减少轮次并保留关键决定 |
| API 仍提示上下文过长 | Reactive | 估算与实际 Token 限制不一致 |

## 十、进入下一章前要记住

1. L1 删除 Message；L2 替换旧 Tool Result 正文；L3 外置巨大 Tool Result；L4 用 LLM 摘要历史。
2. L2 与 L3 的核心区别是：原文是否持久化，以及恢复方式是重跑还是按引用读取。
3. Tool Use 与 Tool Result 的配对边界不能被裁剪破坏。
4. 短结果不必压缩；有副作用的结果即使很短，也要保留操作凭证。
5. Transcript、磁盘文件和业务数据库属于外部 State，不会因为存在就自动成为模型 Context。
6. 压缩率不是唯一指标；还要评测任务正确率、恢复成功率、Token、延迟、成本和副作用安全。
