# Agent Loop 的简单描述

## 一句话概括

**Agent Loop 的核心，是模型根据当前上下文决定下一步动作，程序执行动作，再把结果反馈给模型，直到完成任务或触发停止条件。**

记住这条主线：

**接收任务 → 组装上下文 → 模型决策 → 执行工具 → 结果反馈 → 循环或结束。**

## 面试时可以这样描述

首先，系统接收用户请求，加载系统提示词、历史消息、必要的记忆，以及当前允许使用的工具，组装成模型请求。

然后调用模型。模型可能直接回答，也可能返回结构化的工具调用，比如工具名称和参数。

如果返回工具调用，运行时会检查工具是否存在、参数是否合法、权限是否满足；需要用户确认的操作先确认，再执行工具。

工具执行后，将成功结果或错误作为 tool result（工具执行结果）写回上下文，再次调用模型。模型据此决定继续调用工具、调整方案，还是给出最终回答。

当模型给出最终回答，或者达到最大轮数、超时、用户取消等条件时，循环结束。生产环境还会记录执行状态、调用轨迹、耗时和 Token 使用，方便恢复和排查问题。

这里描述的是常见的工具调用型 Agent Loop。具体项目可以按需要加入规划、审批、子 Agent 等步骤；权限检查和恢复能力需要运行时实际实现。

## 流程图

```text
用户请求
   ↓
组装上下文 → 调用模型
               ↓
          模型返回什么？
          ├─ 最终回答 → 结束
          └─ 工具调用
               ↓
          校验权限和参数
               ↓
           执行工具
               ↓
       把 tool result 放回上下文
               └────────→ 再次调用模型
```

上图展示正常主流程；运行时还需要处理校验拒绝、工具失败、超时和取消等分支。

## 一个具体例子

用户问：“查一下订单什么时候到。”

1. 模型先调用订单查询工具。
2. 程序查询订单和物流信息，把结果返回给模型。
3. 如果信息足够，模型直接回答。
4. 如果还缺预计送达时间，模型可以继续调用物流工具，再综合结果回答。

## 最值得强调的职责边界

**模型负责提出动作，Runtime/Harness 负责校验、执行和控制循环。模型返回一个工具调用，并不代表工具已经执行成功。**

- Runtime：运行时，负责执行和管理本轮任务。
- Harness：模型外围的运行与控制程序，可包含上下文组装、工具执行、权限、状态和观测等能力；不同项目的命名和拆分方式不同。

## 常见追问

- **工具失败后怎么办？** 将结构化错误反馈给模型，让它调整参数或选择其他路径；程序按错误类型和策略决定是否允许重试或终止。
- **怎么防止无限循环？** 设置最大轮数、时间、Token/成本预算和取消机制。

## 反思

- **表述边界**：这是通用流程说明，不代表每个 Agent 框架默认具备完整的权限校验、持久化和恢复能力。
- **学习建议**：能用订单查询的例子解释一次“模型 → 工具 → 结果 → 模型”的往返，再补充失败和停止条件，就能把核心机制讲清楚。
