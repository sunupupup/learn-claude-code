# 快慢的原因

## 显存够不够

假如 27B 的模型

270亿参数 × 0.5字节 ≈ 13.5GB

但训练时还需要：
- 量化参数和缩放系数；
- LoRA 参数；
- 梯度；
- 优化器状态；
- 中间激活值；
- Attention 计算空间；
- CUDA 临时空间。
所以实际可能需要30GB甚至更多。

4090的显存是24GB，那就必然有数据需要放在内存中

一旦需要在GPU和电脑内存之间来回搬数据，速度可能慢几倍甚至十几倍。

而H100有80GB，模型可以比较完整地留在显存中，因此不会频繁搬运。

## 显存带宽

显存带宽决定“喂数据”的速度

GPU核心再快，也必须不断从显存读取模型权重和中间结果。

4090：约1.0TB/s
A100：约2.0TB/s
H100：3.35TB/s
H200：4.8TB/s

训练模型的时候，并不是把数据放在显存就不动了

显存 ──读取数据──> GPU计算核心
显存 <──写回结果── GPU计算核心

GPU非常快，计算完了之后，还在等显存传数据

GPU核心：我算完了，下一批数据呢？

显存：等一下，还在传。

GPU核心：那我只能空等。

## 显存带宽实际例子

假设有个矩阵 W：4096 × 4096 ， BF16，每个参数2字节
大小是 4096 × 4096 × 2字节 ≈ 32MB

然后，要生成一个 token， 假设是 长度 4096 
大约 8KB

GPU 要计算 Y = X × W， 也就是 8KB 的数据



GPU不会把数据一次性全导入Tensor Core，拆成很多块

在H100上，理想情况下读取32MB需要：
32MB ÷ 3.35TB/s ≈ 0.01毫秒

4090需要 
32MB ÷ 1.0TB/s ≈ 0.03毫秒

这部分就有 3 倍的差距

不用考虑向量计算本身的开销

# 补充知识：显卡训练模型显存不够

普通 PyTorch 训练中，如果显存不够，最常见结果是直接报错：

CUDA out of memory

不会静默使用CPU

除非明确开启 明确开启了 CPU Offload 

```
GPU显存放一部分
普通内存放一部分
需要时通过PCIe交换 (这部分交换的速度，很慢)
```

# 补充知识：分布式训练架构

多张独立GPU，在上层搭建分布式训练架构，让它们协同工作。

服务器
├─ CPU
├─ 内存
├─ GPU 1：80GB
├─ GPU 2：80GB
├─ ...
└─ GPU 8：80GB


GPU之前通过 PCle\NVLink 等方式通信

称之为 多GPU服务器、单机多卡、单节点多卡

这是一个服务器

多台服务器又能变成集群，通过高速网络连接

服务器1：8张H100
服务器2：8张H100
服务器3：8张H100
服务器4：8张H100


训练代码
例如Transformers
        ↓
并行训练框架
DeepSpeed / FSDP / Megatron-LM
        ↓
分布式通信框架
PyTorch Distributed / NCCL
        ↓
CUDA驱动
        ↓
NVLink / PCIe / InfiniBand
        ↓
多张独立GPU


集群的目的：加速、单卡装不下一个模型
