# 框架 和 原生 

AI 让自建更便宜；社区维护让框架的长期演进可能更便宜

## 我的观点

在以前没有ai时代，基本上是选择框架，减少coding事件、重复造轮子、性能等成本，哪怕是借鉴，都会有很大的时间成本

但是ai时代，借鉴、轮子、coding 这些所有的时间，被大大减少；倒不如牺牲框架的层面，而从原生的开始

## 框架 

LangGraph 作者：框架应该靠恢复、并行和追踪证明价值

框架几个重要的东西
- 抽象
- 社区
- 带来约束、

使用框架的原因
框架“有机会跟随演进并让项目受益”

自建会形成需要长期维护的内部架构。选择合适且持续维护的框架，可以分摊架构演进成本，但需要承担框架适配和升级成本。

## 原生

原生也有问题
不使用用框架，项目发展中，会逐渐形成独有的抽象和约束
这些技术可能过时、设计理念冗余
到那时框架会随着框架的迭代而进步

所以，原生，必须要承担着升级的风险

AI 降低了“修改代码”的成本，但不会自动告诉你“现有设计已经不合适，应该改成什么”。

   

## Shopify 例子 用原生

Shopify，2026-09-10：

Native is now the future of mobile at Shopify
https://shopify.engineering/back-to-native

Shopify 宣布从 React Native 转回 Swift、Kotlin 原生开发。它明确解释：
- 当初选 React Native，是为了避免同一功能实现两次，减少跨平台协作和功能同步成本。
- AI 现在能参考一个平台的实现，在另一个平台完成对应实现，并辅助测试和审查。
- 两套代码仍有维护成本，但这个成本已不再像当年一样决定选型。
- 因而，更贴近平台能力、减少中间依赖层的收益，重新占了上风。原文


“2025 年 1 月，我写道 React Native 的未来光明，Shopify 计划继续投资它。根据当时我们所知道的情况，这是真的。React Native 对我们来说运行良好，它依然是一个非常出色的框架。但从那以后，编码模型有了显著改进，对于我们的应用和团队来说，**在 Swift 和 Kotlin 中构建同样的功能不再像以前那样高昂**”



他们一开始使用 React Native的原因
- 别再重复建造同样的功能了
- 允许开发人员跨技术栈工作
- 少花时间追求功能均衡，多花点时间创造价值


有个关键的让他们进行迁移的理由
在IOS版本实现的功能，完全实现一个Android的版本，平台之间的平等性
